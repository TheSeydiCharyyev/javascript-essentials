1. What JavaScript is

JavaScript is a programming language. In it you write instructions that the computer carries out in order, from top to bottom. An instruction can be simple: “add 2 and 2”, “show a message”, “take the text from the input field”. Big programs are built from such small steps: an online shop, a chat, a game, a photo editor.

The main difference from HTML and CSS fits in one word: behavior. HTML describes what is on the page. CSS describes how it looks. JavaScript describes what happens when a person clicks, types, scrolls or waits for an answer from the server.

Think of a café. HTML is the tables, the chairs and the menu: what physically stands in the room. CSS is the decoration: the color of the walls, the font of the menu, the waiters’ uniform. JavaScript is the waiter, who takes the order to the kitchen, brings the food and adds up the bill. Without the waiter the café looks nice, but nothing happens.

You have seen JavaScript at work hundreds of times without knowing it:

  • a feed that loads by itself. You scroll down and new posts appear — the page did not reload, so code asked for the data;
  • a shopping cart. You click “buy”, and the number of items in the corner changes at once;
  • form checks. You type a phone number in the wrong format and see a red note right away, before sending anything;
  • dark mode. You click a switch, and the colors change and are remembered for next time;
  • a map. You drag it with a finger, and it loads new pieces and adds markers.

All these examples have one thing in common: the page changed without reloading. This is the simplest sign of JavaScript at work, and you can spot it without looking at the code.

Check it on this very page: open the console with F12 (the Console tab), paste the line and press Enter:

document.querySelector("h1").textContent = "I changed the heading!";

The lesson heading changed without a reload. Reload the page and it comes back: the code changed the page only in the browser, and the file on the server stayed the same.

Here is a program of one line. It shows a window with a message:

alert("Hello, Mary!");

And this program asks for a name and says hello:

const name = prompt("What is your name?");
alert("Hello, " + name + "!");

You can already see three things we will study for the whole course: a value (“Mary” — our city — and the person’s name), the variable name — a box with a name where the value is put, and the function alert — a ready-made command that you use by writing its name and parentheses.

Why this language is learned first

There are hundreds of programming languages. JavaScript comes first for three practical reasons. Nothing needs to be installed: the browser is already on the computer. You see the result at once: write a line and the page changes, so mistakes are found faster. Work needs it: every website is HTML, CSS and JavaScript.

2. What “programming language” means

A computer does not understand human language. It can do very simple operations: add two numbers, compare them, put a value into memory and take it back. A programming language is the go-between. We write words we understand, and a translator program turns them into processor operations.

Every language has a syntax — rules of writing. In English a sentence starts with a capital letter and ends with a period. In JavaScript a line of code ends with a semicolon, text goes in quotes, and the arguments of a function go in parentheses. Break a rule and the program will not run, and the browser will tell you with an error message. That is not scary: everyone sees errors, even people who have written code for twenty years.

The second important phrase is in order. Statements run from top to bottom, one after another. Let us go through a program of four lines step by step:

const price = 12;        // 1
const count = 7;         // 2
const total = price * count;  // 3
console.log(total);      // 4
1

We create a box named price and put the number 12 into it. The word const means “we will not change this value”.

2

We create a second box, count, with the value 7.

3

We calculate 12 * 7. Important: the right side is calculated first, and only then is the result put into the box total. By this moment the computer already knows what is in price and count, because lines 1 and 2 ran earlier.

4

We show the result: 84 appears in the console.

Swap the lines and the program breaks. Let us put the output on the first line of the file app.js:

console.log(total);            // ReferenceError: Cannot access 'total' before initialization
const price = 12;
const count = 7;
const total = price * count;

The engine read the whole file and knows that the name total exists in it, but no value has been put into it yet. In the console of a new tab the message is shorter — total is not defined — but the meaning is the same: on this line there is no value yet. Day 4 covers this in detail. The main idea is already clear: the computer does not guess; it does exactly what is written, in exactly that order.

A program is a recipe. “Pour water, boil it, add tea, cover” — the order matters, the steps are simple, and each step makes sense on its own. A computer is a very fast, very precise and completely clueless cook: it will not understand “just do it the usual way”, but it will follow a detailed recipe a million times without a single mistake.

What every program is made of, whatever the language:

Building blockWhat it isExampleWhen we study it
valuesnumbers, text, “yes / no”12, "tea", trueday 5
variablesnamed boxes for valuesconst price = 12;day 4
operationswhat is done with valuesprice * countdays 6–7
conditionschoosing a pathif (age > 18) { ... }day 9

These six building blocks exist in almost every programming language. Learn them once in JavaScript, and you will recognize them in Python, Java and any other language — only the details of writing change.

Here are all six in one small program. You do not need to read it line by line yet — find the building blocks by the comments:

const prices = [12, 5, 8];            // values and a variable
let sum = 0;
for (const price of prices) {         // loop: for each price in turn
  if (price > 6) {                    // condition: only prices above 6
    sum = sum + price;                // operation
  }
}
console.log(sum);                     // 20 — a function printed the result

3. Three layers of a page: HTML, CSS, JavaScript

Every web page is built from three layers. They work together, but each one has its own job.

You can take the layers off one by one. Turn off CSS and the page becomes plain, but the text stays. Turn off JavaScript and the page stays pretty, but the buttons stop doing anything. Remove HTML and nothing is left.

Take the CSS off this very page with one line in the console:

document.querySelectorAll('link[rel="stylesheet"], style').forEach((el) => el.remove());

Colors, fonts and spacing disappear, but all the text stays in place: the content lives in HTML. Reload the page and the design comes back.

Let us look at one button in all three layers. HTML creates the button and a place for the counter:

<button id="btn">Buy</button>
<span id="count">0</span>

CSS decides how it looks:

<style>
  #btn {
    background: #f59e0b;
    color: white;
    border-radius: 8px;
    padding: 10px 20px;
  }
</style>

And JavaScript responds to the click:

let count = 0;

document.getElementById("btn").addEventListener("click", function () {
  count = count + 1;
  document.getElementById("count").textContent = count;
});

We will go through this code line by line on days 24 and 27. For now, notice the structure: there is a variable that holds a number, and there is a reaction to an event — “when clicked, do this”. Almost every interface on the internet works this way.

Find something on your favorite website that changes without a reload: a like, a star, a cart counter. Think about which variable is behind it and which event changes it. That is how a programmer thinks.
Beginners often try to “do everything in JavaScript”: they draw buttons with code and set colors with code. That is possible, but the page becomes slow and hard to understand. The rule is simple: what you can show with HTML and paint with CSS, do in HTML and CSS. Use JavaScript when you need an action.

4. Where code runs and what runs it

Written code is just text in a file. To make it work, you need something that runs it. In the browser this is called the JavaScript engine. The browser reads the HTML, finds the code in it and hands it to the engine. The engine parses the text, turns it into commands the processor understands and runs them.

How the engine understands code

Inside the engine, code goes through three stages. You do not need to learn them by heart, but it helps to understand them: they explain why some errors show up at once and others only while the program runs.

1

Parsing. The engine reads the text and checks the rules of writing. If a parenthesis is missing, the program does not start at all — this is a syntax error, and it is seen before running.

2

Translation into internal commands. The text becomes a set of simple instructions that the engine understands.

3

Execution. The instructions run one by one. This is where errors appear that could not be noticed in advance: the code used a name that does not exist, or called something as a function that is not a function.

People used to say that JavaScript is an “interpreted” language: code runs line by line, without preparation. Today that is not accurate. Modern engines watch which pieces of code run often and translate them into machine code on the fly — this is called JIT compilation. That is why the same loop can run noticeably faster the second time than the first.

The name V8 comes from a powerful car engine with eight cylinders. The first version of the engine came out together with the Chrome browser in 2008.

Every browser has its own engine, but all of them run the same language:

BrowserEngine
Chrome, Edge, Opera, Yandex BrowserV8
FirefoxSpiderMonkey
SafariJavaScriptCore

The V8 engine can also work without a browser. That is how Node.js appeared — a program that runs JavaScript directly in the operating system. So today this language is used not only for pages:

  • websites and web apps — in the browser;
  • servers that send data to these websites — on Node.js;
  • phone apps — React Native;
  • desktop programs — Electron (VS Code, Discord and Slack are made with it);
  • scripts for spreadsheets, bots and automation.

Behind these lines is a future career choice. The browser runs what a person sees: shops, personal accounts, games — this is the work of a front-end developer, and it is what our course is about. The server gives the pages their data; someone who writes both the page and the server is a full-stack developer.

One language at every level saves effort. A person who learned JavaScript for the page can also write a simple server for it without learning a second language from scratch.

The language and the environment

How can one language work both in the browser and on the server? MDN explains it like this: JavaScript has a core — numbers, strings, functions, Math, JSON — that is the same everywhere. The environment where the code runs adds its own things to the core: the browser adds the page, windows and events, Node.js adds files and the server.

This is easy to check. In the browser console:

typeof document;   // "object" — there is a page
typeof process;    // "undefined" — the browser has no such thing

And here is the file hello.js, run in Node.js with the command node hello.js:

console.log(2 + 3);
console.log(typeof document);   // there is no page
console.log(typeof process);    // but there is a Node.js process
console.log(Math.max(3, 7, 2)); // the core is the same as in the browser
5
undefined
object
7

Numbers and Math work the same way — that is the core. Only the browser gives document, and only Node.js gives process. In this course we write for the browser, so we use both the core and the abilities of the page.

5. Where the language came from

The history of the language explains its oddities. Some decisions that look illogical today appeared because the language was made in a hurry, and then for twenty years nobody could break compatibility with websites already written.

1995
Brendan Eich at Netscape writes the first version of the language in about ten days. The name came from marketing people: Java was popular then, and the word “JavaScript” helped to sell.
1997
The language is described in a standard so that all browsers understand it the same way. The standard is called ECMAScript: by that time the name JavaScript belonged to one company.
1996–2001
The “browser wars”. Microsoft releases its own version of the language — JScript. The same code works in Netscape and does not work in Internet Explorer, and the other way round. Developers write pages twice and add checks like “which browser do you have”.
2005–2008
Libraries like jQuery appear and hide the differences between browsers behind one command. At the same time an approach takes off where the page loads data without reloading: mail, maps and news feeds start working like real programs.
2009
Node.js appears: the same language starts working outside the browser. From now on one person can write both the page and the server for it.
2015
A big update, ES2015: modern features that we will use for the whole course (let, const, arrow functions, classes).
Every year
A new edition of the standard comes out in summer: ES2016, ES2017 and so on. The language is not rewritten; features are added so that old code keeps working.

Who decides what goes into the language? The TC39 committee — people from browser companies and large developers. Every proposal goes through four stages: idea, description, draft with an implementation, finished feature. Until a proposal reaches the last stage, it is better not to use it in teaching code: it may still change.

Because of the compatibility rule, the language still has things that are seen today as design mistakes: for example, var with its strange scope rules, or ==, which compares “roughly”. They are not removed, because millions of old pages would stop working. Instead, correct replacements were added: let and const instead of var, === instead of ==. We will learn the modern way from the start, and we will talk about the old way so that you understand other people’s code.

You can see this “roughly” in the console (day 7 covers it in detail):

0 == "";    // true — “roughly”: the empty string was turned into the number 0
0 === "";   // false — strictly: a number and a string are not equal
The first name of the language was Mocha, the second LiveScript, and only the third JavaScript. Today the official name of the standard is ECMAScript, but in everyday life everyone says “JavaScript” and names versions by year: “this appeared in ES2020”.

6. JavaScript and Java are different languages

“JavaScript is a short version of Java” is the most common beginner misconception. All they share is four letters in the name and a similar look of the braces. They are different languages with different histories, different rules and different jobs: Java is used for banking systems and Android apps, JavaScript for web pages and their servers. “What is the difference between them?” is a normal job interview question, and the answer “none” stands out at once.
JavaScriptJava
Appeared1995, Netscape1995, Sun Microsystems
Where it runsbrowser, server (Node.js)Java virtual machine, Android
Type declarationnot required: let x = 5;required: int x = 5;
Runningthe browser runs the text at oncefirst a build, then a run
Typical jobwebsite interface, web serverbanking system, Android app

The main difference from the table can be seen in three lines. In JavaScript you do not declare the type, and one variable can hold first a number and then text:

let x = 5;
x = "five";   // JavaScript does not mind
x;            // "five"

In Java such a program will not build: incompatible types: String cannot be converted to int — a variable declared as int holds only whole numbers.

7. What the language can do in the browser and what it cannot

Code on a page does not work in empty space: it lives inside a browser tab. The tab gives it many abilities, but keeps it within limits — otherwise any website could harm your computer.

CanCannot
change the text and design of the page read and write any files on the disk
react to clicks, typing, scrolling start programs on the computer
request data from a server and show it freely read the data of another website in another tab
save data in the browser and remember it after a reload turn on the camera or find your location without your permission

The right column is not a weakness of the language but protection. Everything that touches your computer the browser allows only after a clear question: “The site wants to use your camera. Allow?”. A website gets a file from your computer only when you pick it yourself in the file dialog.

The left column, one line per ability:

document.body.append("Code added this line");   // change the page: a line at the bottom
document.addEventListener("click", () => console.log("click"));   // react: click on the page
localStorage.setItem("city", "Mary");   // save in the browser
localStorage.getItem("city");            // "Mary" — even after a reload

Let us check this right now. Open the console on any page and run:

document.title;              // the tab title — can be read freely
document.title = "My site";  // and changed: look at the tab
navigator.language;          // the browser language, for example "en-US"
screen.width;                // screen width in pixels

The page let us read and even change its title. Now try to find out the location:

navigator.geolocation.getCurrentPosition(function (pos) {
  console.log(pos.coords.latitude, pos.coords.longitude);
});

The browser will not give the coordinates silently — a question “Allow access to your location?” appears at the top. Until the person clicks “Allow”, the code gets nothing. The camera, the microphone and notifications work the same way.

This gives an important safety rule: do not run code in the console that strangers sent you “to get a gift”. You run it on behalf of the open page — for example, your mail or your bank. The browser protects you from other websites, but not from yourself.

One more limit is called the “same-origin policy”: the code of one page cannot freely read the content of another. Otherwise a tab with a game could read your messages in the next tab. A page gets data from another server only with that server’s permission — we will see this on day 31, when we get to fetch.

8. First lines of code

Tools come in detail tomorrow, on day 2. Today it is enough to know that every browser has a console — a window where you can write a line of code and see the result at once. It opens with F12, on the Console tab.

The console is a programmer’s scratch pad: it is used to check one idea — “what does this method return?”. You cannot break anything: whatever the code changed on the page disappears after a reload.

ActionHow
open the consoleF12, then the Console tab
run a lineEnter
start a new line without runningShift + Enter
repeat the previous commandarrow ↑
clear the consoleCtrl + L or console.clear()

Try these lines right in the lecture:

2 + 2 * 2;                 // 6 — the order is the same as in math
"Mary" + " " + 2026;       // "Mary 2026" — strings are joined
console.log("It works!");  // prints text in the console

The first two lines have no console.log, and still the result is visible: the console itself shows the value of the last expression. MDN compares it to a console.log wrapped around every line. That is also where the mysterious undefined after the output comes from:

3 + 5;               // 8 — the value of the expression
console.log(3 + 5);  // prints 8, and below it the console writes undefined: console.log returns nothing

The console is a good calculator, and not only for numbers:

10 / 3;      // 3.3333333333333335
0.1 + 0.2;   // 0.30000000000000004 — fractions are not counted perfectly exactly, day 6
"Mary".length;          // 4 — letters in the word
"mary".toUpperCase();   // "MARY"
Open the console and count how many minutes there are in a week. Hint: 60 * 24 * 7. If you got 10080, it is correct — you have just run your first program.

Several lines at once

If a line is not finished — for example, you typed function greet() { and pressed Enter — the console does not run it but waits for the rest. You can also start a new line yourself: Shift + Enter.

function greet() {
  return "Salam!";
}
greet();   // "Salam!"

The first example of the MDN guide is also several lines long. Copy all of it into the console:

(function () {
  "use strict";
  /* Start of your code */
  function greetMe(yourName) {
    alert(`Hello ${yourName}`);
  }

  greetMe("World");
  /* End of your code */
})();

A window with Hello World appears. MDN advises putting the wrapper (function () { … })(); around code in the console so that experiments do not get in each other’s way. What it means we will see on day 13, and the line "use strict" on day 4.

Code can also be written in a file. Then it is connected to the page with one line:

<script src="app.js" defer></script>

The file app.js lies next to the page, and the word defer tells the browser: “first show the page, then run the code”. That is what people do almost always.

A complete small project looks like this. Two files in one folder:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>First page</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1 id="hello">Hello!</h1>
</body>
</html>
// app.js
const title = document.getElementById("hello");
title.textContent = "Salam, Mary!";
console.log("The code ran");

Open the page in the browser — the heading changes before you have time to read it. We will study getElementById on day 24; for now it is enough to see the link: HTML created the heading, JavaScript changed it.

// the same app.js, but <script src="app.js"> is in <head> without defer:
// Uncaught TypeError: Cannot set properties of null (setting 'textContent')
If you write <script src="app.js"> without defer at the very top of the page, the code runs before the heading appears, and getElementById returns null. This is where the classic beginner error comes from: Cannot set properties of null. One word fixes it: defer.

The UTF-8 encoding in the head is required; otherwise letters outside basic Latin — the Turkmen ä, ň, ö, ü, ý, ž or Cyrillic — turn into a row of question marks.

9. When something goes wrong

An error is not a punishment but a message. The browser writes what exactly it did not understand and on which line. Learning to read these messages is more important than memorizing methods: errors will be with you for your whole career.

Three messages you will meet in the first week:

MessageWhat it meansWhat to do
Uncaught ReferenceError: total is not defined a name was used that does not exist check that the variable is declared and the name has no typo
Uncaught SyntaxError: Unexpected token the rules of writing are broken look for an extra or missing parenthesis, quote or comma
Uncaught TypeError: x is not a function something that is not a function was called as a function check the method name: console.lg, getElementByID

An error message is read from the end: the last line tells where exactly the engine tripped. In the console, next to the error, there is the file name and the line number — click it, and the browser shows that place.

console.log(summa);   // ReferenceError: summa is not defined — there is no such name
const summa = 10;
console.log(summa);   // 10 — we declared the name, and the error is gone
console.lg("test");   // TypeError: console.lg is not a function — a typo in the method name
consol.log("test");   // ReferenceError: consol is not defined — a typo in the first word

In the second pair the typos look alike, but the errors are different. In consol.log the engine tripped earlier — on the unknown name consol — so it never got to “not a function”.

// alert("hello);   → SyntaxError: Invalid or unexpected token — the quote is not closed
alert("hello");      // this is correct
Do not be afraid to break code: a wrong line cannot damage the browser. Try, read the error, fix. Copy the whole error text into a search engine — most often the very first answer explains the cause.

10. Documentation: MDN and the specification

A programmer does not keep all methods in their head. They remember that a method exists and can find its description quickly. The main reference for the language is MDN Web Docs. It has two big parts:

  • Guide — a textbook: explains topics in order, with examples;
  • Reference — a reference book: a separate page for every method, property and operator.

There is also the ECMAScript specification — the document browsers themselves are built from. It is written in dry language for engine developers. We will start reading it in course 2, when questions like “but why does it work exactly this way?” appear.

How to read a reference page

A method page in Reference always has the same structure: a short description, then the Syntax section. Here it is for Math.max, word for word:

Math.max()
Math.max(value1)
Math.max(value1, value2)
Math.max(value1, value2, /* …, */ valueN)

This is not code to run but a template: the method can be called with no values, with one, with two or with any number of them. Next come the sections Parameters — what to pass, Return value — what comes back, and Examples. Let us check the template in the console:

Math.max(3, 7, 2);   // 7 — the largest of the values passed
Math.max();          // -Infinity — exactly as Return value says: “if no values are given”
Do not search the web in general; search like this: “mdn” plus the name of the method. The query mdn array map leads straight to the right reference page. The English version of MDN is the most complete, and its language is simple and repetitive — you get used to it in a week.

The Essentials course is the first of four. Next come Intermediate (how the language works inside), Advanced (the language by the specification) and Web APIs (the abilities of the browser). What you need for the lessons

  • A browser — Chrome, Firefox or Edge. Any modern one will do, and it is already on your computer;
  • a code editor — VS Code, free. We install it on day 2;
  • a notebook and a pen — yes, seriously. Diagrams, cheat sheets and error notes written by hand are remembered better;
  • a folder for your work — create one folder and keep all course files in it, one folder per day.

How to ask so that people can help you

The question “it doesn’t work” has no answer. A useful question has four parts: what you wanted to do, what code you wrote, what you got and what you expected to get. Copy the error text from the console in full — the answer is usually in it.

The main advice for the three months: type code by hand, do not copy it. Your fingers learn the syntax faster than your head, and the mistakes you make while typing are the learning itself. Copied code teaches nothing.

    Answer In the MDN reference: a search like “mdn” plus the method name.
  5. What does the error Uncaught ReferenceError: summa is not defined mean?
    Answer The name summa was used, and the engine does not know it: the variable is not declared or the name has a typo.
  6. Why does the console also write undefined after console.log(3 + 5)?
    Answer The console shows the value of every expression. console.log prints 8, but returns nothing itself — and the console shows this “nothing” as undefined.
  7. Why does consol.log("test") give a ReferenceError, while console.lg("test") gives a TypeError?
    Answer In the first case the name consol itself is unknown. In the second the name console exists, but it has no method lg, and it cannot be called as a function.
  8. Why do people write defer in the <script> tag?
    Answer So that the code runs after the browser has built the page. Otherwise the script does not find the elements and gets null.
