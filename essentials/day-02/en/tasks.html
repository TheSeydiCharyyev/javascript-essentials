Day 2. Tasks

Lessons 2 and 3, 90 minutes. Today there is a lot of hands-on work: we install the editor, build a project and learn the console. Keep all files in the folder day-02.

Warm-up

1. The workplace
Easy7 min

install the editor and create the course folder.

Install VS Code and the Live Server extension. Create a course folder and inside it a folder day-02. Open it in the editor: File → Open Folder.

  • the folder name day-02 is visible in the left panel of the editor;
  • the Live Server extension is installed;
  • autosave is on (File → Auto Save).
2. A page and a script
Easy7 min

connect a script file to a page.

Create index.html and app.js. On the page — the heading “Day 2” and the script connected with defer. In the script — the output “File connected”. Open the page through Live Server.

  • the address bar shows http://127.0.0.1:5500, not file:///;
  • the text is visible in the console;
  • after changing the text and saving, the page refreshed by itself.
3. Four message levels
Easy6 min

see the difference between log, info, warn and error.

Print one message with each of the four methods. Then find the level filter in the console and leave only errors and warnings.

The level filter is a drop-down list above the console messages, to the right of the search box.
  • four messages are printed;
  • the filter managed to hide ordinary messages;
  • the color of each level is written down.

Main tasks

4. A table of marks
Medium13 min

show a list of data in a readable way.

Make a list of five students with marks and print it in two ways: with an ordinary console.log and with console.table. Compare which is easier to read.

const students = [
  { name: "Aman", mark: 5 },
  { name: "Meret", mark: 4 },
];
console.table(students);
  • the table has five rows and two columns;
  • a conclusion is written down: in which case a table is more convenient than ordinary output.
5. Groups of messages
Medium13 min

bring order to long output.

Print a timetable for three days: each day is its own group with three subjects inside. Make one of the days folded from the start.

A folded group is opened with console.groupCollapsed and closed the same way — with console.groupEnd.
  • three groups with three lines each;
  • one group is folded when the page opens;
  • the groups open and fold with a click.
6. Measuring time
Medium12 min

measure instead of guessing.

Measure the time of two loops: one of a hundred thousand steps and one of ten million. Print both results and compare them. Inside the loop, add the numbers into a variable.

console.time("small");
let sum = 0;
for (let i = 0; i < 100000; i++) { sum = sum + i; }
console.timeEnd("small");
  • both measurements are printed with different label names;
  • it is written down how many times slower the second loop is;
  • it is explained why the time differs a little between runs.
7. A call counter
Medium12 min

find out how many times a piece of code runs.

Write a greeting function that calls console.count inside. Call it five times with different names, then reset the counter and call it twice more.

  • the counter reached 5, was reset and started counting again;
  • it is written down what the console says if you reset a counter that did not exist yet;
  • console.countReset is used.

Starred tasks

8. Stop and look around
Hard10 min

work with a breakpoint.

Write code that calculates the cost of a purchase: price, quantity, discount. Put a breakpoint before the total is calculated — by clicking the line number in the Sources tab. Reload the page and look at the values of the variables. Then walk through the program step by step to the end.

The control buttons are above the list of variables: resume, step over a line, step into.
  • the program stops at the right line;
  • the values of all variables at the moment of the stop are written down;
  • the same is repeated with the word debugger in the code, and then the line is removed.
9. Break it and fix it
Hard10 min

learn to read errors and the order of steps when something breaks.

Break your project in three ways, one at a time, each time writing down the error text from the console and how you found it:

  1. change the file name in the connection to apps.js;
  2. write consol.log("test"), without the final “e”;
  3. remove the closing quote in a string.
  • the error text is written down for each breakage;
  • it is noted on which line the browser found the problem;
  • the project works again after all three fixes;
  • the name App.js with a capital letter is checked separately, and it is written down why it worked on Windows.
