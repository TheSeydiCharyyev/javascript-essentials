1. Что нужно для работы

Вчера мы писали код прямо в консоли браузера. Это удобно для одной строки, но программу так не соберёшь: закрыли вкладку — всё пропало. Сегодня заведём рабочее место, в котором будем жить три месяца.

Нужны три вещи, и все они бесплатные:

ИнструментЗачемГде взять
Браузервыполняет код и показывает результатуже установлен: Chrome, Firefox, Edge
Редактор кодаписать и хранить файлыVS Code, code.visualstudio.com
Папка для работчтобы файлы не терялисьсоздаёте сами, например D:\js-kurs
Почему нельзя писать код в Word или в «Блокноте»? Word добавляет в текст невидимое оформление, и браузер такой файл не поймёт. «Блокнот» кода не портит, но и не помогает: нет подсветки, нет подсказок, нет проверки скобок. Редактор кода экономит часы.

2. Редактор VS Code

VS Code — самый распространённый редактор для JavaScript. Он бесплатный, работает на Windows, macOS и Linux и, что забавно, сам написан на JavaScript.

Установка

1

Откройте code.visualstudio.com и нажмите большую кнопку Download. Сайт сам определит вашу систему.

2

Запустите скачанный файл. При установке поставьте галочки «Add to PATH» и «Open with Code» — они позволят открывать папку в редакторе правой кнопкой мыши.

3

Откройте редактор и сразу поставьте два расширения: Live Server и Russian Language Pack, если нужен русский интерфейс. Расширения ставятся из левой панели, значок с квадратиками.

Как устроено окно

Несколько клавиш, которые окупятся в первый же день:

КлавишиЧто делают
Ctrl + Sсохранить файл
Ctrl + Zотменить последнее действие
Ctrl + /закомментировать строку
Alt + ↑ / ↓переместить строку вверх или вниз
Ctrl + Dвыделить следующее такое же слово
Ctrl + Fнайти в файле
Включите автосохранение: меню File → Auto Save. Половина вопросов «почему не работает» на первых занятиях решается тем, что файл просто не сохранён.

Три возможности редактора, которые экономят время

Автодополнение. Начните печатать cons — редактор предложит console, затем после точки покажет список методов: log, table, warn. Выбирается стрелками, подтверждается Tab. Это не только быстрее, но и защищает от опечаток вроде consol.

Заготовка страницы. Создайте пустой index.html, напечатайте восклицательный знак и нажмите Tab — редактор развернёт полный каркас HTML-страницы. Этот приём называется Emmet, и он же умеет разворачивать сокращения вроде ul>li*3 в готовый список.

Форматирование. Shift + Alt + F выравнивает отступы во всём файле. Код с ровными отступами читается быстрее, а ошибки со скобками видно сразу.

Редактор — это не «продвинутый блокнот», а мастерская. Молоток можно держать в руке, но верстак, тиски и хорошее освещение делают работу другой. Первые дни кажется, что подсказки мешают; через неделю без них будет неудобно.

3. Первый проект: папка и два файла

Проект — это обычная папка. Договоримся с первого дня держать порядок: на каждый день курса своя папка, внутри понятные имена файлов.

Файл index.html — это сама страница:

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>День 2</title>
  <script src="app.js" defer></script>
</head>
<body>
  <h1>Проверка инструментов</h1>
</body>
</html>

Разберём эту разметку по частям — дальше она будет в каждом проекте:

СтрокаЗачем
<!DOCTYPE html>говорит браузеру: это современная страница
<html lang="ru">обёртка всей страницы; язык нужен поиску и переводчику
<head>служебная часть: кодировка, заголовок вкладки, подключения
<meta charset="UTF-8">кодировка; без неё кириллица превратится в знаки вопроса
<title>надпись на вкладке браузера
<script src="app.js" defer>подключение файла с кодом
<body>видимая часть страницы

Теги пишутся парами: открывающий <h1> и закрывающий </h1>. Внутри одной пары могут лежать другие — так получается дерево, с которым мы будем работать на дне 24. Глубокого знания HTML курс не требует, но эти семь строк надо уметь написать по памяти.

Файл app.js — код:

console.log("Файл подключён");

Комментарии

Комментарий — это текст для человека, который браузер пропускает. Две формы:

// однострочный комментарий: до конца строки

/*
  многострочный:
  удобен для пояснений в несколько предложений
*/

const price = 12;   // можно и в конце строки

Комментариями пользуются для двух вещей: объяснить, почему сделано так (что делает код, обычно и так видно), и временно отключить строку, не удаляя её. Второе на занятиях пригодится постоянно: Ctrl + / превращает строку в комментарий и обратно.

Откройте страницу, нажмите F12 — в консоли должна появиться надпись «Файл подключён». Если её нет, значит, скрипт не подключился: проверьте имя файла, папку и строку <script>.

Имя файла чувствительно к регистру и к языку. App.js и app.js — разные файлы, а арр.js, где первые буквы русские, выглядит точно так же, но не найдётся никогда. Называйте файлы латиницей, маленькими буквами, без пробелов.

Три способа положить код на страницу

Код можно написать прямо в разметке, а можно вынести в файл. Разница важная, поэтому разберём все три способа сразу — в чужих примерах встретятся все.

<!-- 1. Прямо в разметке: годится для одной строки -->
<script>
  console.log("я живу внутри страницы");
</script>

<!-- 2. Внешний файл в конце body: старый способ -->
<script src="app.js"></script>

<!-- 3. Внешний файл с defer в head: так делаем мы -->
<script src="app.js" defer></script>
СпособПлюсМинус
в разметкеничего не надо подключатькод мешается с вёрсткой, его нельзя переиспользовать
файл в конце bodyразметка уже готовабраузер добирается до скрипта последним
файл с deferскачивается сразу, выполняется после разметкинужно помнить про слово defer

Как браузер загружает страницу

Без defer браузер, встретив <script> в шапке, останавливает построение страницы, скачивает файл и выполняет его. Заголовков и кнопок в этот момент ещё нет, поэтому код, который их ищет, ничего не находит. Отсюда правило курса: внешний файл, в head, со словом defer.

4. Почему страницу открывают через сервер

Страницу можно открыть двойным щелчком по файлу. В адресной строке тогда будет file:///D:/.... Для первых уроков этого хватает, но дальше начнутся ограничения: браузер запрещает такой странице загружать данные и модули — из соображений безопасности.

Поэтому ставят расширение Live Server: правой кнопкой по index.html → «Open with Live Server». Страница откроется по адресу http://127.0.0.1:5500, то есть с маленького сервера на вашем же компьютере.

Двойной щелчокLive Server
Адресfile:///…http://127.0.0.1:5500
Обновление после сохранениявручную, F5сама
Загрузка данных, модулибраузер запрещаетработает
Привыкайте сразу открывать проект через Live Server. Тогда на дне 31, когда мы начнём получать данные с сервера, ничего не придётся переучивать.

Что означает адрес 127.0.0.1:5500

Адрес 127.0.0.1 — это всегда «мой собственный компьютер». У него есть и словесное имя, localhost. Число после двоеточия — порт, то есть номер двери, за которой слушает конкретная программа. Live Server по умолчанию садится на дверь 5500.

Поэтому страница, открытая так, ведёт себя как настоящий сайт, хотя никакого интернета не требует и никто снаружи её не видит. Если порт занят другой программой, Live Server возьмёт соседний — 5501, 5502, и адрес в браузере изменится.

Классическая путаница первых дней: страница открыта двойным щелчком (file:///), а студент правит файл и ждёт, что она обновится сама. Не обновится. Сначала посмотрите в адресную строку: если там нет 127.0.0.1, значит, Live Server не запущен.

5. Инструменты разработчика

Инструменты разработчика (DevTools) открываются клавишей F12 или сочетанием Ctrl + Shift + I. Это отдельная панель с вкладками. Сегодня нам нужны две, но знать стоит про четыре.

ВкладкаДля чегоКогда пригодится
Elementsразметка страницы и стили; можно менять прямо на местедни 24–26
Consoleвывод программы и выполнение кодасегодня и всегда
Sourcesфайлы скриптов, точки останова, пошаговое выполнениесегодня, во второй половине
Networkзапросы к серверу: что ушло и что пришлодень 31
Панель можно прицепить справа, снизу или вынести в отдельное окно: три точки в углу DevTools → Dock side. На маленьком ноутбуке удобнее отдельное окно.

Вкладка Elements: потрогать страницу руками

Откройте Elements и щёлкните по любому заголовку на странице. Справа появятся его стили, а сам текст можно изменить двойным щелчком прямо в разметке. Страница сразу перерисуется.

Важно понимать: эти изменения временные. Вы правите не файл, а то, что сейчас показано в браузере. Обновите страницу — всё вернётся. Зато можно за секунду проверить идею: а если заголовок сделать красным? А если убрать картинку?

Откройте эту лекцию, включите Elements, найдите заголовок дня и поменяйте его текст на своё имя. Затем нажмите F5 и убедитесь, что файл не пострадал.

Режим телефона

В DevTools есть значок с телефоном и планшетом (Ctrl + Shift + M). Он показывает страницу так, как её увидят с телефона, и позволяет выбрать размер экрана.

Для нашего курса это особенно важно: конспекты и задания студенты чаще читают с телефона, а не за компьютером. Каждый раз, когда вы что-то делаете со страницей, проверяйте её в этом режиме — привычка сэкономит много переделок.

Вкладка Sources: ваши файлы

Здесь лежат все файлы, которые загрузила страница. Слева дерево файлов, посередине — код, справа — панель отладки, к которой мы вернёмся в конце лекции. Главное, что нужно знать сейчас: если вашего app.js здесь нет, значит, он и не подключился.

6. Консоль: вывод данных

Объект console — это набор команд для вывода. Самая известная из них — log, но остальные тоже экономят время.

console.log("обычное сообщение");
console.info("информация");
console.warn("предупреждение");   // жёлтая строка
console.error("ошибка");          // красная строка

Разница между ними не только в цвете. В консоли есть фильтр по уровням: можно показать только ошибки и предупреждения, спрятав обычные сообщения. В большой программе это спасает.

log принимает сколько угодно значений через запятую и печатает их подряд:

const name = "Аман";
const marks = [5, 4, 5];

console.log("Ученик:", name, "оценки:", marks);
// Ученик: Аман оценки: (3) [5, 4, 5]
Не склеивайте значения плюсом без нужды: console.log("оценки: " + marks) превратит массив в строку "5,4,5", и вы потеряете возможность раскрыть его в консоли. Запятая лучше плюса.

Таблицы и объекты

Когда данных много, обычный вывод превращается в кашу. Метод console.table рисует настоящую таблицу:

const students = [
  { name: "Аман", mark: 5 },
  { name: "Мерет", mark: 4 },
  { name: "Гүлнар", mark: 5 },
];

console.table(students);

Объекты мы будем разбирать на дне 21, но пользоваться таблицей можно уже сейчас: она одинаково хорошо показывает и массивы, и списки объектов.

Метод console.dir показывает значение как дерево свойств. Для обычных данных разницы с log почти нет, а вот для элемента страницы разница большая: log покажет разметку, а dir — все свойства объекта.

console.log(document.body);   // разметка
console.dir(document.body);   // свойства объекта

Ловушка с раскрытием объектов

Когда в консоль выводят объект или массив, рядом появляется треугольник: его можно раскрыть и посмотреть содержимое. Но есть тонкость, из-за которой новички теряют часы.

const cart = ["хлеб"];
console.log(cart);     // в консоли: ["хлеб"]  — но раскройте позже...
cart.push("чай");      // ...и увидите два элемента

Консоль показывает не снимок, сделанный в момент вывода, а живой объект: содержимое подтягивается, когда вы раскрываете строку. Если массив изменился позже, вы увидите уже новое состояние и решите, что код сработал не так.

Как получить честный снимок:

console.log(cart.join(", "));        // строка — уже не изменится
console.log(structuredClone(cart));  // копия объекта
console.table(cart);                 // таблица рисуется сразу

Подстановки: аккуратный вывод

В строку вывода можно вставить значения через специальные знаки. Их называют подстановками:

const name = "Аман";
const mark = 5;

console.log("Ученик %s получил %d", name, mark);
// Ученик Аман получил 5

console.log("%cВажное сообщение", "color: white; background: #f59e0b; padding: 2px 8px;");
ЗнакЧто вставляет
%sтекст
%d или %iцелое число
%fдробное число
%oобъект
%cстиль для следующего текста

Приём с %c используют библиотеки, чтобы выделять свои сообщения цветом. Иногда им предупреждают в консоли: «не вставляйте сюда чужой код» — как раз то, о чём мы говорили вчера.

Что ещё умеет сама консоль

Кроме методов объекта console, в консоли работают несколько команд самого браузера. В файле их писать нельзя — только в консоли:

7. Группы, время и счётчики

Три инструмента, о которых новички обычно не знают, а они решают три частые задачи.

Группы: свернуть лишнее

console.group("Проверка оценок");
console.log("Аман: 5");
console.log("Мерет: 4");
console.groupEnd();

console.groupCollapsed("Подробности");  // группа сразу свёрнута
console.log("длинный список...");
console.groupEnd();

Время: сколько выполнялось

console.time("подсчёт");
let sum = 0;
for (let i = 0; i < 1000000; i++) {
  sum = sum + i;
}
console.timeLog("подсчёт");   // промежуточная отметка
console.timeEnd("подсчёт");   // подсчёт: 5.2 ms

Имя в кавычках связывает начало и конец. Замеров может быть несколько одновременно, если имена разные.

Счётчики: сколько раз сюда зашли

function greet(name) {
  console.count("вызовов greet");
  console.log("Привет, " + name);
}

greet("Аман");    // вызовов greet: 1
greet("Мерет");   // вызовов greet: 2
console.countReset("вызовов greet");

Это выручает, когда функция вызывается чаще, чем вы ожидали, — частая причина «тормозов» на странице.

Проверки и след вызовов

const age = 15;
console.assert(age >= 18, "возраст меньше 18");   // выведет, только если условие ложно

console.trace();     // покажет, откуда вызвали эту строку
console.clear();     // очистить консоль

Ещё два метода вы встретите в чужом коде: console.debug — то же, что log, но на уровне «подробности», и console.dirxml — вывод разметки деревом. Пользоваться ими необязательно, но узнавать полезно.

8. Отладка: debugger и точки останова

Вывод в консоль — не единственный способ понять, что происходит. Программу можно остановить в нужной строке и осмотреться: какие значения в переменных прямо сейчас.

Первый способ — слово debugger прямо в коде:

const price = 12;
const count = 7;

debugger;   // здесь программа остановится, если открыты DevTools

const total = price * count;
console.log(total);

Откройте страницу с открытыми DevTools — выполнение замрёт на этой строке, а справа появится список переменных с их значениями. Дальше работают кнопки: продолжить, шаг вперёд, зайти внутрь функции.

Второй способ удобнее: вкладка Sources, открываете свой файл и щёлкаете по номеру строки. Появится синий маркер — это точка останова. Кода она не требует и после закрытия браузера исчезает.

Не забывайте убирать debugger из кода перед тем, как показывать работу. Строка, оставленная в проекте, будет останавливать программу у каждого, кто откроет страницу с инструментами разработчика.

Справа от кнопок три полезных списка. Scope — переменные, которые видны в этом месте, с текущими значениями. Watch — выражения, за которыми вы попросили следить: добавьте туда price * count, и увидите результат на каждом шаге. Call Stack — цепочка вызовов: какая функция вызвала какую, чтобы попасть сюда.

Зачем это, если есть console.log? Вывод в консоль показывает одно значение в одной точке. Отладчик показывает все переменные сразу и позволяет идти по программе шаг за шагом. Когда ошибка непонятная, отладчик находит её за минуту, а «логами» её можно искать час.

Как хранить файлы курса

Договоримся о порядке с самого начала, чтобы через месяц не искать «тот файл с массивами»:

js-kurs/
  day-01/
    index.html
    app.js
  day-02/
    index.html
    app.js
  projects/
    todo/        // мини-проект дня 29
    catalog/     // мини-проект дня 32

Раз в неделю копируйте всю папку курса на флешку или в облако. Потерянный код — обычная история у начинающих, а восстановить его неоткуда.

9. Что делать, если «ничего не работает»

Порядок действий, который решает девять проблем из десяти на первой неделе:

1

Посмотрите в консоль. Красная строка — там написано, что не так и в какой строке.

2

Проверьте, сохранён ли файл. В VS Code несохранённый файл помечен точкой на вкладке.

3

Обновите страницу с очисткой кеша: Ctrl + F5. Браузер любит показывать старую версию файла.

4

Убедитесь, что скрипт подключён. Поставьте первой строкой console.log("файл работает"). Нет надписи — проблема в подключении, а не в коде.

5

Прочитайте имя файла и путь по буквам. Лишний пробел, заглавная буква или русская «с» вместо латинской «c» ломают всё молча.

Как увидеть, что файл не найден

Есть точный способ проверить подключение: вкладка Network. Откройте её и обновите страницу — появится список всего, что браузер запросил. Ищите строку app.js:

СтатусЧто значитЧто делать
200файл найден и загруженвсё в порядке, проблема в самом коде
404файла по такому пути нетпроверить имя и папку
строки нет совсембраузер его и не запрашивалпроверить строку <script> в разметке

Эти три состояния покрывают почти все проблемы с подключением. Привыкнув смотреть Network, вы перестанете гадать.

Число 404 стало известно далеко за пределами программирования: его печатают на футболках и пишут на страницах «ничего не найдено». Это просто код ответа сервера: «такого адреса у меня нет».

Подключение скрипта: <script src="app.js" defer></script> в <head>.

  1. Чем console.warn отличается от console.log?
    Ответ Цветом и уровнем: предупреждения можно отфильтровать в консоли отдельно от обычных сообщений.
  2. Как показать список учеников с оценками красиво?
    Ответ console.table(students) — выведет таблицей со столбцами.
  3. Зачем нужен Live Server, если страница открывается двойным щелчком?
    Ответ Он обновляет страницу сам и открывает её по адресу http://, а не file://: иначе браузер запретит загрузку данных и модулей.
  4. Что делает строка debugger?
    Ответ Останавливает выполнение в этом месте, если открыты инструменты разработчика, и позволяет посмотреть значения переменных.
  5. Первое, что нужно сделать, когда «ничего не работает»?
    Ответ Посмотреть в консоль и прочитать текст ошибки, затем проверить, сохранён ли файл.
