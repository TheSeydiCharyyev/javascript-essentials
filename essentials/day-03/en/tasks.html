Day 3. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-03 with the files index.html and app.js.

Warm-up

1. Who is of which type
Easy6 min

see that the type belongs to the value.

Open the console and ask typeof about each value in the list. Write the result down in your notebook in two columns: the value and the answer.

42        "Mary"        true        undefined        null
{ }       [1, 2]        console.log        10 / 0        "5" * 2
  • all ten answers are written down;
  • the answers that differ from what you expected are marked — there are at least two;
  • for each such answer there is one sentence: what you expected and what you got.
2. Six liars
Easy7 min

remember the list of falsy values through practice, not by heart.

Check each value with Boolean(...) and write down separately the ones that gave false.

const values = [0, 1, -1, "", " ", "0", [], { }, null, undefined, NaN];
There are six falsy values, but this list has fewer — some of the traps are truthy, although they look empty.
  • an answer is written down for each value;
  • all the falsy ones in the list are found;
  • it is explained why "0" and [] are truthy.
3. Predict first
Easy7 min

catch yourself on the traps of the plus and of comparison.

First write down in your notebook what you think each line prints. Only then check in the console and mark where you were wrong.

"3" + 4 + 5
3 + 4 + "5"
"10" - 5
123 == "123"
123 === "123"
0.1 + 0.2 === 0.3
  • the predictions are written down before the check;
  • the real answers are next to them;
  • for each difference there is one sentence — why it is so.

Main tasks

4. Report card: build the program
Medium15 min

run your first complete program of two files.

Create a folder day-03, make index.html and app.js in it and type the “Report card” program from section 12 of the lecture. Type it by hand, do not copy. Open the page through Live Server.

  • instead of “Calculating...” the page shows a line with the mark;
  • the same line is in the console;
  • the console is clean — there are no red messages;
  • <script> has defer.
5. Report card: your own data and a fourth branch
Medium12 min

change a working program without breaking it.

Improve the program from task 4:

  • put in your name and your marks — at least six;
  • add the number of marks to the output: how many there are in total;
  • add a fourth branch to the condition: if the mark is exactly 5 — “straight-A student”;
  • choose marks so that you see all four branches in turn.
The number of marks is student.marks.length. Put the new branch first: conditions are checked in order, and >= 4.5 would fire before “exactly 5”.
  • the line has the name, the mark, the number of marks and the verdict in words;
  • all four branches are shown and written down in the notebook with a set of marks for each;
  • the program still works without errors.
6. Three breakages
Medium12 min

learn to read an error message on your own code.

Break the program one time at a time, each time putting everything back. For each breakage, write down in a table: the kind of error, its text, the file and the line.

  1. remove the word defer from <script>;
  2. write the function name with a typo: avarage(student.marks);
  3. delete the closing curly brace of the function.
a table of three rows: what you broke → the kind of error → the line from the console.
Click an address like app.js:14:15 on the right in the console — the browser opens the file at the right line. This is the fastest way to find where the error is.
  • the kind of error is named for each breakage;
  • it is written down which line the browser pointed to;
  • it is explained why the third breakage does not let even the first line of the file run.
7. Take apart someone else’s code
Medium11 min

recognize parts of the language in unfamiliar code — the main skill of the day.

Copy this code into your notebook and label eight things on it: an object, an array, a function declaration, a function parameter, a variable that changes, a loop over values, a condition, a template literal.

const shop = {
  name: "Bereket",
  prices: [12, 40, 7.5],
};

function total(list) {
  let sum = 0;
  for (const price of list) {
    sum += price;
  }
  return sum;
}

const bill = total(shop.prices);

if (bill > 50) {
  console.log(`${shop.name}: expensive, ${bill.toFixed(2)} manat`);
} else {
  console.log(`${shop.name}: fine`);
}
  • all eight labels are in place;
  • without running it, it is written down what the program prints;
  • the answer is checked by running it and matches.

Starred tasks

8. Hunting four bugs
Hard10 min

go the whole way of debugging: from a dead file to the right number.

This code has four bugs. Type it into a new file, run it and fix them one at a time, reloading the page each time. For each one, write down the kind of error and what you did.

const marks = [5, 4, 3, 5];

function average(numbers) {
  let sum = 0;
  for (const n of numbers) {
    sum += numbers;
  }
  return
    sum / numbers.length;
}

const score = Average(marks);
console.log("Average mark: " + score.toFixed(2);
The bugs show themselves in turn, and that is no accident: while the file has a SyntaxError, not a single line runs. The fourth bug gives no message at all — it gives itself away with a wrong answer.
  • all four bugs are found;
  • for the first three the kind of error is named, for the fourth — why the browser stayed silent;
  • the fixed program prints “Average mark: 4.25”;
  • the order in which the bugs showed up is written down.
9. Your own program on the same model
Hard10 min

build a program from scratch, not from something already written.

Write your own program with the same structure, but about something else. Choose one: expenses for the week, temperature by day, travel time to school, the number of pages read in a week.

The program must have: an object with a name and an array of numbers, a function that calculates one number from the array, a condition with at least two branches, a template literal and output of the result both to the console and to the page.

You do not have to calculate the average. It can be the sum, or the number of days above normal — count with a loop, as in the “Report card”.
  • all five required parts are in place;
  • the program works without red messages in the console;
  • the result on the page matches the result in the console;
  • the variable names tell what is inside.
