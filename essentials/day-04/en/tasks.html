Day 4. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–2 are done in the console, the rest in the folder day-04.

Warm-up

1. const or let
Easy6 min

learn to choose the declaration word by meaning.

For each quantity, write a declaration line and choose const or let. Next to it, in one word — why.

  • the name of your city;
  • a counter of correct answers in a game;
  • the number of days in a week;
  • the current temperature outside;
  • a list of subjects in the timetable, to which one more will be added later.
The last item is a trap. Ask yourself: does the name change or the contents?
  • five declaration lines are written;
  • the reason for the choice is given for each;
  • the list of subjects is declared with const — and it is explained why this does not stop you from adding subjects.
2. What const forbids
Easy7 min

see the border between the name and the contents with your own eyes.

Run the lines one at a time and write down what the console answered: a value or an error.

const city = "Mary";
city = "Ashgabat";

const marks = [5, 4];
marks.push(3);
marks[0] = 2;
marks = [1];

const user = { name: "Aman" };
user.name = "Meret";
user.age = 17;
user = { };
  • the result is written down for each line;
  • all three lines that give an error are found;
  • the general rule is put into one sentence.
3. Predict first: visible or not
Easy7 min

catch the difference between let and var before running.

First write down in your notebook what each console.log prints. Then check in app.js, one fragment at a time: an error stops the file, and the following lines will not run.

// 1
if (true) {
  let a = 1;
  var b = 2;
}
console.log(b);
console.log(a);

// 2
console.log(c);
var c = 3;

// 3
console.log(d);
let d = 4;
  • the predictions are written down before the check;
  • the real answers are next to them, the differences are marked;
  • it is explained why two lines gave different errors.

Main tasks

4. The “Report card” on constants
Medium14 min

apply everything from today to a working program.

Copy the folder day-03 to day-04 and improve app.js:

  • move the thresholds 4.5 and 3.5 into the constants MIN_EXCELLENT and MIN_GOOD at the top of the file;
  • add one more mark to the array with push, without touching the declaration;
  • check that verdict is declared before if;
  • go through the file and change to const everything that does not change.
  • there are no bare numbers left in the conditions;
  • let stays only where the value really changes;
  • the program works, the console is clean;
  • it is written down how many let are left and why each one.
5. One threshold — the whole output
Medium10 min

understand why settings are moved into constants.

In the program from task 4, choose values of MIN_GOOD so that with the same marks you get all three verdicts in turn. Change only one line — the declaration of the constant.

a table: the value of MIN_GOOD → which verdict came out.
If you had to edit more than one line, a bare number is still left somewhere in the code. Find it.
  • the table of three rows is filled in;
  • each time exactly one line of the file was changed;
  • a conclusion is written down: how this is more convenient than numbers right in the condition.
6. The variable escaped from the block
Medium13 min

learn to fix the most common scope mistake.

This code does not work. Find the cause, fix it in two different ways and decide which is better.

const temperature = 31;

if (temperature > 30) {
  const advice = "stay at home";
} else {
  const advice = "you can go out";
}

console.log(`Today it is ${temperature} degrees: ${advice}`);
There are exactly two ways, and they are opposite: either move the declaration up above the block, or move the use down into the block. In the second case the output line will have to be written twice.
  • the kind of error and its cause are named;
  • both fixes work;
  • in the first fix you had to take let — it is explained why const does not fit here;
  • in the second fix const stayed — it is explained why it is allowed now;
  • it is written down which fix you would keep and why.
7. Rewrite old code
Medium13 min

be able to read var and bring code up to today’s rules.

Rewrite it with const and let using the algorithm from section 8 of the lecture. The program must print the same thing.

var prices = [12, 40, 7.5];
var total = 0;

for (var i = 0; i < prices.length; i++) {
  var price = prices[i];
  total = total + price;
}

var message = "Total: " + total + " manat";
console.log(message);
console.log(i);
  • there is no var left in the code;
  • for each variable it is explained why const or let;
  • the line that stops working after the rewrite is found;
  • it is written down why it worked before and what this says about var.

Starred tasks

8. A silent typo
Hard10 min

see why an undeclared variable is dangerous and learn to catch it.

This code gives no errors but calculates wrongly. Run it, find the cause, fix it.

let summa = 0;
const prices = [10, 20, 30];

for (const price of prices) {
  sumaa = summa + price;
}

console.log("Total:", summa);

Then do two experiments: type globalThis.sumaa in the console, and then put "use strict"; as the first line of the file and run it again.

  • it is named what exactly the program prints and what it should print;
  • it is written down what globalThis.sumaa answered and where this variable came from;
  • it is written down what changed after "use strict"; — with the exact text of the error;
  • a conclusion is made: why a typo in a name is harder to find than a syntax error.
9. Four traps
Hard10 min

bring together everything that behaves unexpectedly today.

For each fragment first write down a prediction, then check it and explain the difference in one sentence.

// 1
let n = 0;
for (let i = 0; i < 3; i++);
  n++;
console.log(n);

// 2
let x = y = 5;
console.log(globalThis.y);

// 3
for (var a of [1, 2, 3]);
console.log(a);

// 4
const frozen = Object.freeze({ value: 1 });
frozen.value = 99;
console.log(frozen.value);
None of the four gives an error in normal mode. That is exactly why they are dangerous: the program “works”, but the result is wrong.
  • the predictions are written down before running;
  • for each fragment the cause is named: an empty statement, an undeclared variable, the scope of var, a frozen object;
  • the fourth fragment is checked once more with "use strict";, the difference is written down;
  • the first fragment is rewritten so that it prints 3.
