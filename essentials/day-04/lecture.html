1. Зачем значению имя

Вчера мы видели карту всего языка. Сегодня берём первый кирпич и разбираем его до конца.

Программа работает со значениями: числами, строками, списками. Но значение без имени живёт одно мгновение — вычислилось и пропало. Чтобы вернуться к нему через десять строк, ему дают имя. Это и есть переменная: имя, за которым закреплено значение.

console.log(12 * 40 * 7.5);   // посчитали и забыли

const price = 12;             // а тут каждое число можно назвать
const count = 40;
const days = 7.5;
console.log(price * count * days);

Вторая запись длиннее, но через месяц вы поймёте, что она считает, а первую придётся разгадывать. Имена — это не удобство для компьютера, движку всё равно. Имена — для человека, который будет читать ваш код, и чаще всего этот человек — вы сами через полгода.

Переменная — подписанная коробка. Имя написано на крышке и не меняется, а содержимое можно заменить: положили одно, достали, положили другое. В школьной алгебре x означает неизвестное, которое надо найти. В программировании x — это ярлык на коробке, и вы сами кладёте туда что хотите.

У каждой переменной есть три свойства, и весь сегодняшний урок — про них:

СвойствоВопросГде разбираем
имякак её зовут и по каким правиламраздел 3
изменяемостьможно ли положить в неё другое значениеразделы 4–5
срок жизнис какой строки и до какой она существуетразделы 6–9

Первое свойство очевидно, второе понятно после одного примера. А вот третье — срок жизни — и есть то место, где новички теряют больше всего времени: переменная «есть», но почему-то не видна, или видна, но пустая. К концу урока обе ситуации станут предсказуемыми.

2. Объявление и инициализация

В строке let score = 42; две разные вещи, и у каждой своё название:

  • объявление — let score. Оно заводит имя, и с этого момента обращение к нему не вызывает ошибки;
  • инициализатор — = 42. Он кладёт в коробку первое значение.

Инициализатор можно не писать. Тогда в переменной окажется undefined — «ничего не клали»:

let score;
console.log(score);   // undefined

score = 42;           // положили позже
console.log(score);   // 42

То есть let score = 42; — это ровно то же самое, что let score; score = 42;, просто в одну строку.

У const инициализатор обязателен. Логика простая: значение константы нельзя заменить потом, поэтому пустая константа была бы навсегда пустой — почти наверняка это описка программиста, и язык её не пропускает. 
const total;   // SyntaxError: Missing initializer in const declaration

Несколько переменных в одной строке

После let или const можно перечислить несколько имён через запятую. Причём следующий инициализатор уже видит предыдущее имя:

let width = 3, height = 4;
let base = 10, doubled = base * 2;   // doubled = 20

Запятая здесь — просто разделитель списка, а не оператор. Пишут так редко: отдельная строка на каждую переменную читается лучше и удобнее правится. Но знать эту запись надо, потому что в старом коде она встречается постоянно.

А вот похожая строка, которая делает совсем не то, чего от неё ждут:

let a = b = 5;

console.log(a);              // 5 — как и ожидали
console.log(globalThis.b);   // 5 — а вот это сюрприз

Движок читает это как let a = (b = 5). Сначала выполняется присваивание b = 5 — а b нигде не объявлена, и потому молча становится глобальной переменной. Потом её значение попадает в a. Одна переменная объявлена как надо, вторая — случайная глобальная. Про этот механизм подробнее в разделе 10.

3. Имена переменных

Имя переменной на языке документации называется идентификатором. Правила такие:

ПравилоМожноНельзя
первый символ — буква, _ или $name, _tmp, $el2fast
дальше можно и цифрыtemp99, user2user-2
без пробелов и дефисовfirstNamefirst name
не зарезервированное словоresultclass, return

Буквы — любые из Unicode, так что технически это работает:

const Früh = "рано";     // немецкая буква в имени — допустимо
const счёт = 10;         // кириллица тоже допустима

Но так не делают. Весь код вокруг вас — библиотеки, примеры, документация — на английском, и смесь двух языков в одном файле читается плохо. Договоримся на весь курс: имена пишем латиницей.

Регистр имеет значение. score, Score и SCORE — три разные переменные. Это причина половины сообщений «is not defined» в первую неделю: объявили userName, а обратились к username.

Если забыть имя совсем, движок ругается сразу. В Chrome сообщение такое:

var = 5;   // SyntaxError: Unexpected token '='

В Firefox та же ошибка называется понятнее — SyntaxError: missing variable name. Это нормально: у одной ошибки в разных браузерах разный текст. Смысл один, а слова подбирает тот, кто писал движок. На MDN такие страницы озаглавлены по формулировке Firefox, так что не удивляйтесь расхождению с тем, что видите в Chrome.

Комментарии и одна ловушка

Раз уж мы говорим о том, как язык читает наш текст: комментарии бывают двух видов, и оба движок просто выбрасывает, как пробелы.

// однострочный — до конца строки

/* многострочный
   комментарий */

Ловушка в том, что многострочные комментарии не вкладываются друг в друга. Первая же последовательность */ закрывает комментарий, а всё, что после неё, движок снова читает как код:

/* внешний /* внутренний */ хвост */
console.log("сюда не дойдём");

Комментарий закончился на первом */, дальше движок увидел слово хвост, потом *, потом / — и решил, что началось регулярное выражение. Сообщение получается совершенно загадочное:

// SyntaxError: Invalid regular expression: missing /

Запомните это сочетание: непонятная ошибка про регулярное выражение — ищите лишний */. Обычно так получается, когда комментируют кусок кода, в котором уже был комментарий.

5. const: что запрещает и что нет

const запрещает переприсваивание — попытку привязать имя к другому значению:

const city = "Мары";
city = "Ашхабад";   // TypeError: Assignment to constant variable.

А вот чего он не запрещает — и это удивляет каждого второго:

const basket = ["хлеб", "чай"];
basket.push("рис");        // работает! ошибки нет
console.log(basket);       // ["хлеб", "чай", "рис"]

const user = { name: "Аман" };
user.name = "Мерет";       // тоже работает
user.age = 17;             // и добавить свойство можно

Почему так? Вспомните день 3: объект и массив передаются по ссылке. В переменной лежит не сам список, а адрес списка. const запрещает поменять адрес — но не запрещает прийти по этому адресу и переставить вещи внутри.

Если нужно запретить и содержимое, есть Object.freeze(объект). Правда, в обычном режиме попытка изменить замороженный объект просто молча ничего не делает, а ошибку TypeError: Cannot assign to read only property вы увидите только в строгом режиме. Строгий режим — тема курса 3, а freeze пригодится уже в проектах.

6. Блок — это фигурные скобки

Блок — пара фигурных скобок с инструкциями внутри. Он нужен там, где язык ждёт одну инструкцию, а нам надо несколько:

if (score > 4) {
  console.log("молодец");     // блок из двух инструкций
  count = count + 1;
}

Блоки стоят у if, у циклов, у функций. Но блок бывает и сам по себе, без всякого условия — просто скобки:

{
  const tmp = "временное значение";
  console.log(tmp);
}
// здесь tmp уже не существует

Так иногда делают нарочно, чтобы временная переменная не мешалась дальше в файле. И именно это свойство блока — главное на сегодня.

Там, где язык ждёт одну инструкцию, объявление поставить нельзя — только через блок: 
if (true) let a = 1;
// SyntaxError: Lexical declaration cannot appear in a single-statement context

if (true) { let a = 1; }   // так правильно
Запрет разумный: переменная, объявленная без скобок, всё равно была бы никому не видна.

Ещё одна тонкость про скобки. Если строка начинается с {, движок считает это блоком, а не объектом:

{ "x": 1 }        // SyntaxError: Unexpected token ':'

const obj = { "x": 1 };   // а так это объект — скобки стоят не в начале строки

На практике это редко мешает, потому что объекты почти всегда кладут в переменную или передают в функцию. Но знать стоит: одни и те же скобки означают разное в зависимости от того, где стоят.

7. Где переменная видна

Область, в которой переменная существует, называется областью видимости. Их три, и они вложены друг в друга:

Проверим это кодом. Сначала let:

if (true) {
  let y = 5;
}
console.log(y);   // ReferenceError: y is not defined

А теперь ровно то же самое с var:

if (true) {
  var x = 5;
}
console.log(x);   // 5 — переменная пережила блок

Для var фигурные скобки if, цикла или try вообще не являются границей. Границей для него служит только функция. Доходит до смешного:

for (var a of [1, 2, 3]);
console.log(a);   // 3 — счётчик цикла остался жить после цикла

Обратная сторона блочной области — затенение: внутри блока можно завести переменную с тем же именем, и она не тронет внешнюю.

let s = 1;
{
  let s = 2;        // это другая переменная
  console.log(s);   // 2
}
console.log(s);     // 1 — внешняя цела

Работает это и в другую сторону: изнутри блока или функции прекрасно видно всё, что объявлено снаружи. Видимость идёт только вглубь:

const tax = 0.05;

function withTax(price) {
  return price + price * tax;   // tax объявлена снаружи, и она видна
}

console.log(withTax(100));      // 105

Это свойство мы разберём всерьёз в курсе 2 — оно называется замыканием и лежит в основе многих приёмов языка. Сегодня достаточно запомнить направление: внутрь видно, наружу нет.

const в цикле

Отдельный вопрос, который встаёт у всех на второй неделе. В цикле for...of счётчик объявляют через const — и это работает:

for (const n of [1, 2, 3]) {
  console.log(n);   // 1, 2, 3
}

А в обычном for такой же const ломается:

for (const i = 0; i < 3; i++) { }
// TypeError: Assignment to constant variable.

Причина в том, как устроены эти два цикла. В обычном for переменная одна на весь цикл, и i++ каждый раз меняет её значение — константу так менять нельзя. А в for...of на каждом проходе создаётся новая переменная, в которую кладут очередной элемент; её никто не меняет, поэтому const подходит.

Отсюда привычка, которой стоит следовать с первого дня: for...of — пишем const, обычный for — пишем let. Сами циклы разберём на днях 10 и 11.

8. Почему var больше не пишут

Слово var — единственный способ объявить переменную в JavaScript до 2015 года. Его не убрали и не уберут: в интернете миллионы страниц со старым кодом, и они обязаны работать. Но в новом коде его не пишут, и вот три причины.

Первая — не уважает блок. Мы только что видели: переменная вылезает из if и из цикла и живёт дальше. Из-за этого две далёкие строки внезапно оказываются связаны.

Вторая — молча объявляется повторно. Объявили переменную дважды — язык не возразит, а старое значение пропадёт:

var total = 100;
var total = 5;      // ни ошибки, ни предупреждения
console.log(total); // 5

let sum = 100;
let sum = 5;        // SyntaxError: Identifier 'sum' has already been declared

В файле на двести строк такое случается легко, и let тут работает как страховка.

Третья — засоряет глобальный объект. Объявленная в файле переменная var становится свойством глобального объекта (в браузере это window), а let и const — нет:

var a = 1;
let b = 2;
console.log(globalThis.a);   // 1        — var попала в глобальный объект
console.log(globalThis.b);   // undefined — let не попала

Чем это плохо: подключили чужую библиотеку, а у неё внутри своя var config — и ваша переменная с тем же именем тихо затёрлась.

var вы всё равно увидите — в старых проектах, в ответах на форумах, в примерах десятилетней давности. Его нужно уметь читать, поэтому мы его и разбираем. Писать — не нужно.

Как переписать старый код

Нашли пример с var и хотите привести его к сегодняшним правилам? Порядок такой:

  1. заменить каждое var на const;
  2. запустить: там, где движок скажет TypeError: Assignment to constant variable., поменять на let;
  3. если появится ReferenceError — значит, код рассчитывал, что переменная вылезет из блока. Такое место надо разобрать руками: обычно объявление нужно поднять выше блока.
// было
for (var i = 0; i < items.length; i++) {
  var item = items[i];
  console.log(item);
}

// стало
for (let i = 0; i < items.length; i++) {
  const item = items[i];      // новая переменная на каждом проходе
  console.log(item);
}

Первые два шага механические, и движок сам показывает, где именно нужен let. Третий шаг требует подумать — зато обычно именно там и прячется настоящая ошибка старого кода.

9. Обращение до объявления

Что будет, если обратиться к переменной раньше строки, где она объявлена? Ответ зависит от слова, которым её объявили, и это четвёртое отличие var.

console.log(bar);   // undefined — var ведёт себя тихо
var bar = 1;

console.log(foo);   // ReferenceError: Cannot access 'foo' before initialization
let foo = 2;

Объявления var движок обрабатывает заранее, до выполнения кода, — как будто поднимает их в начало функции. Это называется поднятием. Но поднимается только объявление, а присваивание остаётся на месте. Поэтому переменная уже существует, но пока пустая:

Что написано
console.log(x);
var x = 3;
Как понял движок
var x;
console.log(x);   // undefined
x = 3;

У let и const так не выйдет. От начала блока до строки объявления переменная находится в мёртвой зоне: имя уже занято, но трогать его нельзя.

Обратите внимание на третью строку схемы. Оператор typeof, который обычно безопасен и для несуществующих имён отвечает "undefined", в мёртвой зоне тоже падает:

console.log(typeof nothingAtAll);   // "undefined" — имени вообще нет, и это не ошибка

{
  console.log(typeof i);            // ReferenceError: Cannot access 'i' before initialization
  let i = 10;
}

Звучит придирчиво, но на деле это подарок: язык ловит опечатку в тот момент, когда вы её сделали, а не через сто строк, когда в расчёт уже попал undefined.

А функции?

С функциями история третья, и её стоит узнать сейчас, потому что вы наверняка уже видели такой код и удивлялись. Функция, объявленная словом function, поднимается целиком — вместе с телом. Поэтому её можно вызвать выше того места, где она написана:

console.log(greet("Аман"));   // "Салам, Аман!" — работает

function greet(name) {
  return `Салам, ${name}!`;
}

А вот функция, положенная в переменную, подчиняется правилам переменной — и потому так не умеет:

hi();                         // ReferenceError: Cannot access 'hi' before initialization
const hi = () => "салам";

hi2();                        // TypeError: hi2 is not a function
var hi2 = function () { };    // var поднял имя, но значение ещё не присвоено

Обратите внимание на разные ошибки в последнем примере. С const движок говорит «нельзя трогать», с var — «это не функция»: имя-то уже есть, в нём лежит undefined, а вызвать undefined нельзя. Сами функции разбираем на днях 12–15, здесь важно одно: поднимается только запись через function.

Зачем вообще придумали мёртвую зону, если можно было сделать как у var? Посмотрите на const. Его обещание — «значение не меняется». Но если бы обращение до объявления возвращало undefined, получилось бы вот что: 
console.log(PI);   // undefined ?
const PI = 3.14;
console.log(PI);   // 3.14 ?
Одна и та же константа дала бы два разных значения — ровно то, что const обязан исключить. Мёртвая зона закрывает эту дыру: до строки объявления константы просто нет, и спорить не о чем. А раз правило нужно для const, его сделали одинаковым и для let.

10. Необъявленная переменная

Отдельный случай — присвоить значение имени, которое вообще не объявляли:

totl = 42;   // ни let, ни const, ни var

Ошибки не будет. Язык создаст глобальную переменную сам — это поведение осталось с девяностых. И вот чем оно опасно. Представьте опечатку:

let total = 0;
totl = total + 5;        // опечатались в имени
console.log(total);      // 0 — а мы ждали 5

Никто не ругнулся, программа работает, число неправильное. Такую ошибку ищут долго, потому что искать нечего: в консоли пусто.

Отсюда правило без исключений: каждая переменная объявлена словом const или let. Не ради красоты — ради того, чтобы опечатка сразу стала видимой ошибкой ReferenceError, а не тихо неверным результатом.

В строгом режиме язык такое уже запрещает и бросает ReferenceError: totl is not defined. Строгий режим включается строкой "use strict"; и сам собой действует внутри модулей; подробно — в курсе 3.

Как такую ошибку ловят на практике, если строгий режим не включён? Есть три приёма, и все три вам пригодятся:

  • первой строкой файла поставить "use strict"; — самый простой способ превратить тихое поведение в честную ошибку прямо сегодня;
  • проверить globalThis — если подозреваете случайную глобальную, наберите в консоли globalThis.totl. Ответ не undefined означает, что переменная создалась «сама»;
  • поставить в редакторе линтер — программу, которая читает код и находит такие места до запуска. Про неё поговорим ближе к проектам.
Проверьте всё сами прямо на лекции. Откройте консоль и выполните две строки по очереди: slucaynaya = 1;, затем globalThis.slucaynaya. Вторая ответит 1 — переменной, которую вы не объявляли, теперь место в глобальном объекте.

11. Шесть сообщений дня

Все ошибки этого дня — про переменные. Вот они вместе, с текстом из Chrome:

КодСообщениеЧто не так
const x = 1; x = 2; TypeError: Assignment to constant variable. пытаемся заменить значение константы
const x; SyntaxError: Missing initializer in const declaration у константы нет начального значения
var = 5; SyntaxError: Unexpected token '=' забыли имя переменной
console.log(a); let a = 1; ReferenceError: Cannot access 'a' before initialization обращение в мёртвой зоне
"use strict"; b = 5; ReferenceError: b is not defined присваивание необъявленной (только в строгом режиме)
Object.freeze(o); o.x = 2; TypeError: Cannot assign to read only property свойство только для чтения (только в строгом режиме)

Два последних сообщения в обычном режиме не появляются: присваивание необъявленной молча работает, а запись в замороженный объект молча не работает. Это и есть главный довод в пользу строгого режима — он превращает тихие странности в честные ошибки.

Все шесть читаются по одному алгоритму, и он же годится для любой будущей ошибки про переменные. Сначала смотрим на вид ошибки — он говорит, когда она случилась.

ВидКогда случилосьПервый вопрос к себе
SyntaxError до запуска, при чтении файла что я написал не по правилам в этой строке?
ReferenceError во время работы, при чтении имени это имя вообще объявлено — и выше ли по коду?
TypeError во время работы, при записи я не пытаюсь ли изменить то, что менять нельзя?

Разница между первым и двумя остальными особенно полезна. SyntaxError означает, что не выполнилась ни одна строка файла — движок даже не начинал. Если вы видите такую ошибку, бессмысленно искать причину в логике: дело в скобке, кавычке или пропущенном имени. А ReferenceError и TypeError появляются на ходу, и значит, всё, что было до них, уже отработало — этим можно пользоваться, сужая поиск.

12. Инструкция-выражение и пустая инструкция

Две маленькие темы, которые закрывают картину из дня 3.

Инструкция-выражение — это когда выражение стоит само по себе, как целая инструкция. Так выглядит почти каждая строка вашей программы:

count = count + 1;        // присваивание
console.log("Салам");     // вызов функции
count++;                  // увеличение

Результат такого выражения никуда не сохраняется — значит, смысл есть только тогда, когда у выражения есть побочное действие: что-то изменилось или что-то вывелось. Строка 2 + 2; синтаксически верна, но бесполезна: посчитали и выбросили.

Пустая инструкция — одинокая точка с запятой. Она означает «здесь ничего не делаем» и нужна там, где язык требует хоть какую-то инструкцию. Чаще, впрочем, она появляется случайно — и это классическая ловушка:

let n = 0;
for (let i = 0; i < 3; i++);   // ← лишняя точка с запятой
  n++;

console.log(n);   // 1, а не 3

Точка с запятой закрыла цикл. Цикл трижды выполнил «ничего», а n++ оказался снаружи и сработал один раз. Отступ обманывает глаз, ошибки нет — просто неверный ответ.

13. Как выбирать и как называть

Правило выбора на весь курс, ровно два шага:

  1. пишем const;
  2. если оказалось, что значение надо заменить, — меняем на let.

Почему в таком порядке, а не наоборот: const сообщает читателю «это значение дальше не изменится» — одной строкой стало меньше того, за чем нужно следить. И движок подстрахует, если вы присвоите по ошибке.

Теперь имена. Правила языка мы разобрали, а вот договорённости людей:

ЧтоКак пишутПример
обычная переменнаяcamelCase — со второго слова с большой буквыfirstName, totalPrice
настройка, которую не меняютUPPER_CASE через подчёркиваниеMAX_SCORE, MIN_GOOD
«да / нет»начинают с is, hasisReady, hasError
списокво множественном числеmarks, students
Хорошее имя отвечает на вопрос «что внутри», а не «какого оно типа». d — плохо, data — почти так же плохо, daysLeft — хорошо. Длинное понятное имя лучше короткого загадочного: набирать его вы будете секунду, а читать — месяцами.

Посмотрите, как одни только имена меняют читаемость. Вот код, который считает стоимость заказа:

Непонятно
let a = 12;
let b = 40;
let c = 0.05;
let d = a * b;
let e = d + d * c;
Понятно
const price = 12;
const count = 40;
const TAX = 0.05;
const subtotal = price * count;
const total = subtotal + subtotal * TAX;

Обе программы считают одно и то же, и движку они одинаковы. Но в левой невозможно заметить ошибку: если перепутать c и d, никто не удивится. В правой subtotal * TAX читается как предложение, и total * price сразу выглядело бы странно.

Заодно обратите внимание на вторую разницу: слева пять let, хотя ни одно значение не меняется. Справа — пять const, и это сообщает читателю, что следить тут не за чем.

14. «Табель» на переменных

Вернёмся к вчерашней программе и перепишем её по сегодняшним правилам. Изменилось три вещи, и каждая — из сегодняшней лекции.

Пороги стали именованными константами. Вчера в условии стояли голые числа 4.5 и 3.5. Такие числа называют «магическими»: через месяц никто не вспомнит, что они означают, а если порог встречается в трёх местах, менять придётся все три и одно обязательно забудут. Константа наверху файла решает обе беды сразу.

Оценки добавляются в массив, который объявлен через const. Это прямая проверка раздела 5: имя заперто, содержимое — нет.

verdict объявлен снаружи блока. Самое важное изменение, и ниже мы посмотрим, что будет, если этого не сделать.

const MIN_EXCELLENT = 4.5;      // настройки вынесли наверх и назвали
const MIN_GOOD = 3.5;

const student = {
  name: "Аман",
  marks: [5, 4, 5, 3, 5],
};

student.marks.push(4);          // const не мешает: меняем содержимое, не имя

function average(numbers) {
  let sum = 0;                  // sum меняется в цикле — значит let
  for (const n of numbers) {
    sum += n;
  }
  return sum / numbers.length;
}

const score = average(student.marks);

let verdict;                    // объявлен ЗДЕСЬ, снаружи блоков
if (score >= MIN_EXCELLENT) {
  verdict = "отлично";
} else if (score >= MIN_GOOD) {
  verdict = "хорошо";
} else {
  verdict = "надо подтянуть";
}

console.log(`${student.name}: ${score.toFixed(2)} — ${verdict}`);
Аман: 4.33 — хорошо

Последний кусок — самый важный на сегодня. Посмотрите, что будет, если объявить verdict внутри условия:

if (score >= MIN_GOOD) {
  const verdict = "хорошо";     // объявили ВНУТРИ блока
}
console.log(verdict);           // ReferenceError: verdict is not defined

Переменная родилась и умерла внутри скобок. Отсюда приём, которым пользуются каждый день: если значение нужно после блока — объявите его до блока через let, а внутри только присваивайте.

Откройте вчерашнюю папку day-03, сохраните копию как day-04 и внесите эти изменения. Затем поменяйте MIN_GOOD на 4.4 и посмотрите, как одна строка меняет вывод. Ради этого пороги и выносят в константы наверх файла.

// имена

  1. Чем let x; отличается от const x;?
    Ответ Первое допустимо: в x окажется undefined. Второе — SyntaxError: у константы инициализатор обязателен.
  2. Почему const arr = [1]; arr.push(2); не даёт ошибки?
    Ответ const запрещает заменить значение переменной, то есть адрес массива. Сам массив остаётся изменяемым, push меняет содержимое по тому же адресу.
  3. Что выведет код: if (true) { var a = 1; let b = 2; } console.log(a);?
    Ответ 1. Для var блок не граница. А console.log(b) дал бы ReferenceError.
  4. Чем отличается вывод console.log(v) перед var v = 1 и перед let v = 1?
    Ответ С var — undefined: объявление поднято, присваивание нет. С let — ReferenceError: Cannot access 'v' before initialization: переменная в мёртвой зоне.
  5. Чем опасна строка totl = 5; без let?
    Ответ В обычном режиме она молча создаст глобальную переменную. Если это опечатка в имени, программа продолжит работать с неверными данными и ничего не сообщит.
