День 5. Типы данных

Выжимка лекции: восемь типов, typeof, null и undefined, NaN, превращения и проверки.

Главное

JavaScript динамический — тип принадлежит значению, а не переменной. И слабо типизированный — при встрече разных типов язык приводит их сам, без ошибки. Отсюда все сегодняшние странности.
Семь примитивов неизменяемы — их можно только заменить целиком. Объект — единственный изменяемый тип и единственный, что передаётся по ссылке.

typeof

typeof 42;            // "number"      typeof "Мары";   // "string"
typeof true;          // "boolean"     typeof undefined; // "undefined"
typeof 9n;            // "bigint"      typeof Symbol();  // "symbol"
typeof { };           // "object"      typeof function(){}; // "function"

typeof null;          // "object"   ← ошибка языка 1995 года
typeof [1, 2];        // "object"   ← массив не отличается
typeof neObyavlena;   // "undefined" — единственный оператор, что не падает
Ответов ровно восемь, список закрытый. null проверяем через === null, массив — через Array.isArray().

Язык подставляет undefined в четырёх случаях: let x;, несуществующее свойство, функция без return, пропущенный аргумент. Ошибки при этом нет.

NaN

typeof NaN;           // "number" — это числовое значение
NaN === NaN;          // false — единственное, не равное себе
NaN > 1;  NaN < 1;    // оба false — любое сравнение ложно

Number.isNaN(x);      // правильная проверка
isNaN("салам");       // true — сначала превращает в число, осторожно
Number.isNaN("салам");// false
NaN заразен: любое действие с ним даёт NaN. Число, пришедшее от пользователя, проверяйте сразу, а не в конце расчёта.

Infinity

1 / 0;                 // Infinity — деление на ноль не ошибка
Number.MAX_VALUE * 2;  // Infinity
Infinity - Infinity;   // NaN
42 / -0;               // -Infinity — нулей два, +0 и -0

Ложны ровно шесть: false, 0, "", NaN, null, undefined. Всё остальное истинно — в том числе "0", [] и {}.
new Boolean(false) — объект, и он истинен. Boolean, Number, String пишем без new.

Шпаргалка проверок

typeof x === "number" && !Number.isNaN(x)   // число
typeof x === "string"                       // строка
typeof x === "function"                     // функция
Array.isArray(x)                            // массив
typeof x === "object" && x !== null && !Array.isArray(x)   // объект
x === null;   x === undefined;   x == null  // пустота
!x                                          // любое ложное — осторожно, ноль тоже!

Две ошибки

// ReferenceError: schet is not defined   — имени нет
// TypeError: Cannot read properties of undefined (reading 'marks')
//                                        — имя есть, значение не то
Как чинить TypeError. Сообщение называет свойство в скобках: (reading 'marks'). Виновато не оно, а то, что слева от точки. В цепочке a.b.c.d запись (reading 'd') означает, что пустым оказалось a.b.c. Идите влево и ищите, откуда там взялась пустота.
  1. Выпишите в тетрадь таблицу typeof для всех восьми типов и отметьте два места, где ответ не совпадает с типом.
  2. Проверьте в консоли Number(), String() и Boolean() на значениях "", "0", [], null, undefined. Запишите все 15 ответов.
  3. Допишите в «Табель» функцию, которая превращает введённую строку в оценку и возвращает null, если это не число. Проверьте на "5", "пять", "".
  4. Напишите условие, которое отличает «пользователь ввёл ноль» от «пользователь ничего не ввёл». Объясните, почему if (!x) тут не подходит.
