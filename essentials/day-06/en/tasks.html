Day 6. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-06.

Warm-up

1. Plus or joining
Easy6 min

catch the difference between addition and joining.

First predict the result of each line in your notebook, then check.

2 + 3
"2" + 3
2 + "3"
1 + 2 + "3"
"1" + 2 + 3
"10" - 5
"10" * 2
true + true
  • the predictions are written down before the check;
  • the real answers are next to them, the differences are marked;
  • it is explained why two lines with the same numbers gave different results.
2. The remainder in practice
Easy7 min

master % on simple tasks.

Calculate in the console and write down the answers:

  • whether the number 2026 is even;
  • the last digit of 2026;
  • the last two digits of 2026;
  • how many full weeks there are in 100 days and how many days are left;
  • 10 % 0 — what you get.
Full weeks are division with the fractional part dropped: Math.floor(100 / 7).
  • all five answers are written down;
  • for the weeks both numbers are shown — the whole ones and the remainder;
  • it is explained why 10 % 0 gives exactly this result.
3. Postfix versus prefix
Easy7 min

see what each form returns.

Run each fragment on fresh variables and write down both values.

let i = 5;
const a = i++;
console.log(a, i);

let j = 5;
const b = ++j;
console.log(b, j);

let k = 5;
k++;
console.log(k);
  • the values are written down for all three fragments;
  • it is explained why the form does not matter in the third fragment;
  • it is written down what const c = 1; c++; gives and why.

Main tasks

4. Time from seconds
Medium13 min

apply division and the remainder together.

Write a function formatTime(sec) that turns a number of seconds into a string of the form “h:mm:ss”. Check it on the values 65, 600, 3725 and 0.

formatTime(3725);   // "1:02:05"
formatTime(65);     // "0:01:05"
Hours are Math.floor(sec / 3600). Minutes are Math.floor(sec / 60) % 60. Seconds are sec % 60. A leading zero can be added with a condition or with String(m).padStart(2, "0").
  • all four values give the right answer;
  • minutes and seconds are printed with a leading zero;
  • it is written down what division is responsible for and what the remainder is responsible for;
  • it is checked that formatTime(0) does not break.
5. The bill for an order
Medium13 min

build a formula from several steps without mixing up the order.

An item costs 1200, 3 of them are bought, there is a 10% discount, then 5% tax on the resulting sum. Calculate the total, splitting the calculation into named steps and printing each one.

Then answer two questions by changing the code:

  • how much it comes to if the tax is calculated before the discount, not after;
  • how much it comes to without any discount.
three sums and a conclusion: whether the order “discount — tax” affects the total.
  • the calculation is split into at least three steps with clear names;
  • each step is printed to the console;
  • all three sums are calculated;
  • a conclusion about the order is made and backed up by numbers.
6. A carousel both ways
Medium12 min

use the remainder for a circular counter and fix going backward.

There is an array ["Mon", "Tue", "Wed", "Thu", "Fri"] and a variable i = 0. Write two lines: one moves i forward around the circle, the other backward. Check that a step back from i = 0 gives the last day, not an error.

Forward is simple. Backward, (i - 1) % n does not work — check what it returns and remember the formula from section 6 of the lecture.
  • a step forward from “Fri” gives “Mon”;
  • a step back from “Mon” gives “Fri”;
  • it is written down what the naive version (i - 1) % 5 returns when i = 0;
  • it is explained why arr[-1] is not an error but undefined.
7. The “Report card” with statistics
Medium12 min

bring the course program up to a real calculation.

Copy the folder day-05 to day-06 and add to the “Report card”:

  • the sum of all marks with +=;
  • the average with two digits after the decimal point;
  • the percentage of the maximum (the maximum is 5), as a whole number;
  • a list output numbered from one, where every second row is marked;
  • how many marks are even and how many are odd.
  • all five items work;
  • the average is not printed as 4.333333333333333;
  • the numbering starts from 1, not from 0;
  • even and odd are counted with %, not by listing.

Starred tasks

8. Take care of the pennies
Hard10 min

see the problem of fractional precision and get around it.

Run these and write down the results:

0.1 + 0.2
0.1 + 0.2 === 0.3
(0.1 + 0.2).toFixed(2)
Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON
Math.round(1.005 * 100) / 100
0.1 * 3

Then calculate the cost of three items in two ways — with fractional numbers and with whole numbers (in tenge, dividing only for output) — for two prices: 12 manat 50 tenge and 1 manat 10 tenge. Compare the results in both cases.

For one of the two prices both ways give the same thing, for the other they do not. This is the most interesting part: the error does not always appear, which means it is hard to catch with tests.
  • all six results are written down;
  • it is explained why Math.round(1.005 * 100) gives something other than expected;
  • both versions of the calculation are written for both prices — four numbers;
  • the price on which the ways differed is named;
  • a conclusion is made about how to store money and why “it works for me anyway” is a bad argument.
9. Six traps
Hard10 min

bring together everything that behaves unexpectedly today.

For each fragment first write down a prediction, then check it — each fragment separately — and explain the difference in one sentence.

// 1
let x = 10;
x += "5";
console.log(x, typeof x);

// 2
console.log(-10 % 3);

// 3
console.log(2 ** 3 ** 2);

// 4
console.log(-2 ** 2);

// 5
let y = 5;
if (y = 0) { console.log("entered"); }
console.log(y);

// 6
console.log([] + [], [] + { });
One fragment will not run at all. The other five quietly give an unexpected result — that is more dangerous.
  • the predictions are written down before running;
  • the only fragment with an error is found, its kind and text are written down;
  • for the other five the cause is named: joining in +=, the sign of the remainder, the right associativity of exponentiation, assignment in a condition, the conversion of objects;
  • fragments 3, 4 and 5 are rewritten so that they do what is expected of them.
