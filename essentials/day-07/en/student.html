Day 7. Comparison and logic

A summary of the lecture: === versus ==, order, logical operators, ??, the ternary operator.

The main points

Comparisons answer “yes” or “no”. Logical operators join several answers into one. Together they give the program the ability to choose.
A rule without exceptions: we write only === and !==. The only justified place for == is the check value == null, which catches null and undefined at once.

=== versus ==

5 === 5;          // true    type + value
5 === "5";        // false   different types — false right away
5 == "5";         // true    converts types

"0" == 0;         // true   \
"" == 0;          // true    } == is not transitive: A=B, B=C, but A≠C
"0" == "";        // false  /

({}) === ({});    // false   two different objects
[1,2] === [1,2];  // false   and two different arrays
Objects are compared by reference, not by contents. A workaround is JSON.stringify(a) === JSON.stringify(b), but it depends on the order of properties.

Greater and less

"10" > 9;      // true    the string became a number
"10" > "9";    // false   both are strings — character by character!
"Z" < "a";     // true    capital letters come before small ones
"a" > 1;       // false \  the string did not become a number — NaN,
"a" < 1;       // false /  and both comparisons are false

null == 0;     // false
null > 0;      // false
null >= 0;     // true  ← a contradiction: == has its own rule for null
< > <= >= have no strict version — the types are always converted. A range is written only with two comparisons: mark >= 2 && mark <= 5. The form 2 <= mark <= 5 is always true.

Logical operators

1 && "salam";      // "salam"  — they return an OPERAND, not true
0 && "salam";      // 0
"" || "Guest";     // "Guest"
1 && 2 && 3;       // 3        all are truthy → the last one
!0;                // true     ! always gives true/false

&& — the first falsy or the last. || — the first truthy or the last.

Negation changes the conjunction: !(a && b) is !a || !b, and !(a || b) is !a && !b. It is better not to flip at all: give the condition a name and write !canEnter.

Short-circuit evaluation

false && f();          // f() will NOT be called — the answer is already clear
true || f();           // it will not be called either

const name = input || "Guest";   // a fallback value
const title = user && user.name; // protection from null

?? instead of ||

0 || 10;        // 10   ← || works on all six falsy values
0 ?? 10;        // 0    ← ?? only on null and undefined
"" || "Guest";  // "Guest"
"" ?? "Guest";  // ""
false ?? 10;    // false

// null || undefined ?? "foo";   → SyntaxError: Unexpected token '??'
(null || undefined) ?? "foo";   // "foo" — parentheses are needed
The question for choosing: are zero and the empty string normal data? A quantity, a score, a temperature — yes, take ??. A name that must not be empty — ||.

The ternary operator

condition ? value_if_yes : value_if_no

const status = age >= 18 ? "adult" : "child";
console.log(`${count} ${count === 1 ? "ticket" : "tickets"}`);

const grade = score >= 90 ? "5"
  : score >= 75 ? "4"
  : "3";

if is a statement, it does not return a value. The ternary operator is an expression, and its result can be assigned to a const right away.

When to use what. The result goes to the right of = or into ${ } — the ternary operator. The result goes nowhere, these are just actions — if...else. More than three branches — if...else if.
The comma operator (1, 2, 3) returns the last value; it lives practically only in the head of for: i++, j--.
