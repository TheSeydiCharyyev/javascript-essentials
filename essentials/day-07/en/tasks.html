Day 7. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-07.

Warm-up

1. The truth table
Easy6 min

learn &&, || and ! in practice.

Fill in the table for all four combinations of a and b: a && b, a || b, !a. First in your notebook, then check in the console.

  • the table of four rows is filled in before the check;
  • all twelve values matched the console;
  • the rule is written down in words: when && says “yes”, and when || does.
2. First predict: equal or not
Easy7 min

see where == differs from ===.

For each pair predict two answers — with == and with ===. Then check.

const pairs = [
  [1, "1"],
  [0, false],
  [0, ""],
  [null, undefined],
  [null, 0],
  [NaN, NaN],
  [[], false],
];
  • fourteen predictions are written down before the check;
  • the differences are marked;
  • a pair is found where == and === gave the same answer, and it is explained why.
3. What it returns, not “true or false”
Easy7 min

remember that && and || give back an operand.

Write down not “yes / no” but the specific value that each line returns.

1 && "salam"
0 && "salam"
"" || "Guest"
"Aman" || "Guest"
1 && 2 && 3
null || 0 || "" || "last"
!0
!!"text"
  • for all eight lines a value is written down, not true/false;
  • for each one the typeof of the result is given;
  • it is explained how the behavior of ! differs from the other two operators.

Main tasks

4. A valid mark
Medium12 min

write a range check and not get caught by the types.

Write a function isValidMark(mark): it returns true if this is a number from 2 to 5 inclusive. Check it on the list and write down the answers:

const marks = [2, 5, 1, 9, 3.5, "4", null, undefined, NaN];
Two traps. The string "4" turns into a number in a comparison and passes the range check — unless you cut it off separately. And NaN fails any comparison, but typeof NaN is "number".
  • all nine values are checked, the answers are written down;
  • "4" does not pass — it is explained what would happen without the type check;
  • NaN does not pass;
  • the range is written with two comparisons, not as 2 <= mark <= 5;
  • it is written down what the naive form 2 <= mark <= 5 returns for mark = 9, and why.
5. || versus ??
Medium12 min

understand when each operator puts in a fallback value.

For each value calculate x || "fallback" and x ?? "fallback" and fill in the table.

const values = [0, "", false, NaN, null, undefined, "text", 42];

Then solve two tasks and explain the choice of operator in each:

  • the setting “how many items to show on a page”, 10 by default, but the user can set 0 to show all of them;
  • a caption under a photo, “No caption” by default; an empty string should not be shown.
  • the 8 × 2 table is filled in;
  • all the values on which the operators differed are found — there are four of them;
  • for both tasks an operator is chosen and the choice is explained;
  • it is written down what happens if you take || in the first task.
6. Rewrite with the ternary
Medium13 min

see where the ternary operator fits and where it does not.

Three fragments. Rewrite two with the ternary operator, leave the third as it is and explain why.

// 1
let label;
if (count === 1) { label = "item"; } else { label = "items"; }

// 2
let price;
if (isMember) { price = 800; } else { price = 1000; }

// 3
if (isReady) {
  console.log("ready");
  sendReport();
} else {
  console.log("waiting");
}
  • the first two are rewritten and work;
  • in both the variable is declared with const — it is explained why this is possible now;
  • the third is left with if, the reason is named;
  • the rule of choice is put into one sentence.
7. The “Report card” with data checking
Medium13 min

put the whole day together in a working program.

Copy the folder day-06 to day-07 and improve the “Report card”:

  • leave the garbage in the array of marks: [5, 4, 5, 3, 5, 4, 9, 1];
  • count only the marks from 2 to 5, and treat the rest as skipped;
  • take a fallback name if the name is empty;
  • make the verdict with the ternary operator, with three branches;
  • protect the division: if there are no valid marks, the average must be 0, not NaN.
  • all five items work;
  • there is not a single == in the code;
  • on the array [9, 1, 0] the program prints 0.00, not NaN;
  • it is written down how many marks were counted and how many were skipped.

Starred tasks

8. The non-transitivity of ==
Hard10 min

work out to the end why == does not deserve trust.

Run three lines and explain each one separately: what type the operands are, what turned into what, why the answer is what it is.

console.log("0" == 0);
console.log("" == 0);
console.log("0" == "");

Then find one more such triple yourself — three values where two equalities are true and the third is false.

A hint for your own triple: take false, a number and a string. See the conversion rules in the lecture, section 3.
  • for each of the three lines the types of the operands and the result of the conversion are named;
  • it is explained why the third line behaves differently;
  • your own triple is found and checked;
  • it is written down what this property means in practice.
9. Six traps
Hard10 min

bring together everything that behaves unexpectedly today.

For each fragment first write down a prediction, then check it and explain the difference in one sentence.

// 1
console.log("10" > "9");

// 2
console.log(null == 0, null >= 0);

// 3
const mark = 9;
console.log(2 <= mark <= 5);

// 4
console.log([1, 2, 3] === [1, 2, 3]);

// 5
console.log(null || undefined ?? "foo");

// 6
const x = 5;
console.log(x !== 1 || x !== 2);
One fragment will not run at all. Two more give true where false is expected — and this is more dangerous, because the program will simply go down the wrong branch. Check the fragments one at a time: if you paste the whole block, not a single fragment will run because of that one.
  • the predictions are written down before running;
  • the fragment with an error is found, its kind and text are written down;
  • for the other five the cause is named: comparing strings, the null rule for ==, a chain of comparisons, comparison by reference, the conjunction in a negation;
  • fragments 1, 3 and 6 are rewritten so that they do what is expected of them.
