День 7. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке day-07.

Разминка

1. Таблица истинности
Легко6 мин

выучить &&, || и ! на практике.

Заполните таблицу для всех четырёх сочетаний a и b: a && b, a || b, !a. Сначала в тетради, потом проверьте в консоли.

  • таблица из четырёх строк заполнена до проверки;
  • все двенадцать значений совпали с консолью;
  • записано правило словами: когда «да» у &&, когда у ||.
2. Сначала предскажи: равно или нет
Легко7 мин

увидеть, где == расходится с ===.

Для каждой пары предскажите два ответа — через == и через ===. Потом проверьте.

1 и "1"
0 и false
0 и ""
null и undefined
null и 0
NaN и NaN
[] и false
  • четырнадцать предсказаний записаны до проверки;
  • расхождения отмечены;
  • найдена пара, где == и === дали одинаковый ответ, и объяснено почему.
3. Что вернёт, а не «истина или ложь»
Легко7 мин

запомнить, что && и || отдают операнд.

Запишите не «да / нет», а конкретное значение, которое вернёт каждая строка.

1 && "салам"
0 && "салам"
"" || "Гость"
"Аман" || "Гость"
1 && 2 && 3
null || 0 || "" || "последний"
!0
!!"текст"
  • для всех восьми строк записано значение, а не true/false;
  • для каждой указан typeof результата;
  • объяснено, чем отличается поведение ! от двух других операторов.

Основные задания

4. Годная оценка
Средне12 мин

написать проверку диапазона и не попасться на типах.

Напишите функцию isValidMark(mark): возвращает true, если это число от 2 до 5 включительно. Проверьте на списке и запишите ответы:

2      5      1      9      3.5      "4"      null      undefined      NaN
Две ловушки. Строка "4" при сравнении превратится в число и пройдёт проверку диапазона — если её не отсечь отдельно. И NaN провалит любое сравнение, но typeof NaN это "number".
  • все девять значений проверены, ответы записаны;
  • "4" не проходит — объяснено, что бы случилось без проверки типа;
  • NaN не проходит;
  • диапазон записан двумя сравнениями, а не 2 <= mark <= 5;
  • записано, что вернёт наивная запись 2 <= mark <= 5 для mark = 9, и почему.
5. || против ??
Средне12 мин

понять, когда какой оператор подставляет запасное значение.

Для каждого значения посчитайте x || "запас" и x ?? "запас" и заполните таблицу.

0      ""      false      NaN      null      undefined      "текст"      42

Затем решите две задачи и объясните выбор оператора в каждой:

  • настройка «сколько товаров показывать на странице», по умолчанию 10, но пользователь может поставить 0, чтобы показывать все;
  • подпись под фотографией, по умолчанию «Без подписи», пустую строку показывать не надо.
  • таблица 8 × 2 заполнена;
  • найдены все значения, на которых операторы разошлись — их четыре;
  • для обеих задач выбран оператор и объяснён выбор;
  • записано, что будет, если в первой задаче взять ||.
6. Переписать на тернарный
Средне13 мин

увидеть, где тернарный оператор уместен, а где нет.

Три фрагмента. Два перепишите на тернарный оператор, третий оставьте как есть и объясните почему.

// 1
let label;
if (count === 1) { label = "штука"; } else { label = "штук"; }

// 2
let price;
if (isMember) { price = 800; } else { price = 1000; }

// 3
if (isReady) {
  console.log("готово");
  sendReport();
} else {
  console.log("ждём");
}
  • первые два переписаны и работают;
  • в обоих переменная объявлена через const — объяснено, почему теперь можно;
  • третий оставлен с if, причина названа;
  • сформулировано правило выбора одним предложением.
7. «Табель» с проверкой данных
Средне13 мин

собрать день целиком в работающей программе.

Скопируйте папку day-06 в day-07 и доработайте «Табель»:

  • в массиве оценок оставьте мусор: [5, 4, 5, 3, 5, 4, 9, 1];
  • считайте только оценки от 2 до 5, остальные считайте отброшенными;
  • имя возьмите запасное, если оно пустое;
  • вердикт сделайте тернарным оператором, три ветки;
  • защитите деление: если годных оценок нет, средний балл должен быть 0, а не NaN.
  • все пять пунктов работают;
  • в коде нет ни одного ==;
  • на массиве [9, 1, 0] программа выводит 0.00, а не NaN;
  • записано, сколько оценок засчитано и сколько отброшено.

Со звёздочкой

8. Нетранзитивность ==
Сложно10 мин

разобрать до конца, почему == не заслуживает доверия.

Выполните три строки и объясните каждую отдельно: какого типа операнды, что во что превратилось, почему такой ответ.

console.log("0" == 0);
console.log("" == 0);
console.log("0" == "");

Затем найдите ещё одну такую тройку сами — три значения, где два равенства истинны, а третье ложно.

Подсказка для своей тройки: возьмите false, число и строку. Правила приведения смотрите в лекции, раздел 3.
  • для каждой из трёх строк названы типы операндов и результат приведения;
  • объяснено, почему третья строка ведёт себя иначе;
  • найдена и проверена своя тройка;
  • записано, что это свойство означает на практике.
9. Шесть ловушек
Сложно12 мин

собрать вместе всё, что сегодня ведёт себя неожиданно.

Для каждого фрагмента сначала запишите предсказание, потом проверьте и объясните расхождение одним предложением.

// 1
console.log("10" > "9");

// 2
console.log(null == 0, null >= 0);

// 3
const mark = 9;
console.log(2 <= mark <= 5);

// 4
console.log([1, 2, 3] === [1, 2, 3]);

// 5
console.log(null || undefined ?? "foo");

// 6
const x = 5;
console.log(x !== 1 || x !== 2);
Один фрагмент не запустится вообще. Ещё два дают true там, где ожидается false — и это опаснее, потому что программа просто пойдёт не по той ветке.
  • предсказания записаны до запуска;
  • найден фрагмент с ошибкой, записан её вид и текст;
  • для остальных пяти названа причина: сравнение строк, правило null для ==, цепочка сравнений, сравнение по ссылке, союз в отрицании;
  • фрагменты 1, 3 и 6 переписаны так, чтобы делали то, что от них ожидают.
