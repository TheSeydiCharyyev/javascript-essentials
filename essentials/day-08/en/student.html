Day 8. Type conversion and precedence

A summary of the lecture: three contexts of conversion, the answer to the question of day 7, the precedence table, syntax errors.

The main points

Type conversion is turning a value of one type into another. There are only three directions: to a string, to a number, to a boolean. Every operator knows in advance which one it needs.
The main danger of silent conversion is that it never crashes. A type error in JavaScript is not a message in the console but a wrong number in a report.

Number("") is 0, not NaN. An empty input field gives an honest zero and passes Number.isNaN. Emptiness has to be checked before converting: input.trim() === "".

The answer to the question of day 7

"0" == 0;    // different types → both to numbers → 0 == 0 → true
"" == 0;     // different types → both to numbers → 0 == 0 → true
"0" == "";   // the types MATCH → nothing to convert → character by character → false

Number("0") and Number("") give one and the same zero — that is the whole answer. The third pair never gets to numbers at all. Different types — a different route, hence the lack of transitivity.

One value, five answers

const x = [];
if (x) { }      // goes in   — truthy
`${x}`;         // ""        — to a string
x + 1;          // "1"       — "" and joining
x - 1;          // -1        — "" → 0
x == false;     // true      — through a number

Number versus parseInt

Number("42px");   // NaN   parseInt("42px");   // 42
Number("");       // 0     parseInt("");       // NaN
Number("3.9");    // 3.9   parseInt("3.9");    // 3

Number() requires the whole string to be a number. For checking input — use it. For pulling a number out of "16px" — parseInt (day 17).

Converting by yourself

Number(x);   +x        // to a number
String(x);   `${x}`    // to a string
Boolean(x);  !!x       // to a boolean
// do NOT write new before them — you will get a wrapper object
Convert types once, at the boundary of the program — where data comes from the user. Inside, let proper values travel. Then you will not need the tables.

Precedence

( )  →  . [ ] f()  →  ++ -- ! unary + -  →  **
     →  * / %  →  + -  →  < > <= >=  →  === !== == !=
     →  &&  →  || ??  →  ? :  →  =  →  ,

It is easier to remember the pattern: arithmetic → comparison → logic. That is why 1 + 2 === 3 && 2 > 1 works without parentheses.

10 - 5 - 2;    // 3     left to right
2 ** 3 ** 2;   // 512   right to left
a = b = 7;     // right to left
a || b && c;   // && binds tighter — put parentheses!

Where to look. The browser shows where it stumbled, not where the mistake is. Unexpected end of input almost always means an unclosed bracket — look for it higher up in the file, not on the line shown. Remember: a SyntaxError switches off the whole file, and not a single line will run.
[object Object] in the output means an object was printed instead of text. Write console.log("data:", obj) with a comma, not with a plus.
