Day 8. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-08.

Warm-up

1. The conversion table
Easy7 min

see all three directions on the same values.

For each value calculate String(), Number() and Boolean(). Fill in an 8 × 3 table.

const values = ["0", " ", "", [0], [null], [1, 2], null, undefined];
Three values will give zero in the Number() column, although they look empty or nothing like zero. Find them.
  • the table is filled in before checking in the console;
  • all 24 values are checked;
  • all the cases where Number() gave 0 are marked;
  • it is explained why Boolean("0") and Boolean([]) are true.
2. One value, five contexts
Easy6 min

feel that the result depends on the place, not on the value.

Take const x = []; and run five lines. For each one write down the result and which type the array was converted to.

x ? "truthy" : "falsy";
`${x}`;
x + 1;
x - 1;
x == false;
  • five results are written down;
  • for each one the direction of conversion is given;
  • it is explained why x + 1 and x - 1 gave different results.
3. Who is calculated first
Easy7 min

check the precedence table in practice.

First predict, then check. For each line write down the order of steps.

2 + 3 * 4;
(2 + 3) * 4;
10 - 5 - 2;
2 ** 3 ** 2;
1 + 2 === 3 && 2 > 1;
true || false && false;
  • the predictions are written down before the check;
  • for each line the order of operations is written out step by step;
  • two lines are found where the order turned out not to be left to right;
  • it is explained why the last line gives true.

Main tasks

4. The route of a comparison
Medium12 min

take the mechanism of == apart to the end.

For each pair write out the route in three lines: what types, what turned into what, what the result is.

"0" == 0;
"" == 0;
"0" == "";
true == 1;
"1" == true;
null == 0;
[] == false;
for each pair: types → after conversion → result.
The pair "1" == true goes through two conversions: first true becomes a number, then the string. Follow both steps.
  • the route is written out for all seven pairs;
  • a pair is found where there was no conversion at all, and it is explained why;
  • a pair is found where there were two conversions;
  • it is written down what === gives for each pair.
5. A check at the boundary
Medium14 min

write a function after which only valid data travels through the program.

Write toMark(input): it takes a string from an input field and returns a number from 2 to 5, or null if the input is invalid. Check it on the list:

const inputs = ["4", "  5  ", "", "  ", "five", "9", "3.5", "4px"];
The order of the checks matters. Catch emptiness before Number() — otherwise the empty string will become zero and get into the range check with the wrong message.
  • all eight values are checked, the answers are written down;
  • "" and " " give null;
  • "4px" gives null — it is written down what parseInt would give and why it does not fit here;
  • the order of the checks is written down, and it is explained what breaks if you swap them.
6. Hunting a SyntaxError
Medium12 min

learn to find the place of the mistake, not the place of the message.

Type this file and run it. Fix the errors one at a time, rerunning it each time. For each one write down: the text of the message, the line number in the console and the number of the line where the mistake really is.

function total(a, b) {
  const sum = a + b;
  console.log("sum: " + sum);

const price = 3px;
const name = "Aman;
console.log(name);
The first error the browser shows is not the first one in the file. Fix from top to bottom only after you understand where the message points.
  • all three errors are found, and the order in which the browser showed them is written down;
  • for each one both lines are written down: the one shown and the real one;
  • it is noted that for two errors the lines matched, and for one they did not;
  • it is explained why they differed for that one and why the message pointed to the end of the file;
  • the fixed file prints the name and the sum without errors.
7. The “Report card”: cleaning the input
Medium12 min

apply conversion to real data from a form.

Copy the folder day-07 to day-08. Replace the array of marks with a “raw” one, as if from input fields, and process it:

const raw = ["5", "4", "", "  3  ", "five", "9", "5"];

The program must build two lists: the accepted marks (as numbers) and the rejected ones — with the reason for each.

  • exactly four marks are accepted, all of them numbers, not strings;
  • each rejected one has its own reason: empty, not a number, out of range;
  • " 3 " is accepted — it is explained why;
  • it is checked with typeof that the accepted list holds numbers;
  • the average is calculated only from the accepted marks.

Starred tasks

8. Number or parseInt
Hard10 min

understand when each conversion function fits.

Fill in the table: for each string calculate Number(), parseInt() and parseFloat().

const strings = ["42", "42px", "px42", "", "  7  ", "3.9", "1e3"];

Then solve two tasks and explain the choice of function:

  • the user types an age into a field — you need to check that a number was entered;
  • you need to get 16 out of the string "16px" taken from the styles of the page.
  • the 7 × 3 table is filled in;
  • all the strings where the functions differed are found;
  • for both tasks a function is chosen and the choice is explained;
  • it is written down what happens if you take parseInt in the first task and the user types "18 years".
9. Six traps
Hard10 min

bring together everything that behaves unexpectedly today.

For each fragment first write down a prediction, then check it and explain the difference in one sentence.

// 1
const input = "";
console.log(Number(input), Number.isNaN(Number(input)));

// 2
console.log([5] + 1, [5] - 1);

// 3
const student = { name: "Aman" };
console.log("Student: " + student);

// 4
console.log(typeof 1 + 1);

// 5
console.log(true || false && false);

// 6
console.log("" == 0, "0" == 0, "0" == "");
Not a single fragment gives an error — all six quietly return something other than what it seems. That is exactly why type conversion is dangerous.
  • the predictions are written down before running;
  • for each one the cause is named: the empty string as zero, ToPrimitive of an array, an object in a string context, the precedence of typeof, the precedence of &&, the routes of ==;
  • fragments 3 and 4 are rewritten so that they print what is expected;
  • for fragment 1 a correct check of empty input is written.
