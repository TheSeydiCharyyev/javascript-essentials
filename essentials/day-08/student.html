День 8. Приведение типов и приоритет

Выжимка лекции: три контекста приведения, ответ на вопрос дня 7, таблица приоритетов, синтаксические ошибки.

Главное

Приведение типов — превращение значения из одного типа в другой. Направлений всего три: к строке, к числу, к логическому. Каждый оператор заранее знает, какое ему нужно.
Главная опасность молчаливого приведения — оно никогда не падает. Ошибка типов в JavaScript это не сообщение в консоли, а неверное число в отчёте.

Number("") это 0, а не NaN. Пустое поле ввода даст честный ноль и пройдёт Number.isNaN. Проверять пустоту надо до превращения: input.trim() === "".

Ответ на вопрос дня 7

"0" == 0;    // типы разные → оба в число → 0 == 0 → true
"" == 0;     // типы разные → оба в число → 0 == 0 → true
"0" == "";   // типы СОВПАЛИ → приводить нечего → посимвольно → false

Number("0") и Number("") дают один и тот же ноль — вот и вся разгадка. Третья пара до чисел вообще не доходит. Разные типы — разный маршрут, отсюда и нетранзитивность.

Одно значение, пять ответов

const x = [];
if (x) { }      // войдёт    — истинен
`${x}`;         // ""        — к строке
x + 1;          // "1"       — "" и склейка
x - 1;          // -1        — "" → 0
x == false;     // true      — через число

Number против parseInt

Number("42px");   // NaN   parseInt("42px");   // 42
Number("");       // 0     parseInt("");       // NaN
Number("3.9");    // 3.9   parseInt("3.9");    // 3

Number() требует, чтобы вся строка была числом. Для проверки ввода — он. Для вытаскивания числа из "16px" — parseInt (день 17).

Превращать самому

Number(x);   +x        // к числу
String(x);   `${x}`    // к строке
Boolean(x);  !!x       // к логическому
// new перед ними НЕ писать — получится объект-обёртка
Приводите типы один раз, на границе программы — там, где данные приходят от пользователя. Внутри пусть ходят нормальные значения. Тогда таблицы не понадобятся.

Проще запомнить закономерность: арифметика → сравнение → логика. Поэтому 1 + 2 === 3 && 2 > 1 работает без скобок.

10 - 5 - 2;    // 3     слева направо
2 ** 3 ** 2;   // 512   справа налево
a = b = 7;     // справа налево
a || b && c;   // && крепче — ставьте скобки!

Где искать. Браузер показывает, где споткнулся, а не где ошибка. Unexpected end of input почти всегда значит незакрытую скобку — ищите её выше по файлу, а не в указанной строке. Помните: SyntaxError отключает весь файл, ни одна строка не выполнится.
[object Object] в выводе — вывели объект вместо текста. Пишите console.log("данные:", obj) через запятую, а не через плюс.
  1. Заполните таблицу приведения для "0", " ", [0], [null] по трём колонкам. Сверьте с консолью.
  2. Объясните письменно, почему "0" == 0 истинно, а "0" == "" ложно. Нарисуйте маршрут каждого сравнения.
  3. Напишите функцию toMark(input), которая возвращает число или null. Проверьте на "4", " 5 ", "", "пять".
