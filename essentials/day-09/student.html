День 9. Условия

Выжимка лекции: if, лестница else if, switch, break и провал.

Главное

Ветвление — развилка: программа смотрит на условие и выбирает дорогу. Выполнится ровно одна ветка, после чего программа пойдёт дальше как обычно.
Фигурные скобки ставим всегда, даже для одной строки. Без них if забирает ровно одну инструкцию, а всё остальное выполняется всегда — и отступ это прячет.

if и лестница

if (mark === 5) {
  console.log("отлично");
} else if (mark === 4) {
  console.log("хорошо");
} else {
  console.log("остальное");
}

Лестница проверяется сверху вниз и останавливается на первой подошедшей ветке. Поэтому сверху ставят самое строгое условие.

if (score >= 50) ... else if (score >= 90) — при 95 сработает первая ветка, и отличник получит тройку. Нижние не сработают никогда.

Проверка на границах

// для порога 90 проверяем три значения
grade(89);  grade(90);  grade(91);

// дырка между ветками
if (score > 90) { g = "5"; }
else if (score < 90) { g = "4"; }
// при score === 90 переменная останется undefined

Ошибки живут на краях диапазонов, в середине всё обычно работает. У строк край — "" и " ", у массивов — пустой, у ввода — null и undefined.

Что считается условием

if (name) { }            // непустая строка — истина
if (marks.length) { }    // 0 ложь, значит «если не пусто»

// ложны только: false 0 "" NaN null undefined
if (count) и if (count !== undefined) расходятся на нуле и пустой строке. Если ноль — законные данные (счётчик, температура), пишите точную проверку.

Распутать вложенность

// 1. объединить через &&
if (isLoggedIn && hasTicket) { }

// 2. ранний выход — сначала отказы
if (mark === undefined) return "негодная";
if (mark < 2 || mark > 5) return "негодная";
return "годится";

// 3. дать условию имя
const isAdult = user !== null && user.age >= 18;
if (isAdult) { }

switch

switch (mark) {
  case 5:
    word = "отлично";
    break;          // забыли — провалится в следующую ветку!
  case "сб":
  case "вс":        // группировка: общий код на два значения
    word = "выходной";
    break;
  default:
    word = "неизвестно";
}
case — это метка входа, а не отдельная ветка. Совпадение говорит, откуда начать; останавливает только break. Сравнение — через ===, без приведения типов.

Три ловушки switch

// 1. весь switch — ОДИН блок
switch (x) {
  case 1: let a = 1; break;
  case 2: let a = 2; break;   // SyntaxError: already been declared
}
// лечится своими { } у ветки:
case 1: { let a = 1; break; }

// 2. default не обязан быть последним — но ставьте последним
// 3. диапазоны через switch не проверить — нужна лестница else if

Частые ошибки. if (x = 5) присваивает. Широкое условие выше узкого — нижние ветки мертвы. Забытый break проваливает выполнение дальше. Лестница без последней ветки молча возвращает undefined.
try...catch (день 11) — не замена проверкам. Что можно проверить условием — проверяйте условием.
  1. Напишите grade(score): 90 и выше — «5», 75 и выше — «4», 50 и выше — «3», иначе «2». Проверьте на шести граничных значениях: 49, 50, 74, 75, 89, 90.
  2. Перепишите эту же функцию через switch — и объясните письменно, почему это плохая идея.
  3. Напишите dayType(day) через switch с группировкой: «сб» и «вс» — выходной, остальные — рабочий, незнакомое — «не знаю такой день».
  4. Возьмите код с тремя уровнями вложенности из раздела 7 лекции и перепишите его двумя способами: через && и через ранний выход.
