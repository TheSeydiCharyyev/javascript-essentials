Day 11. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-11.

Warm-up

1. of versus in
Easy7 min

see the difference on the same array.

For the array [5, 4, 3] write two loops. In each, print the value of the variable and its typeof.

  • both loops are written, all six lines of output are written down;
  • it is explained what of gives and what in gives;
  • it is written down what type the variable has in each case;
  • what x + 1 prints in the loop with in is predicted and checked.
2. Go through an object
Easy6 min

learn to get both the key and the value.

For the object { name: "Aman", age: 17, city: "Mary" } print lines like name: Aman. Then try to go through the same object with for...of and write down what happens.

A value by key is taken with square brackets: user[key]. A dot will not do here — think about why.
  • the three lines are printed correctly;
  • the exact text of the error from for...of is written down;
  • it is explained why user.key does not work and user[key] does.
3. The first try...catch
Easy7 min

see that an error stops stopping the program.

Run it first without try, then with it. Write down both outputs.

console.log("before");
JSON.parse("{bad}");
console.log("after");
  • both outputs are written down;
  • it is explained why without try the line “after” is not printed;
  • in the version with try, e.name and e.message are printed;
  • finally is added, and it is checked that it runs.

Main tasks

4. Three traps of for...in
Medium12 min

understand why for...in is not used for arrays.

For each case write both loops — for...of and for...in — and write down what each one printed.

// A: an extra property
const a = [5, 4];
a.meta = "exam";

// B: a hole in an array
const b = [1];
b[5] = 6;

// C: arithmetic with a key
const c = [10, 20, 30];
// print key + 1 in a for...in loop
  • both outputs are written down for all three cases;
  • for A it is explained where the third element came from;
  • for B it is written down how many times each loop ran and why the numbers differ;
  • for C it is shown how to get a real number from a key.
5. Safe parsing
Medium12 min

write a function that does not crash on bad data.

Write safeParse(text): it returns an object if the string can be parsed, and null if it cannot. In catch print the type of the error. Check it on four strings:

const texts = [
  `{"name": "Aman", "age": 17}`,
  `{name: "Aman"}`,
  `[1, 2, 3]`,
  ``,
];
The last string is empty. Think in advance about what JSON.parse will do with it, and check your guess.
  • all four cases are checked, the answers are written down;
  • for each failure e.name and e.message are written down;
  • the function never crashed the program;
  • it is written down why exactly null is returned, not undefined — with a reference to day 5.
6. Your own errors
Medium13 min

throw an error with the right type and tell the types apart when catching.

Write checkAge(age):

  • not a number or NaN — throw a TypeError;
  • less than 0 or more than 120 — throw a RangeError;
  • otherwise return the age.

Then write a loop that runs the list [17, "five", -3, 200, 0, NaN] through it, catches the errors and writes its own message for each one, telling the types apart with instanceof.

  • all six values are handled, and none of them crashed the program;
  • the messages for TypeError and RangeError are different;
  • 0 passes the check — it is explained why this matters (day 7, || versus ??);
  • the catch has an else branch that rethrows an unfamiliar error.
7. The “Report card”: data from outside
Medium13 min

put both tools of the day together in the course program.

Copy the folder day-10 to day-11. The student’s data now comes as a string:

const raw = `{"name": "Aman", "marks": [5, 4, 9, 3, 5]}`;

Do the following:

  • parseStudent(text) — parses the string and returns null on failure;
  • checkMark(mark) — throws a TypeError or a RangeError;
  • a for...of loop over the marks, with a try inside; invalid marks are skipped with a message;
  • a for...in loop over the student — print all of its fields.
  • all four parts work;
  • 4 marks are counted, the average is 4.25;
  • try stands inside the loop — it is checked that when it is moved outside, the average changes, and it is written down to what;
  • a broken string gives a message and null, and the program does not crash.

Starred tasks

8. Where the error flies
Hard10 min

follow how an error goes up through the calls.

Type it in and run it. First predict the order of the lines in the output and which of them will not appear at all.

function level3() {
  console.log("level3 started");
  throw new RangeError("it broke deep down");
  console.log("level3 finished");
}

function level2() {
  console.log("level2 started");
  level3();
  console.log("level2 finished");
}

function level1() {
  console.log("level1 started");
  try {
    level2();
  } catch (e) {
    console.log("level1 caught:", e.name);
  }
  console.log("level1 finished");
}

level1();

Then move the try from level1 to level2 and see what changes.

  • the prediction is written down before running;
  • all the lines that did not run are named, and it is explained why;
  • the output of the second version is written down, and the differences are explained;
  • a conclusion is made: where to put try — next to the error or where you know what to do.
9. Six traps
Hard10 min

bring together everything that behaves unexpectedly today.

For each fragment first write down a prediction, then check it and explain the difference in one sentence.

// 1
const user = { name: "Aman" };
for (const v of user) { console.log(v); }

// 2
const marks = [5, 4, 3];
for (const i in marks) { console.log(i + 1); }

// 3
function f() {
  try { return "from try"; }
  finally { return "from finally"; }
}
console.log(f());

// 4
try { throw "just a string"; }
catch (e) { console.log(e.name, e.message); }

// 5
const a = [1];
a[5] = 6;
let n = 0;
for (const k in a) { n++; }
console.log(n);

// 6
try { JSON.parse("{bad}"); } catch (e) { }
console.log("all is fine?");
One fragment throws an error and stops the program — move it into a separate file, otherwise you will not be able to check the others. Fragment 6 does not crash, and that is its problem.
  • the predictions are written down before running;
  • the fragment that crashes is found, and the text of the error is written down;
  • for the others the cause is named: string keys, finally overrides return, a thrown string without properties, holes in an array, an empty catch;
  • fragments 2, 3, 4 and 6 are rewritten correctly;
  • for fragment 6 it is explained why an empty catch is dangerous in practice.
