День 11. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке day-11.

Разминка

1. of против in
Легко7 мин

увидеть разницу на одном и том же массиве.

Для массива [5, 4, 3] напишите два цикла. В каждом выводите значение переменной и её typeof.

  • оба цикла написаны, все шесть строк вывода записаны;
  • объяснено, что даёт of, а что in;
  • записано, какого типа переменная в каждом случае;
  • предсказано и проверено, что выведет x + 1 в цикле с in.
2. Перебрать объект
Легко6 мин

научиться доставать и ключ, и значение.

Для объекта { name: "Аман", age: 17, city: "Мары" } выведите строки вида name: Аман. Затем попробуйте перебрать этот же объект через for...of и запишите, что получится.

Значение по ключу берётся через квадратные скобки: user[key]. Точка тут не подойдёт — подумайте почему.
  • три строки выведены правильно;
  • записан точный текст ошибки от for...of;
  • объяснено, почему user.key не работает, а user[key] да.
3. Первый try...catch
Легко7 мин

увидеть, что ошибка перестаёт останавливать программу.

Запустите сначала без try, потом с ним. Запишите оба вывода.

console.log("до");
JSON.parse("{плохо}");
console.log("после");
  • записаны оба вывода;
  • объяснено, почему без try строка «после» не печатается;
  • в варианте с try выведены e.name и e.message;
  • добавлен finally, проверено, что он выполняется.

Основные задания

4. Три ловушки for...in
Средне12 мин

понять, почему for...in не берут для массивов.

Для каждого случая напишите оба цикла — for...of и for...in — и запишите, что вывел каждый.

// А: лишнее свойство
const a = [5, 4];
a.meta = "экзамен";

// Б: дырка в массиве
const b = [1];
b[5] = 6;

// В: арифметика с ключом
const c = [10, 20, 30];
// выведите ключ + 1 в цикле for...in
  • для всех трёх случаев записаны оба вывода;
  • для А объяснено, откуда взялся третий элемент;
  • для Б записано, сколько раз сработал каждый цикл и почему числа разные;
  • для В показано, как получить настоящее число из ключа.
5. Безопасный разбор
Средне12 мин

написать функцию, которая не падает на плохих данных.

Напишите safeParse(text): возвращает объект, если строка разбирается, и null, если нет. В catch выведите вид ошибки. Проверьте на четырёх строках:

`{"name": "Аман", "age": 17}`
`{name: "Аман"}`
`[1, 2, 3]`
``
Последняя строка — пустая. Подумайте заранее, что с ней сделает JSON.parse, и проверьте догадку.
  • все четыре случая проверены, ответы записаны;
  • для каждой неудачи записан e.name и e.message;
  • функция ни разу не уронила программу;
  • записано, почему возвращается именно null, а не undefined — со ссылкой на день 5.
6. Свои ошибки
Средне13 мин

бросать ошибку с правильным типом и различать типы при ловле.

Напишите checkAge(age):

  • не число или NaN — бросить TypeError;
  • меньше 0 или больше 120 — бросить RangeError;
  • иначе вернуть возраст.

Затем напишите цикл, который прогоняет через неё список [17, "пять", -3, 200, 0, NaN], ловит ошибки и для каждой пишет своё сообщение, различая типы через instanceof.

  • все шесть значений обработаны, ни одно не уронило программу;
  • сообщения для TypeError и RangeError разные;
  • 0 проходит проверку — объяснено, почему это важно (день 7, || против ??);
  • в catch есть ветка else, которая пробрасывает незнакомую ошибку дальше.
7. «Табель»: данные извне
Средне13 мин

собрать оба инструмента дня в программе курса.

Скопируйте папку day-10 в day-11. Данные о студенте теперь приходят строкой:

const raw = `{"name": "Аман", "marks": [5, 4, 9, 3, 5]}`;

Сделайте:

  • parseStudent(text) — разбирает строку, при неудаче возвращает null;
  • checkMark(mark) — бросает TypeError или RangeError;
  • цикл for...of по оценкам, внутри — try, негодные пропускаются с сообщением;
  • цикл for...in по студенту — вывести все его поля.
  • всё четыре части работают;
  • засчитано 4 оценки, средний 4.25;
  • try стоит внутри цикла — проверено, что при выносе наружу средний балл меняется, записано на какой;
  • испорченная строка даёт сообщение и null, программа не падает.

Со звёздочкой

8. Куда летит ошибка
Сложно10 мин

проследить, как ошибка поднимается по вызовам.

Наберите и запустите. Сначала предскажите порядок строк в выводе и какие из них не появятся вообще.

function level3() {
  console.log("level3 начал");
  throw new RangeError("сломалось глубоко");
  console.log("level3 закончил");
}

function level2() {
  console.log("level2 начал");
  level3();
  console.log("level2 закончил");
}

function level1() {
  console.log("level1 начал");
  try {
    level2();
  } catch (e) {
    console.log("level1 поймал:", e.name);
  }
  console.log("level1 закончил");
}

level1();

Затем перенесите try из level1 в level2 и посмотрите, что изменится.

  • предсказание записано до запуска;
  • названы все строки, которые не выполнились, и объяснено почему;
  • записан вывод второго варианта, отличия объяснены;
  • сделан вывод: где ставить try — рядом с ошибкой или там, где знаешь, что делать.
9. Шесть ловушек
Сложно12 мин

собрать вместе всё, что сегодня ведёт себя неожиданно.

Для каждого фрагмента сначала запишите предсказание, потом проверьте и объясните расхождение одним предложением.

// 1
const user = { name: "Аман" };
for (const v of user) { console.log(v); }

// 2
const marks = [5, 4, 3];
for (const i in marks) { console.log(i + 1); }

// 3
function f() {
  try { return "из try"; }
  finally { return "из finally"; }
}
console.log(f());

// 4
try { throw "просто строка"; }
catch (e) { console.log(e.name, e.message); }

// 5
const a = [1];
a[5] = 6;
let n = 0;
for (const k in a) { n++; }
console.log(n);

// 6
try { JSON.parse("{плохо}"); } catch (e) { }
console.log("всё хорошо?");
Один фрагмент бросает ошибку и останавливает программу — вынесите его в отдельный файл, иначе не проверите остальные. Фрагмент 6 не падает, и в этом его беда.
  • предсказания записаны до запуска;
  • найден фрагмент, который падает, записан текст ошибки;
  • для остальных названа причина: строковые ключи, finally перебивает return, брошенная строка без свойств, дырки в массиве, пустой catch;
  • фрагменты 2, 3, 4 и 6 переписаны правильно;
  • для фрагмента 6 объяснено, чем пустой catch опасен на практике.
