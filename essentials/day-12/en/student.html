Day 12. Functions

A summary of the lecture: declaration, parameters, return, scope, splitting a task.

The main points

A function is a piece of a program with a name. It solves three problems: not repeating yourself, giving an action a name, dividing a task into parts.
Declaring and calling are different things. The work begins with a call, when the name is followed by parentheses. Forgotten parentheses do not crash: you simply get the function itself instead of the result.

Declaration

function add(x, y) {   // x, y are PARAMETERS (in the declaration)
  return x + y;
}
add(2, 3);             // 2, 3 are ARGUMENTS (in the call)

The link goes by order, not by names. Matching names mean nothing.

How many arguments

add(2, 3);      // 5
add(2, 3, 4);   // 5   the extra ones are silently thrown away
add(2);         // NaN the missing one = undefined
add();          // NaN

add.length;     // 2   how many parameters are declared
add.name;       // "add"
A call with the wrong number of arguments is not an error. No warning, no message, only a strange result later. Important functions check their arguments themselves and throw a TypeError.
Up to three parameters — a list, beyond that — one object: createStudent({ name, age }).

return

function f() { }             // undefined
function f() { return; }     // undefined too
function f() { return       // A TRAP: a semicolon is inserted by itself
  42; }                      // returns undefined!

// return ends the function IMMEDIATELY — the code below is dead
// this is not an error: Firefox will warn, Chrome will say nothing

An early exit

function grade(s) {
  if (s >= 90) return "5";
  if (s >= 75) return "4";
  return "3";
}

else is not needed: if the first return worked, the second one is never reached. It reads like a list of rules.

Scope

function f() { const secret = 42; }
f();
console.log(secret);   // ReferenceError

const TAX = 0.05;
function withTax(p) { return p + p * TAX; }   // looking outside is allowed
You can see in from the inside, not out from the outside. Everything a function needs, it gets through its parameters, and does not take from outside variables. The exception is settings constants.

Hoisting

greet();  function greet() { }    // works — hoisted completely
hi();     const hi = function(){}; // ReferenceError

A function is a value

const sum = add;           // into a variable
const ops = [add];         // into an array
marks.map(double);         // as an argument — this is a CALLBACK
button.addEventListener("click", handleClick);    // we passed the function
button.addEventListener("click", handleClick());  // A MISTAKE: we called it right away

Names

What it doesHow to name it

“yes / no”isValidMark, hasErrors

One function — one job. Three signs that there are more jobs: the name has the word “and”; you cannot explain it in one sentence; it does not fit on the screen.

Recursion

function factorial(n) {
  if (n <= 1) return 1;        // an exit condition is REQUIRED
  return n * factorial(n - 1);
}
// without an exit: RangeError: Maximum call stack size exceeded
Seven errors of the day. TypeError: x is not a function is the most common one, and it has three causes: a typo, accessing something that does not exist, a name taken by something else. Look to the left of the parentheses.
Syntax errors (before running): a parameter that is not a name, parameters without a comma, a function without a name, no ) after the arguments. While running: not a function, too much recursion.
Code after return is not an error but a warning, and only in Firefox.

  2. Call maxOf(5) and maxOf(5, 3, 1). Write down what was returned and why there was no error.
  3. Rewrite with an early exit: a function with three nested if...else that gives a mark from points.
  4. Split into four functions a program that calculates the average from an array of marks and gives a verdict. Check each function separately.
