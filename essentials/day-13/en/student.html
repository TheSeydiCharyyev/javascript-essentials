Day 13. Ways to write a function

A summary of the lecture: declaration, function expression, arrow function.

The main points

The three forms do the same thing and are called the same way. The difference is in hoisting, in the name and in three small things that arrow functions lack.
The second and third forms are not a function declaration but an ordinary assignment. To the right of = stands a value. All their behavior follows from this.

Three forms

function add(a, b) { return a + b; }            // declaration
const sum = function (a, b) { return a + b; };  // expression
const plus = (a, b) => a + b;                   // arrow

Shortening an arrow function

n => n * 2;          // one simple parameter — the parentheses can go
(a, b) => a + b;     // several — parentheses are required
() => 42;            // zero parameters — parentheses are required
(n = 1) => n;        // a default value — parentheses are required
There is a { after the arrow — there must be a return. Curly braces switch off the implicit return.
(n) => n * 2 returns 10. (n) => { n * 2; } returns undefined.

Returning an object

() => { a: 1 }      // undefined — this is a BLOCK, a: is read as a label
() => ({ a: 1 })    // correct — parentheses

Hoisting

add(2, 3);  function add(a, b) { return a + b; }           // works

sum(2, 3);  const sum = (a, b) => a + b;
// ReferenceError: Cannot access 'sum' before initialization (in the console: sum is not defined)

plus(2, 3); var plus = function (a, b) { return a + b; };
// TypeError: plus is not a function ← the name exists, the value is undefined

Names

const myVar = function () { };   // myVar.name === "myVar"
const arrowFn = () => { };       // arrowFn.name === "arrowFn"
const outer = function inner(){}; // outer.name === "inner", no inner outside

The name is visible in the call stack. An anonymous function right in place shows up as a line without a name — it is harder to find.

What arrow functions lack

const o = { name: "Aman", say: () => this.name };   // will not work — no this
const f = () => arguments.length;   // ReferenceError: arguments is not defined
new (() => {})();                   // TypeError: not a constructor
Arrow functions are not made into object methods. A line break before => is a SyntaxError; after the arrow you can break the line.

IIFE

(function () { /* ... */ })();
(() => { /* ... */ })();

// hide data while leaving access:
const counter = (function () {
  let count = 0;
  return { inc: () => ++count, get: () => count };
})();
Choice. The course agreement: function for program functions, arrows for callbacks. The main thing is not to mix them in one file without a reason.
How to read: to the left of the arrow are the parameters; there is a { — look for return; where it is passed — that one will call it.
The passing trap: filter(isFive) — passed the function, filter(isFive()) — called it and passed the result.
  1. Write the function “double a number” in all three ways and call each one.
  2. Shorten to the limit: const f = function (n) { return n + 1; }; Write down all the intermediate forms.
  3. Write an arrow function that returns the object { name, age } with a short body. First without parentheses — write down the result, then with them.
  4. Take marks.filter(m => m >= 4).map(m => m * 10) and unfold it into nine lines with named functions. Check that the result is the same.
