Day 14. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-14.

Warm-up

1. Five arguments, one default
Easy6 min

see with your own eyes that a default reacts only to undefined.

Write the function and call it five times, writing down each result:

function makeGreeting(name, greeting = "Salam") {
  return greeting + ", " + name + "!";
}

makeGreeting("Aman");
makeGreeting("Aman", undefined);
makeGreeting("Aman", null);
makeGreeting("Aman", 0);
makeGreeting("Aman", "Hoş geldiň");
Two calls will give the same result — find which ones. The other three will show what was passed, with no substitution at all.
  • all five results are written down;
  • the two calls that gave the same thing are named, and it is explained why;
  • it is explained why null and 0 did not switch the default on;
  • the rule is stated in one sentence.
2. Predict first: used or not
Easy7 min

tell a default apart from the old trick with ||.

Predict the result of each call, then check.

function a(num = 10) { return num; }
function b(num) { num = num || 10; return num; }
function c(num) { num = num ?? 10; return num; }

console.log(a(), a(0), a(null));
console.log(b(), b(0), b(null));
console.log(c(), c(0), c(null));
Nine values. The differences will appear only in the columns 0 and null — the first column is the same for all three.
  • nine predictions are written down before checking;
  • it is found where b differs from a, and the cause is named;
  • it is found where c differs from a, and the cause is named;
  • it is written down which of the three functions you would write in your own code and why.
3. Add up anything
Easy7 min

write your first function with a rest parameter.

Write sumAll, which adds up any number of arguments. Check it on three, one and zero arguments. Then print the typeof of the rest parameter and Array.isArray of it.

Inside the function it is an ordinary array — go through it with for...of from day 11. The starting value of the sum is zero, so a call without arguments works too.
  • sumAll(5, 4, 5), sumAll(5) and sumAll() give 14, 5 and 0;
  • it is written down what typeof and Array.isArray showed;
  • it is explained why a call without arguments gives no error;
  • the same thing is written once more as an arrow function.

Main tasks

4. An inconvenient order
Medium12 min

understand from your own mistake why optional parameters are put last.

Type a function whose default comes first, and try to use it:

function report(greeting = "Salam", name) {
  return greeting + ", " + name;
}

report("Aman");   // wanted “Salam, Aman”

You got something else. Get the result you need without changing the declaration. Then rewrite the function correctly and show that it is more convenient.

Arguments are laid out by places, not by names: “Aman” went into the first place. To say “take your own for the first one”, there is exactly one value — it is from section 3 of the lecture.
  • it is written down what report("Aman") returned and why;
  • a call is found that gives “Salam, Aman” without editing the declaration;
  • the function is rewritten with the default at the end, two calls are shown;
  • it is explained in one sentence why the second version is better.
5. Rewrite old code
Medium12 min

replace arguments with a rest parameter.

Here is a function written before 2015. It joins all the arguments with a space:

function oldJoin() {
  const parts = Array.prototype.slice.call(arguments);   // course 2
  let out = "";
  for (const p of parts) {
    out += p + " ";
  }
  return out;
}

Rewrite it with a rest parameter so that the result matches to the character. Then answer the question: what changes if the function gets a first required parameter title?

The line with slice.call was needed only to turn arguments into an array — with a rest parameter it is not needed at all. For the second question compare arguments.length and the length of the rest parameter.
  • the new version is shorter and gives the same result on ("bir", "iki");
  • the results of both versions are compared, the match is checked;
  • it is explained why with the old version title would get into the output, and with the new one it would not;
  • it is written down why the old version cannot be repeated in an arrow function.
6. A default that works
Medium13 min

make sure that a default is code, not a value.

Three experiments in a row; for each one write down the output and an explanation.

  1. A call counter: 
    let calls = 0;
function next() { calls = calls + 1; return calls; }
function withCall(n = next()) { return n; }
    Call withCall() twice, then withCall(100). After each call print calls.
  2. A new array every time: function addMark(mark, marks = []) { marks.push(mark); return marks; }. Call it twice without the second argument, then twice with the same array.
  3. A required argument: write required(name), which throws a TypeError, and a function with the parameter name = required("name").
In the first experiment it is important to print calls after each call, otherwise you will not see the difference. In the third remember throw from day 11.
  • for experiment 1 the value of calls after each of the three calls is written down, and it is explained why the third one did not change it;
  • for experiment 2 it is shown that two calls in a row do not accumulate marks, while with a shared array they do;
  • for experiment 3 the function crashes without an argument and works with one;
  • it is checked that a call with undefined also causes the error, and it is explained why.
7. The “Report card”: loose marks
Medium13 min

move the course program to the new way of passing data.

Copy the folder day-13 into day-14 and rewrite it:

  • makeReport takes the marks with a rest parameter, and the name gets the default "unnamed";
  • verdict gets three optional thresholds: excellent = 4.5, good = 3.5, pass = 2.5;
  • the calls of makeReport are rewritten without square brackets.

Add a fifth call — makeReport() with no arguments at all.

The bodies of isValidMark, sum, average and makeReport do not need changing — only the parameter lists and the calls. If the first four reports changed, something went wrong.
  • the first four reports match yesterday’s — compared line by line;
  • the fifth call gives “unnamed: 0 of 0…” and does not crash;
  • it is shown that verdict(4.6) and verdict(4.6, 4.8) give different words;
  • it is explained why the call verdict(avg) inside makeReport did not have to change.

Starred tasks

8. Four errors and one exception
Hard10 min

get all four errors of the day with your own hands and find the one that behaves differently.

Each fragment goes into a separate file: these are SyntaxErrors, they break the whole file. Write down the exact text of each error from your console.

// 1
function add(x, x) { return x; }
console.log(add(1, 2));

// 2
function add(x, x = 1) { return x; }

// 3
function f(arg) { let arg = "foo"; }

// 4
function replacer(match, ...groups, offset) { }

// 5
function doSomething(...args = []) { }

There are five fragments but four errors. Figure out what happens with the first one.

The first fragment is the only one that depends on the mode. Try adding the line "use strict"; at the start of the file and run it again. Compare with fragment 2 and draw a conclusion.
  • the exact text of the four errors from your console is written down;
  • for fragment 1 it is written down what it printed without strict mode and what with it;
  • it is explained how fragment 2 differs from fragment 1, which makes the error appear;
  • the texts are compared with the titles of the MDN pages from the reference of the day, and it is noted that they do not match;
  • all five fragments are rewritten correctly.
9. A universal list
Hard10 min

build a function where both of today’s topics work at once.

Write makeList, which prints a numbered list:

makeList("Marks", 5, 4, 5);    // "Marks: 1) 5 2) 4 3) 5"
makeList("Marks");             // "Marks: empty"
makeList();                    // "List: empty"
makeList(undefined, "bir");    // "List: 1) bir"

The title is optional and equals "List" by default; there can be any number of items.

The order of the parameters is given by the examples: first the title with a default, then the rest parameter. Keep the number in a separate variable — it grows at every step of for...of. Check the “no items” case before the loop.
  • all four calls from the example give exactly what is written;
  • with zero items the loop does not run even once;
  • it is explained why makeList(undefined, "bir") prints “List” and not “undefined”;
  • it is checked that makeList("Marks", [5, 4]) gives one item, and it is explained why;
  • an optional separator parameter is added between the title and the rest parameter — and it is shown how to skip it.
