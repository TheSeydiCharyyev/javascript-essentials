Day 15. Tasks

A mixed day: three blocks of 25 minutes, each one right after its part of the theory. Everything is done in the folder day-15.

Block 1 — after part 1 (25 minutes)

1. Cut the pile yourself
Easy8 min

apply the four signs to a real program.

Type the program from section 1 of the lecture and cut it into functions — without peeking at section 3. Run it and make sure the output has not changed.

Start not with code but with a list of names on paper: write down what actions the program performs, one verb per line. As many lines as you get — that many functions.
  • the output matches the old one — compared line by line;
  • every function has a name made of a verb, not a single f or doIt;
  • there is one function that builds the result from the others;
  • it is written down by which sign each piece was cut out;
  • after comparing with section 3 it is written down where your boundaries differed from the lecture’s analysis.
2. Rename
Easy8 min

learn to see that a name lies.

For each function invent the right name and explain what was wrong with the old one. The bodies do not need changing.

function data(marks) {
  return marks.length;
}

function check(mark) {
  return mark >= 2 && mark <= 5;
}

function average(marks) {
  console.log(sum(marks) / marks.length);
}

function doIt(names, marks) {
  return names.length === marks.length;
}
Two of the four return true or false — the names of such functions start with is or has. One returns nothing, and its name promises too much.
  • a new name and a reason are written down for all four;
  • the two checks are named with is or has;
  • for the third one it is explained why the name average deceives;
  • it is written down what must change in the third one for the name getAverage to become honest.
3. Split the “and”
Medium9 min

separate calculating and showing into different functions.

function countAndPrint(present) {
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  console.log("Present: " + came);
  return came;
}

Split it in two. Then show with calls what could not be done with the old version and can be done with the new one.

Invent a task where you need to count but must not print — for example, count those present in three groups and print only the total.
  • two functions, each with one job;
  • the old output is reproduced with two lines;
  • a call is shown that would have cluttered the console with the old version;
  • it is explained in one sentence why calculating is separated from showing.

Block 2 — after part 2 (25 minutes)

4. The program lies, it does not crash
Medium8 min

find an error that nobody reports.

This program prints Good marks: 133%. There is no error in the console.

function countHigh(marks, limit) {
  let count = 0;
  for (const m of marks) {
    if (m > limit) {
      count += 1;
    }
  }
  return count;
}

function percentOf(part, total) {
  if (total === 0) {
    return 0;
  }
  return part / total * 100;
}

function report(marks, limit) {
  const high = countHigh(marks, limit);
  return "Good marks: " + percentOf(marks.length, high).toFixed(0) + "%";
}

console.log(report([5, 4, 3, 5], 3));
First calculate the right answer in your head: how many marks are greater than three, out of how many. Then add printing at the boundaries to both functions and look at what leaves one and arrives in the other.
  • the right answer is calculated by hand before running;
  • the line with the error is found, the cause is named;
  • the printing at the boundaries that shows it is presented;
  • after the fix 75% is printed;
  • it is explained why a percent over a hundred is a good reason to be alarmed.
5. Read the call stack
Medium8 min

find the real cause by the chain of calls.

Type it into a file exactly like this, with the empty lines — you will need the line numbers:

function sumOf(numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

function averageOf(numbers) {
  return sumOf(numbers) / numbers.length;
}

function makeLine(name, numbers) {
  return name + ": " + averageOf(numbers).toFixed(1);
}

console.log(makeLine("Aman", [5, 4]));
console.log(makeLine("Meret"));
The first line of output will be correct, the second will crash. The stack is read from the bottom up: the bottom line is your file, start from it.
  • the text of the error and the whole call stack from your console are written down;
  • the line that must be fixed is named, and its number is written down;
  • it is explained why sumOf does not need fixing, although it crashed exactly in it;
  • the error is fixed, both lines are printed;
  • it is written down what the stack will show if you write makeLine("Meret", []) instead of makeLine("Meret") — and why there is no error there anymore.
6. Shrink the input
Hard9 min

bring an error down to the smallest call on which it is visible.

The function must name the best student. On three students it answers Aman (5), although the five is Meret’s.

function best(names, marks) {
  let bestName = names[0];
  let bestMark = marks[0];
  let i = 1;
  for (const name of names) {
    if (marks[i] > bestMark) {
      bestMark = marks[i];
      bestName = name;
    }
    i += 1;
  }
  return bestName + " (" + bestMark + ")";
}

console.log(best(["Aman", "Meret", "Gülnar"], [4, 5, 3]));

Shrink the input until the error becomes obvious, then fix it.

Try two students, then one, then empty lists. At some step the answer will suddenly become right — and that is the most interesting place. Look at which element of the list marks[i] is compared with on the first turn of the loop.
  • all the trial calls and their answers are written down;
  • the smallest call on which the answer is still wrong is named;
  • a call on which the answer is right is named, and it is explained why there is no error there;
  • the error is fixed and checked on three, two and one student;
  • it is written down what the fixed function does on empty lists, and it is decided whether that is good or not.

Block 3 — after part 3 (25 minutes)

7. Read without running
Medium8 min

take an unfamiliar function apart layer by layer and check the guess.

function g(a, b) {
  let c = 0;
  for (const x of a) {
    if (x >= b) {
      c += 1;
    }
  }
  return c / a.length * 100;
}

First write down: what the function returns, what types the parameters are, what the branch does, what you would call it. Predict three calls — and only then run them.

g([5, 4, 3, 5, 2], 4);
g([5, 4, 3, 5, 2], 6);
g([], 4);
Look at return first: there is division by the length and multiplication by a hundred — this tells you right away what the answer is measured in. The third call is exactly the edge case for which they are checked.
  • the analysis by four layers is written down before running;
  • three predictions are written down before running;
  • for the third call it is explained where its result comes from;
  • meaningful names are invented for the function and both parameters.
8. Rewrite in small steps
Hard9 min

put someone else’s function in order without breaking anything on the way.

Take g from task 7 and rewrite it one step at a time, running the three calls from task 7 after each step and comparing the answers.

  1. only the names: of the function and both parameters;
  2. the edge case from the third call — return 0 instead of NaN;
  3. a default value for the threshold, so that a call with one argument works;
  4. checking the edges once more: an empty list, a threshold above all marks, a threshold below all of them.
After step 2 the first two answers must stay the same — if they changed, the emptiness check was put in the wrong place. Its place is before all the calculations.
  • after each step the answers of the three calls are written down;
  • the answers of the first two calls did not change at any step;
  • the third call gives 0 after step 2;
  • a call with one argument works and gives an answer that can be explained;
  • it is written down why rewriting everything at once is worse than in steps.
9. The “Report card”: an early branch
Medium8 min

close yesterday’s debt of the course program.

Copy the folder day-14 into day-15. Yesterday “Gülnar” did not have a single valid mark, and the verdict was “needs work” — that is not true. Add an early branch and make sure the other reports did not suffer.

makeReport("Gülnar", 9, 0, "five");   // "Gülnar: no valid marks"
makeReport("Oguljan");                // "Oguljan: no valid marks"
makeReport("Sapar", 5, 5, 4, 5);      // as yesterday, unchanged
The branch is put after the selection marks.filter(isValidMark) and before all the calculations — otherwise average will manage to divide by zero before you stop it.
  • the reports “Aman”, “Meret” and “Sapar” match yesterday’s — compared line by line;
  • “Gülnar” and the call without marks give the new text;
  • the branch stands before the calculations, not after — it is explained why;
  • it is checked that makeReport() with no arguments at all does not crash;
  • it is written down which other functions of the “Report card” would be worth protecting from empty input.
