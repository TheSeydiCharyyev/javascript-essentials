День 15. Задания

Смешанный день: три блока по 25 минут, каждый — сразу после своей части теории. Всё делаем в папке day-15.

Блок 1 — после части 1 (25 минут)

1. Разрежьте кучу сами
Легко8 мин

применить четыре признака к настоящей программе.

Наберите программу из раздела 1 лекции и разрежьте её на функции — не подглядывая в раздел 3. Запустите и убедитесь, что вывод не изменился.

Начните не с кода, а со списка имён на бумаге: выпишите, какие действия программа делает, по одному глаголу на строку. Сколько строк получилось — столько и функций.
  • вывод совпал со старым — сверено построчно;
  • у каждой функции имя из глагола, ни одного f или doIt;
  • есть одна функция, которая собирает результат из остальных;
  • записано, по какому признаку выделен каждый кусок;
  • после сравнения с разделом 3 записано, где ваши границы разошлись с разбором лекции.
2. Переименовать
Легко8 мин

научиться видеть, что имя врёт.

Для каждой функции придумайте правильное имя и объясните, что было не так со старым. Тела менять не нужно.

function data(marks) {
  return marks.length;
}

function check(mark) {
  return mark >= 2 && mark <= 5;
}

function average(marks) {
  console.log(sum(marks) / marks.length);
}

function doIt(names, marks) {
  return names.length === marks.length;
}
Две из четырёх возвращают true или false — у таких имя начинают с is или has. Одна не возвращает ничего, и её имя обещает лишнего.
  • для всех четырёх записано новое имя и причина;
  • две проверки названы через is или has;
  • для третьей объяснено, почему имя average обманывает;
  • записано, что нужно изменить в третьей, чтобы имя getAverage стало честным.
3. Разделить «и»
Средне9 мин

развести по разным функциям расчёт и показ.

function countAndPrint(present) {
  let came = 0;
  for (const p of present) {
    if (p === 1) {
      came += 1;
    }
  }
  console.log("Пришло: " + came);
  return came;
}

Разделите её на две. Потом покажите на вызовах, что со старой версией нельзя было сделать, а с новой можно.

Придумайте задачу, в которой считать надо, а печатать нельзя, — например, посчитать пришедших в трёх группах и вывести только общее число.
  • две функции, у каждой одно дело;
  • старый вывод воспроизводится двумя строками;
  • показан вызов, который со старой версией засорял бы консоль;
  • объяснено в одном предложении, зачем расчёт отделяют от показа.

Блок 2 — после части 2 (25 минут)

4. Программа врёт, а не падает
Средне8 мин

найти ошибку, о которой не сообщает никто.

Эта программа выводит Хороших: 133%. Ошибки в консоли нет.

function countHigh(marks, limit) {
  let count = 0;
  for (const m of marks) {
    if (m > limit) {
      count += 1;
    }
  }
  return count;
}

function percentOf(part, total) {
  if (total === 0) {
    return 0;
  }
  return part / total * 100;
}

function report(marks, limit) {
  const high = countHigh(marks, limit);
  return "Хороших: " + percentOf(marks.length, high).toFixed(0) + "%";
}

console.log(report([5, 4, 3, 5], 3));
Сначала посчитайте правильный ответ в уме: сколько оценок больше трёх из скольких. Потом добавьте печать на границах в обе функции и посмотрите, что уходит из одной и приходит в другую.
  • правильный ответ посчитан руками до запуска;
  • найдена строка с ошибкой, названа причина;
  • показана печать на границах, по которой это видно;
  • после починки выводится 75%;
  • объяснено, почему проценты больше ста — хороший повод насторожиться.
5. Прочитать стек вызовов
Средне8 мин

по цепочке вызовов найти настоящую причину.

Наберите в файл ровно так, вместе с пустыми строками — номера строк понадобятся:

function sumOf(numbers) {
  let total = 0;
  for (const n of numbers) {
    total += n;
  }
  return total;
}

function averageOf(numbers) {
  return sumOf(numbers) / numbers.length;
}

function makeLine(name, numbers) {
  return name + ": " + averageOf(numbers).toFixed(1);
}

console.log(makeLine("Аман", [5, 4]));
console.log(makeLine("Мерет"));
Первая строка вывода будет правильной, упадёт вторая. Стек читается снизу вверх: нижняя строка — ваш файл, с неё и начинайте.
  • записан текст ошибки и весь стек вызовов из своей консоли;
  • названа строка, которую надо чинить, и номер записан;
  • объяснено, почему чинить sumOf не нужно, хотя упало именно в ней;
  • ошибка исправлена, обе строки выводятся;
  • записано, что покажет стек, если вместо makeLine("Мерет") написать makeLine("Мерет", []) — и почему там ошибки уже нет.
6. Уменьшить вход
Сложно9 мин

свести ошибку к самому маленькому вызову, на котором она видна.

Функция должна называть лучшего студента. На трёх студентах она отвечает Аман (5), хотя пятёрка у Мерета.

function best(names, marks) {
  let bestName = names[0];
  let bestMark = marks[0];
  let i = 1;
  for (const name of names) {
    if (marks[i] > bestMark) {
      bestMark = marks[i];
      bestName = name;
    }
    i += 1;
  }
  return bestName + " (" + bestMark + ")";
}

console.log(best(["Аман", "Мерет", "Гүлнар"], [4, 5, 3]));

Уменьшайте вход, пока ошибка не станет очевидной, потом почините.

Попробуйте двух студентов, потом одного, потом пустые списки. На каком-то шаге ответ вдруг станет правильным — и вот это самое интересное место. Смотрите, с каким элементом списка сравнивается marks[i] на первом обороте цикла.
  • записаны все пробные вызовы и их ответы;
  • назван самый маленький вызов, на котором ответ ещё неверный;
  • назван вызов, на котором ответ верный, и объяснено, почему там ошибки нет;
  • ошибка исправлена, проверено на трёх, двух и одном студенте;
  • записано, что делает исправленная функция на пустых списках, и решено, хорошо это или нет.

Блок 3 — после части 3 (25 минут)

7. Прочитать, не запуская
Средне8 мин

разобрать незнакомую функцию по слоям и проверить догадку.

function g(a, b) {
  let c = 0;
  for (const x of a) {
    if (x >= b) {
      c += 1;
    }
  }
  return c / a.length * 100;
}

Сначала запишите: что функция возвращает, какого типа параметры, что делает ветка, как бы вы её назвали. Предскажите три вызова — и только потом запускайте.

g([5, 4, 3, 5, 2], 4);
g([5, 4, 3, 5, 2], 6);
g([], 4);
Смотрите на return первым: там деление на длину и умножение на сто — это сразу говорит, в чём измеряется ответ. Третий вызов — тот самый крайний случай, ради которого их и проверяют.
  • разбор по четырём слоям записан до запуска;
  • три предсказания записаны до запуска;
  • для третьего вызова объяснено, откуда берётся его результат;
  • придуманы осмысленные имена функции и обоих параметров.
8. Переписать маленькими шагами
Сложно9 мин

привести чужую функцию в порядок, ничего не сломав по дороге.

Возьмите g из задания 7 и переписывайте по одному шагу, после каждого запуская три вызова из задания 7 и сверяя ответы.

  1. только имена: функции и обоих параметров;
  2. крайний случай из третьего вызова — вернуть 0 вместо NaN;
  3. значение по умолчанию для порога, чтобы вызов с одним аргументом работал;
  4. проверка на краях ещё раз: пустой список, порог выше всех оценок, порог ниже всех.
После шага 2 первые два ответа обязаны остаться прежними — если они изменились, проверка на пустоту встала не туда. Её место — до всех расчётов.
  • после каждого шага записаны ответы трёх вызовов;
  • ответы первых двух вызовов не менялись ни на одном шаге;
  • третий вызов после шага 2 даёт 0;
  • вызов с одним аргументом работает и даёт объяснимый ответ;
  • записано, почему переписывать всё разом хуже, чем по шагам.
9. «Табель»: ранняя ветка
Средне8 мин

закрыть вчерашний долг программы курса.

Скопируйте папку day-14 в day-15. Вчера у «Гүлнар» не было ни одной годной оценки, а вердикт был «надо подтянуть» — это неправда. Добавьте раннюю ветку и убедитесь, что остальные отчёты не пострадали.

makeReport("Гүлнар", 9, 0, "пять");   // "Гүлнар: годных оценок нет"
makeReport("Огулджан");               // "Огулджан: годных оценок нет"
makeReport("Сапар", 5, 5, 4, 5);      // как вчера, без изменений
Ветка ставится после отбора marks.filter(isValidMark) и до всех расчётов — иначе average успеет поделить на ноль раньше, чем вы её остановите.
  • отчёты «Аман», «Мерет» и «Сапар» совпали со вчерашними — сверено построчно;
  • «Гүлнар» и вызов без оценок дают новый текст;
  • ветка стоит до расчётов, а не после — объяснено почему;
  • проверено, что makeReport() вообще без аргументов не падает;
  • записано, какие ещё функции «Табеля» стоило бы защитить от пустого входа.
