Day 17. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-17.

Warm-up

1. Fifteen cells
Easy6 min

see the three ways of conversion side by side.

Fill in the table: five strings through three functions. Predict first, then check.

const values = ["42", "4.5", "42px", "px42", ""];

// for each one: Number(v), parseInt(v), parseFloat(v)
Zero and NaN look different in the console, but in a table they are easy to mix up. If in doubt, check with Number.isNaN. typeof will not help here: the type of NaN is "number" too.
  • all fifteen cells are filled in;
  • the string where parseInt differed from the other two is found;
  • the string where Number gives 0 and the others NaN is found;
  • it is written down which function you will take for data from a form and why.
2. Predict first: which check
Easy7 min

tell the old and the new checks apart.

isNaN("abc");            isNaN("42");            isNaN(NaN);
Number.isNaN("abc");     Number.isNaN("42");     Number.isNaN(NaN);
isFinite("42");          Number.isFinite("42");  Number.isFinite(1 / 0);
All the differences come down to one thing: the functions without the Number. prefix first turn the argument into a number, and the ones with the prefix do not.
  • nine predictions are written down before checking;
  • all the pairs where the answers differed are found;
  • the difference between the two families is stated in one sentence;
  • it is explained why Number.isFinite(1 / 0) gives false.
3. What toFixed returns
Easy7 min

catch two traps of rounding.

(4.333).toFixed(2);
(7).toFixed(2);
(2.5).toFixed(0);
(1.005).toFixed(2);
typeof (4.333).toFixed(2);
(4.333).toFixed(2) + 1;
One line will give something other than school arithmetic suggests, and the last one something other than common sense suggests. The two causes are different.
  • six predictions are written down before checking;
  • it is explained why (1.005).toFixed(2) gives "1.00";
  • it is explained what happened in the last line;
  • it is written down how to add two rounded values correctly.

Main tasks

4. Marks from a form
Medium12 min

accept data in the form in which it comes from a person.

Write two functions and check them on the list below.

// toMark(raw)      — turns anything into a number
// isValidMark(m)   — an integer from 2 to 5

const raw = [5, "4", " 3 ", "4.5", "five", "", null, 9, 0];
Number(String(raw).trim()) covers both numbers and strings with spaces. For the check one Number.isInteger and two comparisons are enough — typeof and a separate NaN check are no longer needed.
  • for all nine values it is written down what toMark returned;
  • exactly 5, "4" and " 3 " are recognized as valid;
  • it is explained why "4.5" and "" did not pass, and their causes are different;
  • it is explained why Number.isInteger cuts off NaN by itself;
  • it is written down what toMark(null) returns and what plain Number(null) returns, and why the second is more dangerous.
5. Money in fractions
Medium13 min

see the error with your own eyes and get around it.

const prices = [10.10, 20.20, 30.30];

let sum = 0;
for (const p of prices) {
  sum += p;
}

console.log(sum);
console.log(sum === 60.6);

It did not come out right. Rewrite the counting so that the comparison with 60.6 gives true — counting in kopecks. Then compare three ways: in fractions, with toFixed and in kopecks.

In kopecks means multiplying each price by 100, rounding to an integer, adding, and dividing back only when printing. Rounding to an integer is Math.round from day 6.
  • the exact value printed by the first version is written down;
  • the version in kopecks gives true in the comparison;
  • it is shown that toFixed(2) shows the value correctly but does not help with comparing — it is explained why;
  • the rule is written down in one line: where to store, where to round;
  • it is checked on three more prices with kopecks.
6. Building a date
Medium12 min

do not get caught on the numbering of months.

Build three dates and print each one with toLocaleDateString("en-GB"), and next to it the results of getMonth() and getDate():

  • 1 January 2026;
  • 22 September 2026, 14:05;
  • 31 December 2026.

Then print new Date(2026, 12, 1) and explain the result.

If the first date showed February, you got caught exactly where everyone gets caught. Check yourself by the output: toLocaleDateString shows the month the way people understand it.
  • all three dates are printed correctly, the month numbers are written down;
  • it is explained why September is 8 in new Date;
  • for new Date(2026, 12, 1) the year and the month are written down with an explanation;
  • a function is written that takes a human month number (1–12);
  • it is checked that it gives the same three dates.

Starred tasks

8. How many days are left
Hard10 min

calculate a difference of dates and run into time.

Write daysBetween(from, to) and check it on four pairs.

daysBetween(new Date(2026, 8, 22), new Date(2026, 11, 25));   // 94
daysBetween(new Date(2026, 11, 25), new Date(2026, 8, 22));   // -94
daysBetween(new Date(2026, 8, 22), new Date(2026, 8, 22));    // 0
daysBetween(new Date(2026, 8, 22, 14, 5), new Date(2026, 11, 25));   // ?
The last pair will give a non-integer number, and that is correct: the first date has a time, and the second one has midnight. Think about what is needed here — rounding or resetting the time, and why the answer depends on the task.
  • the first three pairs give exactly what is written;
  • for the fourth the exact number is written down and it is explained where the fraction comes from;
  • a solution for the fractional case is proposed, the choice is explained;
  • a check for an invalid date is added — the function must not return NaN silently;
  • it is written down what the function returns if the order of the arguments is mixed up.
9. Three errors and one quiet one
Hard10 min

get the errors of the day and tell them apart from trouble without a message.

// 1
console.log((255).toString(1));

// 2
console.log((4.5).toFixed(101));

// 3
console.log(new Date("not a date").toISOString());

// 4
const d = new Date("not a date");
if (d) {
  console.log("there is a date:", d.getFullYear());
}
The first three crash, the fourth does not, and it is exactly the most harmful one: the check if (d) passes, because an invalid date is an object too.
  • the predictions are written down before running;
  • for the three that crash the exact text of the error from your console is written down;
  • the texts are compared with the titles of the MDN pages — it is noted that they do not match;
  • it is explained what fragment 4 printed and why the check did not work;
  • fragment 4 is rewritten with a correct date check.
