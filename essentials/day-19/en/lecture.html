1. What an array is

An array is a list of values that have an order. One name — many values. Instead of five variables student1, student2, student3 you keep one array students and refer to the elements by number.

The number is called an index and starts from zero. This is not a whim of the language: almost all programming languages count this way, because the index means “how many steps from the start”.

Why this is needed is visible on a simple example. Imagine that a class has 30 students and you need to store their marks. Without an array you would have to create thirty variables:

const mark1 = 5;
const mark2 = 4;
const mark3 = 5;
// ... and so on thirty times

And then helplessness begins: how do you calculate the average? How do you find the best mark? How do you add the thirty-first student? Each time you would have to edit the code by hand. With an array all this is done in a few lines, and the number of students stops mattering at all:

const marks = [5, 4, 5, 3, 4, 5];
console.log(marks.length);   // how many in all — 6

Arrays are the most common data structure in work. Here is what they hold every day:

  • the goods in an online shop’s cart;
  • the messages in a chat, in the order they arrived;
  • the items in a to-do list;
  • marks, prices, temperatures — any series of numbers;
  • elements found on the page: all buttons, all pictures (day 24).
const fruits = ["alma", "armyt", "üzüm", "erik", "hurma"];

console.log(fruits[0]);        // "alma"    — the first
console.log(fruits[4]);        // "hurma"   — the fifth
console.log(fruits.length);    // 5         — how many in all
console.log(fruits[5]);        // undefined — there is no such one
An array is a shelf with numbered cells. You name the cell number yourself: “give me what lies in cell 2”. If there is no such cell, nobody shouts an error at you — they simply answer “nothing” (undefined).

2. Four ways to create an array

// 1. A literal — this is how it is written in 95% of cases
const marks = [5, 4, 5, 3];

// 2. An empty array that we will fill later
const basket = [];

// 3. Array.of — from the listed values
const one = Array.of(7);        // [7]

// 4. Array.from — from something that looks like a list
const letters = Array.from("Mary");   // ["M", "a", "r", "y"]
new Array(7) creates not an array with the number 7 but an empty array of length 7. So Array.of(7) and new Array(7) give different things: 
Array.of(7);      // [7]        — one element
new Array(7);     // [empty × 7] — seven empty slots
new Array(2.5);   // RangeError: Invalid array length
The conclusion: write the literal [7] or Array.of(7), and do not use new Array.

Array.from comes in handy not only with a string. It is given any “list-like” object: a list of elements found on the page, a set of letters, the result of a Set. We will meet this on day 24 and in course 2.

3. Access to elements and length

const days = ["duşenbe", "şenbe", "ýekşenbe"];

days[1] = "sişenbe";     // replaced an element
console.log(days);       // ["duşenbe", "sişenbe", "ýekşenbe"]

console.log(days.at(-1));           // "ýekşenbe" — the last
console.log(days[days.length - 1]); // the same, but longer

days.length = 2;         // the length can be changed — the array gets cut
console.log(days);       // ["duşenbe", "sişenbe"]

The at method is handy exactly with negative numbers: at(-1) is the last, at(-2) the one before last. With positive ones it works like ordinary brackets.

Assigning to an index that does not exist is not an error: arr[10] = 1 will stretch the array to 11 elements and fill the empty places with “holes”. Holes behave strangely in some methods, so it is better not to do this — add with push.

Holes in an array

MDN calls them empty slots. A hole is not undefined but the absence of an element altogether. It appears in three ways:

const a = [1, 2, , , 5];   // two commas in a row — two holes
const b = [1, 2];
b[4] = 5;                  // wrote past the end: holes at places 2 and 3
const c = [1, 2];
c.length = 5;              // lengthened through length: three holes at the end
b.length;                  // 5

When reading, a hole cannot be told from undefined. But search methods see it differently — as with NaN in section 6:

const arr = [1, , 3];
arr[1];                    // undefined
arr.includes(undefined);   // true — includes treats a hole as undefined
arr.indexOf(undefined);    // -1 — indexOf skips holes

The conclusion is the same: do not create holes. Add with push, and fill an array of identical values with the fill method from section 8.

Going through an array by indices

Since every element has a number, you can go through the array with an ordinary loop from day 10. The counter starts from zero and goes while it is less than the length:

const marks = [5, 4, 3];

for (let i = 0; i < marks.length; i++) {
  console.log(i + ": " + marks[i]);
}
// 0: 5
// 1: 4
// 2: 3

The condition is i < marks.length, not i <= marks.length — because the last index is one less than the length. A mistake by one here is so common that it has a name: an “off-by-one error”. Its sign is that the last element is undefined:

for (let i = 0; i <= marks.length; i++) {   // a mistake: <= instead of <
  console.log(i + ": " + marks[i]);
}
// 0: 5
// 1: 4
// 2: 3
// 3: undefined — an extra step: there is no index 3 in the array

If you do not need the numbers, for...of is shorter:

for (const mark of marks) {
  console.log(mark);
}

And on day 20 the methods forEach and map will appear, after which ordinary loops for arrays are almost no longer needed.

4. Add and remove: push, pop, shift, unshift

Four methods work with the ends of an array. They are easy to remember in pairs: two work with the tail, two with the head.

const queue = ["Aman", "Meret"];

queue.push("Gülnar");      // to the end
console.log(queue);        // ["Aman", "Meret", "Gülnar"]

const last = queue.pop();  // from the end, returns what was removed
console.log(last);         // "Gülnar"

queue.unshift("Sapar");    // to the start
console.log(queue);        // ["Sapar", "Aman", "Meret"]

const first = queue.shift(); // from the start
console.log(first);        // "Sapar"
MethodWhere it worksWhat it returns
push(x)the endthe new length
pop()the endthe removed element
unshift(x)the startthe new length
shift()the startthe removed element
Why remember what a method returns? Because it decides how the method is written. const x = arr.pop() makes sense: we took an element. But const x = arr.push(1) is almost always a mistake: x will hold the length of the array, while the person expected the array itself.

Stack and queue

These four methods make up two schemes that have names in programming. A stack is “last in, first out”: you put and take from one end, like plates in a pile. This is how the “Undo” button in an editor works:

const history = [];
history.push("wrote a heading");
history.push("added a picture");
history.push("changed the color");

history.pop();   // "changed the color" — the last action is undone
history;         // ["wrote a heading", "added a picture"]

A queue is “first in, first out”: you add at the end and take from the start, like a line at a checkout:

const line = ["Aman", "Meret"];
line.push("Gülnar");   // got in line at the end
line.shift();          // "Aman" — the first one was served
line;                  // ["Meret", "Gülnar"]

When a task says “undo the last one”, it is a stack, push and pop. “Process in the order of arrival” is a queue, push and shift.

5. Pieces: slice and splice

Two methods with similar names and different fates. slice cuts out a copy and leaves the original alone. splice operates on the array itself: it removes, inserts, replaces.

const letters = ["a", "b", "c", "d"];

const part = letters.slice(1, 3);   // from 1 to 3, not including 3
console.log(part);                  // ["b", "c"]
console.log(letters);               // ["a", "b", "c", "d"] — intact

const copy = letters.slice();       // a copy of the whole array
const tail = letters.slice(-2);     // ["c", "d"] — two from the end

letters.splice(1, 2, "X");          // from index 1 remove 2, insert "X"
console.log(letters);               // ["a", "X", "d"] — changed
Remember the difference through the word: slice — “cut a piece for yourself”, the original stayed. splice — “cut out of the original”, the original changed. If you mix them up, the error will appear not where you wrote it but later — when someone else takes the spoiled array.

splice can do everything at once: remove, insert and replace.

const list = ["çaý", "suw"];

list.splice(1, 0, "süýt");   // remove nothing, insert at place 1
console.log(list);           // ["çaý", "süýt", "suw"]

list.splice(0, 1);           // remove one element from the start
console.log(list);           // ["süýt", "suw"]

The three arguments of splice read like this: from which place, how many to remove, what to insert. The third argument is optional, and you can insert several values at once:

const week = ["Mon", "Fri"];
week.splice(1, 0, "Tue", "Wed", "Thu");
console.log(week);   // ["Mon", "Tue", "Wed", "Thu", "Fri"]

The most common task is removing an element by value, not by number. There is no direct method for this, so it is done in two steps: find the index, then cut it out.

const names = ["Aman", "Meret", "Gülnar"];

const i = names.indexOf("Meret");
if (i !== -1) {
  names.splice(i, 1);
}
console.log(names);   // ["Aman", "Gülnar"]

The check i !== -1 is required. Without it, if the name is not in the list, indexOf will return -1, and splice(-1, 1) will remove the last element — not the one you wanted.

Both methods understand negative indices: counting goes from the end.

const a = ["a", "b", "c", "d"];

a.slice(-2);      // ["c", "d"] — the last two
a.slice(1, -1);   // ["b", "c"] — without the first and the last
a.slice();        // a copy of the whole array
Remember slice(-3) — “the last three”. This is the most common technique in real tasks: show the three latest messages, the five latest purchases, the ten latest records.

6. Search: indexOf, lastIndexOf, includes

const marks = [5, 4, 5, 3];

console.log(marks.indexOf(5));      // 0  — the first match
console.log(marks.lastIndexOf(5));  // 2  — the last match
console.log(marks.indexOf(2));      // -1 — not found
console.log(marks.includes(3));     // true
console.log(marks.includes(2));     // false
A common mistake is checking what was found like this: if (marks.indexOf(5)). If the element stands first, indexOf will return 0, and for a condition 0 means “no”. Check explicitly: if (marks.indexOf(5) !== -1), or simply use includes.

Both methods have a second, optional argument — where to search from. It helps when you need to find all matches one by one:

const letters = ["a", "b", "a", "c", "a"];

console.log(letters.indexOf("a"));      // 0
console.log(letters.indexOf("a", 1));   // 2 — searching starting from index 1
console.log(letters.indexOf("a", 3));   // 4

And one difference that not everyone remembers: includes can find NaN, while indexOf cannot. The reason is that NaN is not equal even to itself, and indexOf compares exactly for equality.

const nums = [1, NaN, 3];

console.log(nums.includes(NaN));   // true
console.log(nums.indexOf(NaN));    // -1 — “not found”

Searching for objects in an array with these methods will not work either: two objects that look the same are different values. There is find for such searches, and it will be on day 20.

7. Join and combine: concat, join

const a = [1, 2];
const b = [3, 4];

const all = a.concat(b);      // [1, 2, 3, 4] — a new array
console.log(a);               // [1, 2] — did not change

const names = ["Aman", "Meret", "Gülnar"];
console.log(names.join(", "));  // "Aman, Meret, Gülnar" — we got a string
console.log(names.join(""));    // "AmanMeretGülnar"

join turns an array into a string — this is needed every time a list has to be shown to a person. The reverse action, turning a string into an array, is done by the split method: we will take it apart in course 2 together with regular expressions.

A few details about join that save time:

const a = ["bread", "tea", "butter"];

a.join();            // "bread,tea,butter"   — without an argument, with commas
a.join(", ");        // "bread, tea, butter" — this is how it is shown to a person
a.join(" → ");       // "bread → tea → butter"
a.join("");          // "breadteabutter"     — join without a separator
[].join(", ");       // ""                   — an empty array gives an empty string

There is an automatic conversion too: if an array gets where a string is expected, toString is called, and it works like join() without an argument.

console.log("List: " + [1, 2, 3]);     // "List: 1,2,3"
console.log([1, 2, 3].toString());     // "1,2,3"

concat accepts not only arrays but also separate values, and it can join several at once:

const a = [1, 2];

a.concat(3);            // [1, 2, 3]
a.concat([3], [4, 5]);  // [1, 2, 3, 4, 5]
console.log(a);         // [1, 2] — the original did not change
On day 22 a shorter form of the same will appear: [...a, ...b]. It reads more easily, so in modern code concat is met less often. But you need to know it: in other people’s code it turns up all the time.

8. Changing and copying methods

This is the main idea of the whole day. Some methods change the array they were applied to. Others leave it alone and return a new value. Confusion between them is the source of the nastiest errors in real projects.

Change the source array

push, pop, shift, unshift, splice, reverse, fill, copyWithin

const a = [3, 1, 2];
a.reverse();
console.log(a); // [2, 1, 3]
Return something new, the original is intact

slice, concat, join, at, includes, indexOf, with, toReversed, toSpliced

const a = [3, 1, 2];
const b = a.toReversed();
console.log(a); // [3, 1, 2]
console.log(b); // [2, 1, 3]

The new methods toReversed, toSpliced and with appeared in the language recently: they are the “polite” versions of the old ones. with(0, "X") returns a copy where "X" stands at place 0, and does not touch the original.

const marks = [5, 4, 3];
marks.with(1, 5);        // [5, 5, 3] — a copy where 5 stands at place 1
marks.toSpliced(1, 1);   // [5, 3] — a copy without the element at index 1
marks;                   // [5, 4, 3] — the original is intact

Two more methods from the left column. fill fills a piece of an array with one value, copyWithin copies a piece of an array to another place inside the same array. Both change the array itself:

const seats = ["free", "free", "free", "free"];
seats.fill("taken", 1, 3);           // ["free", "taken", "taken", "free"]
[1, 2, 3, 4, 5].copyWithin(0, 3);    // [4, 5, 3, 4, 5] — the elements from 3 are copied to the start

The second and third arguments of fill are the same “from which place” and “up to which, not including it” as in slice. copyWithin almost never comes up in ordinary tasks, but it is worth recognizing.

9. An array is a reference

This is the most important idea of the day and at the same time the most common cause of puzzling errors. When you put an array into a variable, what gets there is not the array itself but a reference to it — like the address of a house, not the house itself.

const a = [1, 2, 3];
const b = a;        // copied the reference, not the array

b.push(4);

console.log(b);     // [1, 2, 3, 4] — as expected
console.log(a);     // [1, 2, 3, 4] — but this is a surprise

There is one array in memory, but it has two names. Changed it through b — saw it in a too. This does not happen with numbers and strings: they are copied whole.

How to make a real copy:

const a = [1, 2, 3];

const copy1 = a.slice();      // a copy through slice
const copy2 = [...a];         // a copy through spread — we will take it apart on day 22
const copy3 = Array.from(a);  // a copy through Array.from

copy1.push(4);
console.log(a);       // [1, 2, 3] — the original is intact
The word const does not forbid changing an array. It only forbids assigning another value to the variable. So const a = [1]; a.push(2); works, while const a = [1]; a = [2]; is the error Assignment to constant variable.

One more rule follows from the same idea: arrays cannot be compared with the equality sign.

console.log([1, 2] === [1, 2]);   // false — these are two different arrays
const a = [1, 2];
const b = a;
console.log(a === b);             // true — one and the same reference

// the contents can be compared like this (for simple values):
console.log(a.join() === [1, 2].join());  // true
A mistake everyone makes: you passed an array to a function, the function did sort or splice — and the calling code’s data got spoiled. The rule is simple: if a function is not supposed to change the array, let it work with a copy. We will talk about this in detail in course 2.

Walkthrough: a function spoiled someone else’s array

A function must return the three latest messages of a chat. The author remembered splice: remove everything except the last three and return the result.

function lastThree(list) {
  list.splice(0, list.length - 3);   // remove everything except the last three
  return list;
}

const messages = ["hi", "how are you?", "fine", "bye", "see you tomorrow"];
lastThree(messages);   // ["fine", "bye", "see you tomorrow"] — the answer is right
messages;              // ["fine", "bye", "see you tomorrow"] — but the chat is gone

The function’s answer is right, so the error is not visible at once. It will show up later, when someone wants to show the whole chat. The cause is that splice changes the very array that was passed: there is one reference. The fix is a copying method, and this is exactly “the last three” from section 5:

function lastThree(list) {
  return list.slice(-3);   // a copy of the last three, the original is intact
}

10. Which is faster: push or unshift

Methods that work with the end of an array (push, pop) run instantly: an element is added or removed in place. Methods that work with the start (unshift, shift) have to shift all the other elements: each one gets a new index.

MethodWhat happensCost
push, popwork with the last elementalways cheap
unshift, shifta shift of all the elementsthe longer the array, the more expensive

On a list of ten elements you will not notice the difference. Let us measure on a hundred thousand — with console.time from day 2. Paste the block into the console whole: if you type it line by line, the measurement will also include the time you spend typing the next one.

const big = [];
console.time("push");
for (let i = 0; i < 100000; i++) big.push(i);
console.timeEnd("push");      // for us — 1–3 ms

const big2 = [];
console.time("unshift");
for (let i = 0; i < 100000; i++) big2.unshift(i);
console.timeEnd("unshift");   // for us — about 500 ms

Your numbers will be different, but the difference is hundreds of times. The same goes for pop and shift. So if you need to build a long list, add to the end with push, and if a queue must be processed from the start, it is better to remember the position than to move the array every time.

11. An array inside an array

An element of an array can be another array. This is how tables are stored: rows inside rows.

const schedule = [
  ["duşenbe", "algebra", "physics"],
  ["sişenbe", "history", "chemistry"],
];

console.log(schedule.length);      // 2 — two rows
console.log(schedule[0][2]);       // "physics" — the first row, the third subject
console.log(schedule[1][0]);       // "sişenbe"

Access goes by two indices: first the row, then the element inside it. Going through such arrays is more convenient with the loops we took apart on day 10, and printing them nicely — with the methods from day 20.

12. The check: Array.isArray

console.log(typeof [1, 2]);        // "object" — useless
console.log(Array.isArray([1, 2])); // true
console.log(Array.isArray("abc"));  // false

The typeof operator answers "object" for an array, because an array is a special kind of object. So there is a separate method for the check — Array.isArray.

This comes in handy more often than it seems. Data from a server arrives in different shapes: sometimes a list, sometimes one value. The check helps you not to break:

function show(data) {
  if (Array.isArray(data)) {
    console.log("a list of " + data.length + " elements");
  } else {
    console.log("one value: " + data);
  }
}

show([1, 2, 3]);   // a list of 3 elements
show("hello");     // one value: hello

Arrays and strings are more alike than they seem

On day 16 we took apart strings. Compare: much is named the same and works the same.

The main difference: a string cannot be changed. Any string method returns a new string, and the original stays. An array, on the other hand, has half of its methods changing it in place. So "abc".toUpperCase() has to be assigned somewhere, while arr.push(1) does not.

14. All together: a shopping cart

Let us build a small real program from the methods of the day. It keeps a cart: adds goods, removes what is not needed, counts and shows the list.

const cart = [];

// the buyer puts goods in
cart.push("bread");
cart.push("tea");
cart.push("butter");
console.log(cart.length + " items in the cart");  // 3 items in the cart

// changed their mind about the tea: first find it, then remove it
const index = cart.indexOf("tea");
if (index !== -1) {
  cart.splice(index, 1);
}
console.log(cart);                 // ["bread", "butter"]

// a check before adding, so as not to add it twice
if (!cart.includes("bread")) {
  cart.push("bread");
}

// show it to the buyer
console.log("In the cart: " + cart.join(", "));   // In the cart: bread, butter

// save the history without spoiling the cart
const history = cart.slice();
cart.length = 0;                   // emptied the cart
console.log(cart);                 // []
console.log(history);              // ["bread", "butter"] — the history is intact

Eight techniques of the day work in this program: push, length, indexOf, splice, includes, join, slice and assigning to length. Real cart code in a shop looks roughly the same — only instead of strings there are objects with a price and a quantity, and we will take them apart on day 21.

An empty array

It is worth remembering separately what the methods return when an array is empty:

const empty = [];
empty.pop();        // undefined — nothing to remove, but no error either
empty.shift();      // undefined
empty.at(-1);       // undefined
empty.indexOf(1);   // -1
empty.slice(1);     // []
empty.join(", ");   // ""

None of them throws an error — they all return “nothing”. So the error shows up further on, where someone tries to work with this “nothing”:

empty.pop().toUpperCase();   // TypeError: Cannot read properties of undefined (reading 'toUpperCase')

If an array may turn out empty, check length before taking an element.

Separately about the error RangeError: Invalid array length. It appears when the length of an array is set to an impossible value: a fraction, a negative number or one that is too big.

new Array(-1);       // RangeError: Invalid array length
const a = [1, 2];
a.length = 2.5;      // RangeError: Failed to set the 'length' property on 'Array': Invalid array length

When writing to length, Chrome gives a longer message, but its end is the same — this is how the error is recognized.

const a = [1, 2, 3];

a.length;            // 3
a[0];  a.at(-1);     // the first; the last

a.push(4);  a.pop();          // the end: add; remove
a.unshift(0);  a.shift();     // the start: add; remove

a.slice(1, 3);       // a copy of a piece    — the original is intact
a.splice(1, 2, "X"); // cut out and insert   — the original changes

a.indexOf(2);        // an index or -1
a.includes(2);       // true / false
a.join(", ");        // a string with commas
a.concat([4, 5]);    // a new array
a.reverse();         // reverse the array itself
a.with(1, "X");      // a copy with a change — the original is intact
a.fill(0);           // fill with one value — the original changes
Array.isArray(a);    // true

// stack: push + pop; queue: push + shift
// an empty array: pop, shift, at → undefined; indexOf → -1; no error
  1. What will [10, 20, 30].length return, and what is the index of the element 30?
    Answer3 and 2. The length is counted from one, the index from zero.
  2. How is slice(1, 3) different from splice(1, 3)?
    Answer slice returns a copy of the elements from 1 to 2 and does not touch the array. splice(1, 3) removes three elements from the array starting at index 1.
  3. What will Array.of(3) return, and what will new Array(3) return?
    Answer [3] — an array of one number. And an empty array of length 3.
  4. Why is it dangerous to write if (arr.indexOf(x))?
    Answer If x stands first, the index equals 0, and zero in a condition means “no”. You need !== -1 or includes.
  5. The “Undo” button removes the last action. Is this a stack or a queue, and which methods are needed?
    Answer A stack: actions are added with push and undone with pop — last in, first out.
  6. How is a hole in an array different from undefined, and how can you see it?
    Answer A hole is the absence of an element. Reading it gives undefined, but indexOf(undefined) skips it and returns -1, while includes(undefined) finds it.
  7. How do you reverse an array without spoiling the original?
    Answer const b = a.toReversed(); or const b = a.slice().reverse();
