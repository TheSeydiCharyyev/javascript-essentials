Day 20. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-20.

Warm-up

1. A loop becomes a method
Easy6 min

replace three familiar loops with methods.

const marks = [5, 4, 3, 5, 2];

// A — how many times shorter?
const big = [];
for (const m of marks) { big.push(m * 10); }

// B
const good = [];
for (const m of marks) { if (m >= 4) { good.push(m); } }

// C
let total = 0;
for (const m of marks) { total += m; }
Each loop turns into exactly one method. Look at what comes out at the end: a list of the same length, a shorter list or one number.
  • all three are rewritten, the results match the original ones;
  • for each one it is named why exactly this method was chosen;
  • it is written down how many lines there were and how many there are now;
  • it is checked that marks did not change after all three.
2. Predict first: what is returned
Easy7 min

catch six non-obvious answers.

const marks = [5, 4, 3];

marks.forEach((m) => m * 10);
marks.map((m) => m >= 4);
marks.findIndex((m) => m === 5);
marks.find((m) => m > 9);
[].every((m) => false);
[].some((m) => true);
The first answer is not an array. The third is a number that would behave as false in a condition. The fifth contradicts common sense but is mathematically right.
  • six predictions are written down before checking;
  • it is explained why forEach returned something other than an array;
  • it is explained how find differs from findIndex in the “not found” case;
  • it is explained why [].every(...) gives true;
  • it is written down how to check findIndex safely in a condition.
3. The trap with parseInt
Easy7 min

take apart an error that does not crash.

console.log(["1", "2", "3"].map(Number));
console.log(["1", "2", "3"].map(parseInt));
console.log(["10", "10", "10"].map(parseInt));

Explain the second and the third lines. Then check the guess by calling parseInt directly with two arguments.

Remember how many arguments map passes to a function, and what the second parameter of parseInt is.
  • all three results are written down;
  • the guess is checked with three direct calls of parseInt;
  • it is explained why the third element in the last line equals two;
  • two correct ways to get [1, 2, 3] are written down;
  • a rule about passing functions by name is stated.

Main tasks

4. A chain of methods
Medium12 min

put several steps into one expression.

Given a “dirty” list of marks. Get from it, with one chain per item:

const raw = [5, 4, 3, 5, 2, 9, 0, 4];
  • the sum of the valid marks (from 2 to 5);
  • the average of the valid ones, rounded to hundredths;
  • the list of the valid ones multiplied by 10;
  • how many fives there are among them — in two ways: through filter and through reduce.
It is handy to select the valid ones once into a separate variable instead of filtering again in each item. The average is the sum divided by the length, but dividing by zero is not allowed.
  • all four results are obtained and written down;
  • both versions of counting fives give the same number;
  • it is written down which of the two versions reads better and why;
  • protection against an empty list is added — it is shown what broke without it;
  • it is explained why filtering earlier pays off more than filtering later.
5. sort for real
Medium13 min

see both dangers of sort with your own eyes.

const nums = [10, 9, 100, 2];

console.log(nums.sort());
console.log(nums);

Explain both outputs. Then sort the list in four ways — ascending, descending, without touching the original with two different techniques — and each time print the source array.

There are two ways not to spoil the original: make a copy before sorting or take a method that makes the copy itself. Both were in the lecture.
  • it is explained why 100 ended up between 10 and 2;
  • it is explained why nums changed;
  • all four ways are shown, the original is printed after each one;
  • an array of words is sorted, and it is explained why the words with a capital letter came first;
  • it is written down which way you will write by default.
6. The cart counts
Medium12 min

bring yesterday’s cart to what was promised.

const items = ["bread", "tea", "butter"];
const prices = [3.5, 12, 25];

Calculate and print:

  • the total cost;
  • the names of the goods cheaper than 10 manats;
  • the prices with a 10 percent markup, rounded to the kopeck;
  • the prices in ascending order, without spoiling the original;
  • a string like “bread — 3.5 m; tea — 12 m; butter — 25 m”.
The arrays are linked by positions, so where you need both the name and the price, you will need the second argument of the callback — the index.
  • all five results are obtained;
  • the total cost is calculated with reduce with an initial value;
  • the index is used for the price filter — it is explained why;
  • after sorting the source array of prices did not change — checked by printing;
  • a product is added to both arrays, and all five items are recalculated without editing the code.
7. The “Report card”: loops into reduce
Medium13 min

rewrite the program of the course without a single loop.

Copy the folder day-18 into day-20 and replace the loops:

  • sum — through reduce with an initial value;
  • maxOf and minOf — through reduce without one;
  • turning the marks into numbers — through map;
  • selecting the valid ones — keep filter, it is already in place.
  • the output matches day 18 to the character — compared line by line;
  • not a single for is left in the program;
  • it is explained why sum has an initial value and maxOf does not;
  • it is checked that maxOf([]) throws an error, and its text is written down;
  • it is written down whether the program became easier to read, and why.

Starred tasks

8. Everything through reduce
Hard10 min

understand reduce well enough to build the other methods with it.

Build with reduce three things that are usually done with other methods, and compare them with the originals:

myMap([5, 4, 3], (m) => m * 10);      // [50, 40, 30]
myFilter([5, 4, 3], (m) => m >= 4);   // [5, 4]
myCount([5, 4, 5], (m) => m === 5);   // 2
The initial value of the first two is an empty array. Inside the function the element is added with push, and the accumulator must be returned — otherwise at the next step it will be undefined.
  • all three functions are written and give the same results as the built-in ones;
  • compared with map, filter and filter().length;
  • it is explained why the function has return acc;
  • it is shown what happens if you remove it;
  • it is written down which of the three variants you would keep in real code and why.
9. Six catches
Hard10 min

bring together everything that behaves unexpectedly today.

// 1
const doubled = [5, 4].forEach((m) => m * 2);
console.log(doubled);

// 2
console.log([].reduce((a, b) => a + b));

// 3
const nums = [10, 9, 100, 2];
console.log(nums.sort(), nums);

// 4
console.log(["5", "10", "15"].map(parseInt));

// 5
const marks = [5, 4, 3];
if (marks.findIndex((m) => m === 5)) { console.log("there is a five"); }

// 6
console.log([3, 1].sort("ascending"));
Two fragments crash, four do not. Fragment 5 prints nothing, although there is a five in the array — and this is the most harmful kind of error. Run the fragments one at a time: one that crashes stops everything below it.
  • the predictions are written down before running;
  • for the two that crash the exact text of the error from your console is written down;
  • it is explained why fragment 5 stayed silent;
  • all six are rewritten correctly;
  • it is written down which two catches are more dangerous than the others and why.
