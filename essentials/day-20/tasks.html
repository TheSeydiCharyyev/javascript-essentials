День 20. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке day-20.

Разминка

1. Цикл становится методом
Легко6 мин

заменить три знакомых цикла на методы.

const marks = [5, 4, 3, 5, 2];

// А — во сколько раз короче?
const big = [];
for (const m of marks) { big.push(m * 10); }

// Б
const good = [];
for (const m of marks) { if (m >= 4) { good.push(m); } }

// В
let total = 0;
for (const m of marks) { total += m; }
Каждый цикл превращается ровно в один метод. Посмотрите, что получается на выходе: список той же длины, список короче или одно число.
  • все три переписаны, результаты совпали с исходными;
  • для каждого названо, почему выбран именно этот метод;
  • записано, сколько строк было и сколько стало;
  • проверено, что marks после всех трёх не изменился.
2. Сначала предскажи: что вернётся
Легко7 мин

поймать шесть неочевидных ответов.

const marks = [5, 4, 3];

marks.forEach((m) => m * 10);
marks.map((m) => m >= 4);
marks.findIndex((m) => m === 5);
marks.find((m) => m > 9);
[].every((m) => false);
[].some((m) => true);
Первый ответ не массив. Третий — число, которое в условии повело бы себя как ложь. Пятый противоречит здравому смыслу, но математически верен.
  • шесть предсказаний записаны до проверки;
  • объяснено, почему forEach вернул не массив;
  • объяснено, чем find отличается от findIndex в случае «не нашлось»;
  • объяснено, почему [].every(...) даёт true;
  • записано, как безопасно проверить findIndex в условии.
3. Ловушка с parseInt
Легко7 мин

разобрать ошибку, которая не падает.

console.log(["1", "2", "3"].map(Number));
console.log(["1", "2", "3"].map(parseInt));
console.log(["10", "10", "10"].map(parseInt));

Объясните вторую и третью строки. Потом проверьте догадку, вызвав parseInt напрямую с двумя аргументами.

Вспомните, сколько аргументов map передаёт функции, и какой у parseInt второй параметр.
  • все три результата записаны;
  • догадка проверена тремя прямыми вызовами parseInt;
  • объяснено, почему третий элемент в последней строке равен двум;
  • записаны два правильных способа получить [1, 2, 3];
  • сформулировано правило про передачу функций по имени.

Основные задания

4. Цепочка методов
Средне12 мин

собрать несколько шагов в одну запись.

Дан «грязный» список оценок. Получите из него, одной цепочкой на каждый пункт:

const raw = [5, 4, 3, 5, 2, 9, 0, 4];
  • сумму годных оценок (от 2 до 5);
  • средний балл годных, округлённый до сотых;
  • список годных, умноженных на 10;
  • сколько среди них пятёрок — двумя способами: через filter и через reduce.
Годные удобно отобрать один раз в отдельную переменную, а не фильтровать заново в каждом пункте. Среднее — это сумма, делённая на длину, но делить на ноль нельзя.
  • все четыре результата получены и записаны;
  • обе версии подсчёта пятёрок дают одинаковое число;
  • записано, какая из двух версий читается лучше и почему;
  • добавлена защита от пустого списка — показано, что ломалось без неё;
  • объяснено, почему фильтровать выгоднее раньше, чем позже.
5. sort по-настоящему
Средне13 мин

увидеть обе опасности sort своими глазами.

const nums = [10, 9, 100, 2];

console.log(nums.sort());
console.log(nums);

Объясните оба вывода. Потом отсортируйте список четырьмя способами — по возрастанию, по убыванию, не трогая оригинал двумя разными приёмами — и каждый раз печатайте исходный массив.

Не испортить оригинал можно двумя способами: сделать копию перед сортировкой или взять метод, который копию делает сам. Оба были в лекции.
  • объяснено, почему 100 оказалось между 10 и 2;
  • объяснено, почему nums изменился;
  • все четыре способа показаны, после каждого напечатан оригинал;
  • отсортирован массив слов и объяснено, почему слова с большой буквы оказались впереди;
  • записано, какой способ вы будете писать по умолчанию.
6. Корзина считает
Средне12 мин

довести вчерашнюю корзину до обещанного.

const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];

Посчитайте и выведите:

  • общую стоимость;
  • названия товаров дешевле 10 манатов;
  • цены с наценкой 10 процентов, округлённые до копеек;
  • цены по возрастанию, не испортив оригинал;
  • строку вида «хлеб — 3.5 м; чай — 12 м; масло — 25 м».
Массивы связаны позициями, поэтому там, где нужны и название, и цена, понадобится второй аргумент колбэка — индекс.
  • все пять результатов получены;
  • общая стоимость посчитана через reduce с начальным значением;
  • для фильтра по цене использован индекс — объяснено зачем;
  • после сортировки исходный массив цен не изменился — проверено печатью;
  • добавлен товар в оба массива, и все пять пунктов пересчитаны без правок кода.
7. «Табель»: циклы в reduce
Средне13 мин

переписать сквозную программу без единого цикла.

Скопируйте папку day-18 в day-20 и замените циклы:

  • sum — через reduce с начальным значением;
  • maxOf и minOf — через reduce без него;
  • превращение оценок — через map;
  • отбор годных — оставить filter, он уже на месте.
  • вывод совпал с днём 18 до символа — сверено построчно;
  • в программе не осталось ни одного for;
  • объяснено, почему у sum начальное значение есть, а у maxOf нет;
  • проверено, что maxOf([]) бросает ошибку, и записан её текст;
  • записано, стало ли понятнее читать программу, и почему.

Со звёздочкой

8. Всё через reduce
Сложно10 мин

понять reduce настолько, чтобы собрать им остальные методы.

Соберите через reduce три вещи, которые обычно делают другими методами, и сверьте с оригиналами:

myMap([5, 4, 3], (m) => m * 10);      // [50, 40, 30]
myFilter([5, 4, 3], (m) => m >= 4);   // [5, 4]
myCount([5, 4, 5], (m) => m === 5);   // 2
Начальное значение у первых двух — пустой массив. Внутри функции элемент добавляют через push и обязательно возвращают накопитель — иначе на следующем шаге он окажется undefined.
  • все три функции написаны и дают те же результаты, что встроенные;
  • сверено с map, filter и filter().length;
  • объяснено, зачем в функции стоит return acc;
  • показано, что случится, если его убрать;
  • записано, какой из трёх вариантов вы бы оставили в настоящем коде и почему.
9. Шесть подвохов
Сложно10 мин

собрать вместе всё, что сегодня ведёт себя неожиданно.

// 1
const doubled = [5, 4].forEach((m) => m * 2);
console.log(doubled);

// 2
console.log([].reduce((a, b) => a + b));

// 3
const nums = [10, 9, 100, 2];
console.log(nums.sort(), nums);

// 4
console.log(["5", "10", "15"].map(parseInt));

// 5
const marks = [5, 4, 3];
if (marks.findIndex((m) => m === 5)) { console.log("пятёрка есть"); }

// 6
console.log([3, 1].sort("по возрастанию"));
Два фрагмента падают, четыре — нет. Фрагмент 5 не выведет ничего, хотя пятёрка в массиве есть, — и это самый вредный вид ошибки.
  • предсказания записаны до запуска;
  • для двух падающих записан точный текст ошибки из своей консоли;
  • объяснено, почему фрагмент 5 промолчал;
  • все шесть переписаны правильно;
  • записано, какие два подвоха опаснее остальных и почему.
