Day 21. Objects

A summary of the lecture: properties, checks, iteration, copies.

The main points

An array is “many of the same kind, in order”. An object is “one whole of different parts, each with its own name”. A list of goods is an array of objects. 
const student = { name: "Aman", age: 17, city: "Mary" };

student.name;      // "Aman" — a dot: the name is read literally
student["name"];   // "Aman" — brackets: any expression inside
const key = "age";
student[key];      // 17 — a key in a variable: ONLY brackets
student.phone;     // undefined, not an error
Brackets are required in three cases: a key in a variable, a key with a space or a hyphen, a numeric key. When iterating, numeric keys always come first and in ascending order.

Everything can be changed

const pupil = { name: "Meret", age: 16 };

pupil.age = 17;          // changed
pupil.group = "1-A";     // added
delete pupil.name;       // deleted
pupil;                   // { age: 17, group: "1-A" }

const does not get in the way of an object: it forbids changing the variable itself, not the contents. delete returns true almost always — nothing is checked by its result.

Is there a property

const s = { name: "Aman", phone: undefined };

s.phone !== undefined;        // false — but the property is there
"phone" in s;                 // true
Object.hasOwn(s, "phone");    // true

"toString" in s;              // true  — got from the language
Object.hasOwn(s, "toString"); // false — no own one
For your own data take Object.hasOwn: it answers exactly the question asked and does not find inherited things.

Iterating

Object.keys(student);      // ["name", "age", "city"]
Object.values(student);    // ["Aman", 17, "Mary"]
Object.entries(student);   // [["name", "Aman"], ["age", 17], …]

Object.keys(student).length;   // 3 — an object has NO length

Object.keys(student).forEach((key) => {
  console.log(key + ": " + student[key]);
});

for...in is shorter, but it looks into inherited things and does not give an array, so new code more often uses Object.keys.

Copies and references

const a = { x: 1 };
const b = a;                          // NOT a copy: the same reference
const copy = Object.assign({}, a);    // a copy of the top level

const defaults = { city: "Mary", group: "1-A" };
const given = { name: "Aman", city: "Ashgabat" };
Object.assign({}, defaults, given);   // { city: "Ashgabat", group: "1-A", name: "Aman" } — {} first!
Object.assign(defaults, given);       // A MISTAKE:
defaults;                             // { city: "Ashgabat", group: "1-A", name: "Aman" } — spoiled
The copy is shallow. Nested objects stay shared: after copy.address.city = "Ashgabat" the original changes too. Flat objects are copied fine, nested ones are not.

Methods and new things

const o = {
  items: [],
  add(item) { this.items.push(item); },   // course 2
  count() { return this.items.length; },  // course 2
};

Object.fromEntries([["a", 1]]);                  // { a: 1 }
Object.groupBy([5, 4, 3, 5, 2], (m) => m >= 4 ? "ok" : "no");
// { ok: [5, 4, 5], no: [3, 2] } — the method is very new
Nine error pages — more than on any other day. Almost all of them are syntax errors: { x = 5 } instead of { x: 5 }, a forgotten bracket, a dot without a name. Chrome most often says “Unexpected token” or “Unexpected identifier” and shows the place — look for the error one line above; the MDN wordings are taken from Firefox, they are clearer.
Two errors only in strict mode: assigning a property to a number and deleting a protected property. Without strict mode — silence. These are the fourth and fifth such cases in the course after days 4, 14 and 16.
  1. Describe yourself as an object of five properties, including an array and a nested object. Print each property in two ways — through a dot and through brackets.
  2. Go through your object in three ways: Object.keys, Object.entries and for...in. Compare the code.
  3. Make a copy with Object.assign, change the nested object in the copy and check the original. Explain the result in writing.
  4. Turn yesterday’s two arrays (goods and prices) into an array of objects and repeat all five calculations from day 20 — now without indices.
