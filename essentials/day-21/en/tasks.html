Day 21. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-21.

Warm-up

1. From two arrays to objects
Easy6 min

feel the difference between a link by order and a link inside.

const items = ["bread", "tea", "butter"];
const prices = [3.5, 12, 25];

Build from them an array of objects of the form { name, price } — by hand, not automatically. Then sort only the array prices from the source data and explain what happened to the matching.

It is enough to write three objects by hand. The main thing is to compare the two approaches afterwards on one and the same operation: sorting.
  • the array of objects is written and printed;
  • it is shown that after sorting prices the matching with items broke;
  • it is shown that sorting the array of objects breaks nothing;
  • the rule for choosing “an array or an object” is written down in your own words.
2. Predict first: access and checks
Easy7 min

catch the difference between a dot, brackets and the three checks.

const student = { name: "Aman", phone: undefined };
const key = "name";

student.key;
student[key];
student.phone !== undefined;
"phone" in student;
Object.hasOwn(student, "phone");
Object.hasOwn(student, "toString");
"toString" in student;
Boolean({});
The first two lines differ by one character and give completely different things. The last two pairs show how in differs from hasOwn and why an empty object is a trap.
  • eight predictions are written down before checking;
  • it is explained why student.key gives undefined;
  • it is explained why the first check about phone lies;
  • it is explained where the object gets toString from;
  • it is written down how to check correctly that an object is empty.
3. keys, values, entries
Easy7 min

turn an object into an array and back.

const prices = { bread: 3.5, tea: 12, butter: 25 };

Get: a list of names, a list of prices, a list of pairs, the number of goods and the total cost. Then build the object back from the pairs and make sure it matches the source one.

Count the total cost from Object.values with yesterday’s reduce. The number is the length of the array of keys: an object has no length of its own.
  • all five values are obtained;
  • the object is built back with Object.fromEntries;
  • it is written down why prices.length does not work;
  • a numeric key is added — and it is written down where it ended up when iterating.

Main tasks

4. Default settings
Medium12 min

master merging objects and not spoil the source data.

const defaults = { city: "Mary", group: "1-A", year: 2026 };
const given = { name: "Aman", city: "Ashgabat" };

Build the full settings so that what the user set overrides the defaults. Then check that defaults did not change — and show a variant in which it gets spoiled.

The order of the arguments decides what overrides what. And the first argument decides which object suffers.
  • the result has all four properties, the city is from given;
  • defaults is printed before and after — it did not change;
  • a call that spoils defaults is shown, and it is explained why;
  • a function makeSettings(given) with a default from day 14 is written;
  • it is checked that makeSettings() without arguments works.
5. A copy that is not a copy
Medium13 min

see a reference and a shallow copy with your own eyes.

const student = {
  name: "Aman",
  marks: [5, 4],
  address: { city: "Mary", street: "Mir" },
};

Carry out three experiments, printing the original each time:

  1. const b = student; — change b.name;
  2. const copy = Object.assign({}, student); — change copy.name;
  3. in the same copy change copy.address.city and add a mark to copy.marks.
The third experiment is the main one. The top level of the copy is independent, while the nested object and array stayed shared. The array here behaves the same way as the object.
  • the state of the original is written down for all three experiments;
  • it is explained why experiment 1 changed the original and experiment 2 did not;
  • it is explained why experiment 3 changed the original in both cases;
  • a way to copy address separately is suggested — and it is checked that now the original is intact;
  • the rule is written down in one line: when assign is enough, and when it is not.
6. A cart without indices
Medium12 min

rewrite yesterday’s cart with objects.

const cart = [
  { name: "bread", price: 3.5 },
  { name: "tea", price: 12 },
  { name: "butter", price: 25 },
];

Repeat all five calculations of day 20 — the sum, the cheap goods, the prices with a markup, sorting, the string for the buyer — and compare the code with yesterday’s.

Then add a quantity to each product and count the cost taking it into account.

None of the five items needs an index any more. And adding the quantity should not require edits in the lines already written — if it did, look at where you tied yourself to the structure.
  • all five results matched yesterday’s;
  • no callback uses an index;
  • sorting by name is added — it is explained why yesterday it was hard to do;
  • the quantity is added, the total cost is recalculated;
  • it is written down how many lines had to change when the quantity was added.
7. The “Report card”: a student is an object
Medium13 min

separate the data from the code in the program that runs through the course.

Copy the folder day-20 to day-21 and rebuild it:

  • the array students made of objects { name, marks };
  • makeRow(student) takes one object instead of a name and rest marks;
  • the output goes through students.map(makeRow);
  • protection against missing properties with ?? from day 7.
  • the output matched day 20 to the character;
  • makeRow({}) does not crash — what it returned is written down;
  • a sixth student is added by editing only the data array;
  • it is explained why makeRow can be passed to map by name, while parseInt could not yesterday;
  • a group property is added and only the students of one group are printed.

Starred tasks

8. Your own groupBy
Hard10 min

build an object by accumulation and check it against the built-in method.

Write myGroupBy(list, getKey) with reduce and test it on two data sets.

myGroupBy([5, 4, 3, 5, 2], (m) => m % 2 === 0 ? "even" : "odd");
// { odd: [5, 3, 5], even: [4, 2] }

myGroupBy(cart, (item) => item.price < 10 ? "cheap" : "expensive");
// { cheap: [...], expensive: [...] }
The accumulator is an empty object. At each step check whether there is already such a key (Object.hasOwn), create an empty array if needed and do not forget to return the accumulator.
  • both examples give what is written;
  • the result is checked against Object.groupBy;
  • it is explained why the check “is there already such a key” is needed;
  • it is tested on an empty list — what came back is written down;
  • it is written down why the accumulator is an object and not an array.
9. Errors with objects
Hard10 min

get all the errors of the day and see where Chrome stays silent.

Each fragment goes into a separate file: a syntax error breaks the whole file, and a crashed line stops everything below it. Write down the exact text of the error from your console.

// 1
const o = { x = 5 };

// 2
const o = { a: 1, b: 2 c: 3 };

// 3
const a = [1, 2;

// 4
console.log("x" in "string");

// 5
const o = undefined;
console.log(o.x);

// 6 — first without "use strict", then with it
const n = 1;
n.x = 5;
console.log(n.x);
Fragment 6 is the only one that behaves differently: without strict mode it stays silent, and the answer is wrong. Compare the texts of errors 1–3 with the titles of the MDN pages from the reference of the day.
  • the exact error text is written down for fragments 1–5;
  • it is noted that the Chrome texts and the MDN titles do not match, and the reason is named;
  • both behaviors are written down for fragment 6;
  • all six are rewritten correctly;
  • it is written down which of the errors is more dangerous than the others, and why.
