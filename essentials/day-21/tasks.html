День 21. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 делаем в консоли, дальше — в папке day-21.

Разминка

1. Из двух массивов в объекты
Легко6 мин

почувствовать разницу между связью по порядку и связью внутри.

const items = ["хлеб", "чай", "масло"];
const prices = [3.5, 12, 25];

Соберите из них массив объектов вида { name, price } — вручную, не автоматически. Потом отсортируйте только массив prices из исходных данных и объясните, что стало с соответствием.

Достаточно написать три объекта руками. Главное — потом сравнить два подхода на одной и той же операции: сортировке.
  • массив объектов написан и выведен;
  • показано, что после сортировки prices соответствие с items сломалось;
  • показано, что сортировка массива объектов ничего не ломает;
  • записано правило выбора «массив или объект» своими словами.
2. Сначала предскажи: доступ и проверки
Легко7 мин

поймать разницу между точкой, скобками и тремя проверками.

const student = { name: "Аман", phone: undefined };
const key = "name";

student.key;
student[key];
student.phone !== undefined;
"phone" in student;
Object.hasOwn(student, "phone");
Object.hasOwn(student, "toString");
"toString" in student;
Boolean({});
Первые две строки различаются одним символом и дают совершенно разное. Две последние пары показывают, чем in отличается от hasOwn и почему пустой объект — ловушка.
  • восемь предсказаний записаны до проверки;
  • объяснено, почему student.key даёт undefined;
  • объяснено, почему первая проверка про phone врёт;
  • объяснено, откуда у объекта toString;
  • записано, как правильно проверить, что объект пустой.
3. keys, values, entries
Легко7 мин

превратить объект в массив и обратно.

const prices = { хлеб: 3.5, чай: 12, масло: 25 };

Получите: список названий, список цен, список пар, количество товаров и общую стоимость. Потом соберите из пар объект обратно и убедитесь, что он совпал с исходным.

Общую стоимость считайте из Object.values вчерашним reduce. Количество — это длина массива ключей: у объекта своего length нет.
  • все пять значений получены;
  • объект собран обратно через Object.fromEntries;
  • записано, почему prices.length не работает;
  • добавлен числовой ключ — и записано, где он оказался при переборе.

Основные задания

4. Настройки по умолчанию
Средне12 мин

освоить объединение объектов и не испортить исходные данные.

const defaults = { city: "Мары", group: "1-А", year: 2026 };
const given = { name: "Аман", city: "Ашхабад" };

Соберите полные настройки так, чтобы заданное пользователем перекрывало умолчания. Потом проверьте, что defaults не изменился — и покажите вариант, в котором он портится.

Порядок аргументов решает, что перекрывает что. А первый аргумент решает, какой объект пострадает.
  • результат содержит все четыре свойства, город — из given;
  • defaults напечатан до и после — не изменился;
  • показан вызов, который портит defaults, и объяснено почему;
  • написана функция makeSettings(given) с умолчанием из дня 14;
  • проверено, что makeSettings() без аргументов работает.
5. Копия, которая не копия
Средне13 мин

увидеть ссылку и поверхностную копию своими глазами.

const student = {
  name: "Аман",
  marks: [5, 4],
  address: { city: "Мары", street: "Мир" },
};

Проведите три опыта, каждый раз печатая оригинал:

  1. const b = student; — измените b.name;
  2. const copy = Object.assign({}, student); — измените copy.name;
  3. у той же копии измените copy.address.city и добавьте оценку в copy.marks.
Третий опыт — главный. Верхний уровень копии независим, а вложенные объект и массив остались общими. Массив здесь ведёт себя так же, как объект.
  • для всех трёх опытов записано состояние оригинала;
  • объяснено, почему опыт 1 изменил оригинал, а опыт 2 — нет;
  • объяснено, почему опыт 3 изменил оригинал в обоих случаях;
  • предложен способ скопировать address отдельно — и проверено, что теперь оригинал цел;
  • записано правило одной строкой: когда assign достаточно, а когда нет.
6. Корзина без индексов
Средне12 мин

переписать вчерашнюю корзину на объектах.

const cart = [
  { name: "хлеб", price: 3.5 },
  { name: "чай", price: 12 },
  { name: "масло", price: 25 },
];

Повторите все пять вычислений дня 20 — сумма, дешёвые товары, цены с наценкой, сортировка, строка для покупателя — и сравните код с вчерашним.

Потом добавьте каждому товару количество и посчитайте стоимость с учётом него.

Ни в одном из пяти пунктов индекс больше не нужен. А добавление количества не должно потребовать правок в уже написанных строках — если потребовало, посмотрите, где вы завязались на структуру.
  • все пять результатов совпали со вчерашними;
  • ни в одном колбэке не используется индекс;
  • добавлена сортировка по названию — объяснено, почему вчера её было сделать трудно;
  • количество добавлено, общая стоимость пересчитана;
  • записано, сколько строк пришлось изменить при добавлении количества.

8. Свой groupBy
Сложно10 мин

собрать объект накоплением и сверить со встроенным методом.

Напишите myGroupBy(list, getKey) через reduce и проверьте на двух наборах данных.

myGroupBy([5, 4, 3, 5, 2], (m) => m % 2 === 0 ? "чётные" : "нечётные");
// { нечётные: [5, 3, 5], чётные: [4, 2] }

myGroupBy(cart, (item) => item.price < 10 ? "дёшево" : "дорого");
// { дёшево: [...], дорого: [...] }
Накопитель — пустой объект. На каждом шаге проверьте, есть ли уже такой ключ (Object.hasOwn), при необходимости заведите пустой массив и не забудьте вернуть накопитель.
  • оба примера дают то, что написано;
  • результат сверен с Object.groupBy;
  • объяснено, зачем нужна проверка «есть ли уже такой ключ»;
  • проверено на пустом списке — записано, что вернулось;
  • записано, почему в накопителе объект, а не массив.

// 1

// 3

// 4

  • для фрагментов 1–5 записан точный текст ошибки;
