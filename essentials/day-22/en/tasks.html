Day 22. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 are done in the console, the rest in the folder day-22.

Warm-up

1. Take it apart
Easy6 min

write your first patterns for an array and an object.

const marks = [5, 4, 3, 2];
const student = { name: "Aman", age: 17, address: { city: "Mary" } };

With one line for each item, get: the first and the second mark; the third one, skipping two; the first one and the rest; the name and the age; the city; the name under the name who; the group with the default "1-A".

Seven lines, each with exactly one const. For the city you will need a nested pattern, for the group — an equals sign inside the curly braces.
  • all seven items are done with destructuring, without access by index or through a dot;
  • the values are printed and matched the expected ones;
  • it is written down why no variable address appeared when the city was taken apart;
  • it is explained where the group came from, although the object does not have it.
2. Predict first: what will you get
Easy7 min

catch the edges of destructuring.

const [a = 1] = [];
const [b = 1] = [undefined];
const [c = 1] = [null];
const { p = 10 } = { p: null };
const { q = 10 } = {};
const { r } = { r: undefined };
The rule is the same as for the default parameters from day 14: a default fires on exactly one value. Two lines out of six check exactly that.
  • six predictions are written down before checking;
  • the lines where the default did not fire are found, and the reason is named;
  • it is explained how the last two lines differ;
  • the rule is put into one sentence.
3. Three dots in two roles
Easy7 min

learn to tell collecting from spreading.

For each line write down what the three dots do — collect or spread — and what you will get.

function f(...args) { return args.length; }
f(...[1, 2, 3]);

const [head, ...tail] = [5, 4, 3];
const copy = [...tail];

const { name, ...others } = { name: "Aman", age: 17, city: "Mary" };
const merged = { ...others, group: "1-A" };

Math.max(...[3, 7, 5]);
[..."Mary"];
Look at the place: in a function declaration and to the left of the equals sign they collect; in a call and inside square or curly brackets they spread.
  • the role and the result are given for all eight lines;
  • the line where three dots appear in both roles one after another is found;
  • it is explained why Math.max([3, 7, 5]) without dots does not work;
  • the rule for telling them apart is written down in your own words.

Main tasks

4. A function with settings
Medium12 min

replace a long list of parameters with one object.

Here is the function from day 15 that was inconvenient to use:

function makeLine(name, value, unit = "", prefix = "", suffix = "", total = 0) {
  // ...
}

makeLine("Present", 3, undefined, undefined, "", 5);

Rewrite it so that it takes one object with the same settings and defaults. Show three calls: a full one, a minimal one and one that skips the middle.

The pattern is put right in the parameter’s parentheses, and the defaults are written inside it. Do not forget = {} at the end if the function can be called with no arguments at all.
  • the function takes one object, all the defaults are kept;
  • the three calls are written and give the correct results;
  • a call without arguments does not crash — it is shown why;
  • it is explained why the new call reads better than the old one;
  • it is written down at what number of parameters you will switch to an object.
5. Copies and merging
Medium13 min

check what spread copies and what it does not.

const defaults = { city: "Mary", group: "1-A", theme: { color: "white" } };
const given = { name: "Aman", city: "Ashgabat" };

Build the final settings with three dots. Then carry out four checks, printing defaults each time:

  1. change city in the result;
  2. change theme.color in the result;
  3. swap the order of the objects in the merge;
  4. add a year property to a copy of given.
The second item is the main one. The top level was copied, while the nested object theme stayed shared: this is the same shallow copy as yesterday with Object.assign.
  • the final settings are built, the city is taken from given;
  • the state of defaults is written down for all four checks;
  • it is explained why item 1 did not spoil the original and item 2 did;
  • it is shown how to copy theme separately;
  • the result is compared with Object.assign — what is the same is written down.
6. Safe reading
Medium12 min

use ?. where it is needed, and not where it is not.

const students = [
  { name: "Aman", address: { city: "Mary" } },
  { name: "Meret" },
  { name: "Gülnar", address: { city: "Ashgabat" }, greet() { return "salam"; } },
];

For each student print a line like “Aman — Mary”, putting in “not given” if there is no city. Then call greet on all three — so that the program does not crash.

For the city you will need both ?. and ?? — they work as a pair. For the method there is a separate form with parentheses.
  • all three lines are printed correctly;
  • the greet call does not crash on any student;
  • it is written down what the call returned for those who do not have the method;
  • a place where ?. is not needed is found, and it is explained why;
  • it is shown what happens if you make a typo in a property name with ?. — and the conclusion is written down.
7. The “Report card”, shorter
Medium13 min

shorten the program that runs through the course with today’s three forms.

Copy the folder day-21 to day-22 and rewrite it:

  • makeRow takes the pattern { name = "unnamed", marks = [] } = {};
  • delete maxOf and minOf — use Math.max(...valid) and Math.min(...valid) instead;
  • a student is added with [...students, newStudent].
  • the output matched day 21 to the character;
  • the two functions are deleted, the program got shorter — it is written down by how many lines;
  • makeRow() without arguments works — it is explained what = {} gives;
  • it is shown that [...students, newStudent] does not change the original;
  • it is explained why the variable inside had to get a name other than marks.

Starred tasks

8. Rewrite someone else’s code
Hard10 min

use all three forms of the day at once.

const order = {
  id: 7,
  customer: { name: "Aman", phone: null },
  items: [{ name: "tea", price: 12 }, { name: "bread", price: 3.5 }],
};

function describe(order) {
  const id = order.id;
  const name = order.customer.name;
  const phone = order.customer && order.customer.phone
    ? order.customer.phone
    : "no phone";
  const total = order.items.reduce(function (sum, item) {
    return sum + item.price;
  }, 0);
  return "Order " + id + ": " + name + ", " + phone + ", total " + total;
}

Shorten the function using destructuring in the parameter, ??, arrows and a template string. The result must match to the character.

You can take the nested part apart right away: { customer: { name, phone } }. The phone check will be replaced by ??, and inside reduce a pattern for the element will come in handy.
  • the new version gives exactly the same string — checked by comparison;
  • all three forms of the day are used;
  • it is tested on an order without customer — what came out is written down;
  • protection is added so that such an order does not crash the function;
  • it is written down whether it became clearer, and which places you left as they were.
9. Six catches
Hard10 min

collect everything that behaves unexpectedly today.

// 1
let a;
{ a } = { a: 1 };

// 2
const { x } = undefined;

// 3
const obj = { inner: { n: 1 } };
const copy = { ...obj };
copy.inner.n = 99;
console.log(obj.inner.n);

// 4
const student = { name: "Meret" };
console.log(student.adress?.city);

// 5
console.log(Math.max([3, 7, 5]));

// 6
const nums = [1, 2];
const [p, q] = [q, p];
Each fragment goes into a separate file: the first one breaks the whole file before it even runs. Fragment 4 has a typo in the word “address” — and ?. hides it. Fragment 6 looks like the swap from the lecture, but there is nothing to swap there.
  • the predictions are written down before running;
  • for the ones that crash, the exact error text is written down;
  • it is explained why fragment 4 does not crash, although it has an error;
  • it is explained what is wrong with fragment 6;
  • all six are rewritten correctly.
