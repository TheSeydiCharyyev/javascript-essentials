День 22. Деструктуризация, spread, ?.

Выжимка лекции: разобрать, разложить, безопасно прочитать.

Главное

Новых возможностей сегодня нет — есть три короткие записи для вчерашнего: разобрать объект на части, скопировать и объединить, прочитать поле, которого может не быть.

Деструктуризация

const [first, second] = marks;   // массив — ПО ПОЗИЦИИ
const [, , third] = marks;       // пропуск
const [a, b = 0] = marks;        // умолчание (только на undefined)
const [head, ...tail] = marks;   // остаток
[x, y] = [y, x];                 // обмен; точка с запятой на строке ВЫШЕ

const { name, age } = student;            // объект — ПО ИМЕНИ
const { name: studentName } = student;    // переименование
const { group = "1-А" } = student;        // умолчание
const { address: { city } } = student;    // вложенная
const { name: n, ...others } = student;   // остаток
У массива соответствие по позиции, имена придумываете вы. У объекта — по имени свойства, порядок в образце не важен.

Разбирать массив по позициям стоит только там, где позиция что-то значит, — например, пару «ключ — значение» из Object.entries.

В параметрах и колбэках

function makeRow({ name, marks = [] } = {}) { }   // = {} спасает от вызова без аргументов

cart.map(({ name, price }) => name + " — " + price);

for (const [key, value] of Object.entries(prices)) { }

Плюс к краткости: у функции с объектом-параметром порядок аргументов перестаёт иметь значение, и вызов читается сам по себе.

Три ловушки. Без const нужны круглые скобки: ({ a } = obj). Разобрать undefined нельзя — TypeError: Cannot destructure property…. Умолчание не сработает на null.

Spread — три точки раскладывают

const copy = [...marks];                    // копия массива
const both = [...a, ...b];                  // объединение
const merged = { ...defaults, ...given };   // правый побеждает
const plus = { ...obj, year: 2026 };        // копия плюс свойство

Math.max(...marks);   // массив → аргументы
[..."Аман"];          // ["А", "м", "а", "н"]
Копия поверхностная — вложенные объекты остаются общими, как у Object.assign.
Литерал объекта нельзя начинать со строки: { ...obj }; прочтётся как блок. Кладите результат в переменную.

Три точки: где стоят — то и делают

Необязательная цепочка

student.address.city;    // TypeError, если адреса нет
student.address?.city;   // undefined, без ошибки

student?.[key];        // свойство по переменной
student.greet?.();     // вызов метода, которого может не быть

student.address?.city ?? "не указан";
student.address?.city.length;   // undefined — вся цепочка обрывается целиком
Чего ?. не делает: не спасает от опечатки в имени свойства (молча undefined) и от необъявленной переменной (ReferenceError).
Не ставьте его везде подряд: программа перестанет падать, но начнёт врать. Он нужен там, где отсутствие поля — нормальная ситуация.
  1. Возьмите объект студента из дня 21 и достаньте из него имя, возраст, город и первую оценку — одной строкой на каждое, с деструктуризацией.
  2. Перепишите три своих колбэка из дня 20 так, чтобы параметр разбирался образцом: ({ name, price }) => …
  3. Скопируйте объект с вложенным объектом через { ...obj }, измените вложенное и проверьте оригинал. Запишите, что получилось.
  4. Найдите в своём коде за прошлые дни три места, где ?. уместен, и три, где он был бы лишним. Объясните разницу.
