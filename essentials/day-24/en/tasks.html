Day 24. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Almost all tasks are done on the study page “Group JS-1” from the lecture: build it in the folder day-24 and keep the console open. Task 4 is done on your own page, task 7 — in the folder day-24/tabel.

Warm-up

1. Three ways
Easy6 min

make sure that different ways of searching lead to one and the same object.

Find the heading h1 in three ways and put it into three variables: with getElementById, with querySelector by id and with querySelector by the selector "header h1". Compare them in pairs and print nodeName.

=== for objects asks “is it the same box”. If all three comparisons give true, then the tree has one heading, and there are many ways to get to it.
  • three variables, three different ways of searching;
  • all three comparisons gave true;
  • it is written down what nodeName returned and why in capital letters;
  • it is explained why the hash is not needed in getElementById but is required in a selector.
2. How many of what
Easy7 min

learn to predict what a selector will find.

First write down on paper how many elements each selector will find. Then check:

const selectors = ["li", ".absent", "li:not(.absent)", "p", ".note", "nav a", "main *"];

selectors.forEach((sel) => {
  console.log(sel, document.querySelectorAll(sel).length);
});
* is any element, and main * is any element inside main. Count with the tree scheme from the lecture; main itself is not part of the answer.
  • the predictions are written down before running;
  • the real answer is written down for all seven selectors;
  • for every miss it is explained where the mistake was;
  • an eighth selector that finds nothing is added — it is written down what length returned.
3. Nodes and elements
Easy7 min

see the text nodes made of whitespace and find the pattern.

["#list", "nav", "footer", "header"].forEach((sel) => {
  const el = document.querySelector(sel);
  console.log(sel, el.childNodes.length, el.children.length);
});

Predict both numbers for each element, run the code and compare. Then print nodeName of firstChild and of firstElementChild for each of the four.

Look at the markup: each child stands on its own line. How many pieces of “a line break plus indentation” are there around the five list items?
  • the predictions are written down before running;
  • a formula linking the two numbers is found and checked on all four;
  • it is written down that for all four firstChild is a text node;
  • it is explained what changes if the list is written in one line without spaces.

Main tasks

4. Selectors
Medium12 min

pick a selector for a task and check that exactly what is needed was found.

Create a page with a schedule:

<section id="week">
  <h2>Schedule</h2>
  <ul class="days">
    <li class="day">Monday <span class="subject">JavaScript</span></li>
    <li class="day off">Tuesday</li>
    <li class="day">Wednesday <span class="subject">JavaScript</span> <span class="subject extra">HTML</span></li>
    <li class="day off">Thursday</li>
    <li class="day">Friday <span class="subject">JavaScript</span></li>
  </ul>
  <p class="note">Weekend — Saturday and Sunday</p>
</section>

For each item write one selector and check it with querySelectorAll(...).length: all days (5), days off (2), working days (3), all subjects (4), the extra subject (1), Wednesday’s subjects (2), the first and the last day (1 each).

For working days :not comes in handy, for Wednesday — :nth-child(3) and a space before the subject’s class. Check not only the number but also the elements themselves: print the list to the console.
  • all eight selectors give exactly the stated number;
  • each list is printed to the console and looked through;
  • one selector is broken on purpose (two dots in a row) — the error text is written down;
  • it is explained how .day .subject differs from .day > .subject and why here they find the same thing.
5. A walk through the tree
Medium13 min

get to any element by transitions, without a new search.

const meret = document.querySelector(".absent");

Starting from meret and using only transitions and closest, get to seven elements: Aman, Oguljan, the list ul, main, footer, the heading h1 and the second link in nav. Check each result against a direct search with ===.

Distant elements are easy to reach through a common ancestor: climb up to main, step to a sibling, go down. header is the sibling of main on the left, footer — on the right.
  • all seven paths are written down, each comparison with a direct search gave true;
  • two paths lead to main: a chain of parentElement and one through closest;
  • it is explained which paths will break if ul is wrapped in an extra div;
  • a transition that returns null is found, and it is explained why.
6. Where the element lies
Medium12 min

answer questions about an element with closest and matches.

Write where(el): it returns "header", "list", "footer" or "other" — depending on where the element lies. Test it on the heading, on Meret, on the paragraph from the footer and on the paragraph with the schedule.

where(document.querySelector("h1"));          // "header"
where(document.querySelector(".absent"));     // "list"
where(document.querySelector("footer p"));    // "footer"
where(document.getElementById("info"));       // "other"

Then count those who were absent in two ways: with querySelectorAll(".absent") and with an array of all li, filter and matches.

closest returns an element or null, and in an if condition an element is truthy, null is falsy. For filter, first turn the list into an array.
  • all four checks gave the expected answer;
  • it is explained why the paragraph with the schedule is “other”, although it is in main;
  • both ways of counting gave 2;
  • it is tested on a link from nav — what the function returned is written down.
7. The “Report card” on the page
Medium13 min

move the display from the console into a table without touching the calculation.

Copy the folder day-23 to day-24/tabel and rebuild it:

  • in index.html there is a table with id="tabel": a header of six columns and five empty rows of six cells;
  • makeRow is replaced with makeCells(report), which returns an array of six texts;
  • the rows are found with querySelectorAll, the cells — with children, the texts are put in by the ready-made function write;
  • the tab title shows the number of students.
// a ready-made function: how it works — tomorrow

  cell.textContent = text;   // day 25

  • the numbers in the table matched day 23 to the digit;
  • makeReport did not change in a single line;
  • it is checked in the console that exactly five rows were found, and it is explained why the header row did not get into them;

Starred tasks

8. The path to an element
Hard10 min

go from an element to the root and write down the way.

Write path(el): it climbs from the element up to body and returns the way as a string.

path(document.querySelector(".absent"));   // "BODY > MAIN > UL > LI"
path(document.querySelector("nav a"));     // "BODY > HEADER > NAV > A"
path(document.body);                       // "BODY"
A while loop with parentElement: at each step the name is added to the beginning of an array (unshift from day 19), and at the end comes join(" > "). Think about when the loop should stop.
  • all three examples give the stated answer;
  • the function is tested on every list item — the way is the same for all;
  • depth(el) is added — the number of steps to body;
  • it is explained what happens if you pass an element from head, and how to fix it.
9. Six catches
Hard10 min

gather everything that behaves unexpectedly today.

Run the fragments one at a time: paste each one into the console separately.

// 1
console.log(document.getElementById("#list"));

// 2
console.log(document.querySelector("absent"));

// 3
console.log(document.querySelectorAll("li").map((li) => li.nodeName));

// 4
console.log(document.getElementById("list").firstChild.nodeName);

// 5
const first = document.querySelector("li");
console.log(first.closest(".student") === first);

// 6
console.log(document.getElementsByTagName("li").forEach);
Only one fragment crashes. Two more silently return null, and the sixth prints what you usually see for a nonexistent property.
  • the predictions are written down before running;
  • for the fragment that crashes, the exact error text is written down;
  • it is explained why the fifth gives true;
  • it is explained where such a name in the fourth came from;
  • all six are rewritten to do what the author apparently wanted.
