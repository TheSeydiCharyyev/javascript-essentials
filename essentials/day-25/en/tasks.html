Day 25. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. The tasks are done on the study page from the lecture (the folder day-25), task 7 — in the folder day-25/tabel. Before each task reload the page (F5) to start from how it was.

Warm-up

1. Three ways to read
Easy6 min

see the difference between textContent, innerText and innerHTML.

Print all three properties to the console, first for the paragraph #info, then for main. For main check with includes which of the three has the word “Test”.

For #info two properties will match, and the third will have a tag. For main all three will differ: look at the hidden paragraph and at the indentation from the file.
  • all six values are printed and written down;
  • it is explained where the <b> in innerHTML came from;
  • it is explained why “Test” is only in two of the three;
  • it is written down which property you will use to show text to the user, and why.
2. Text or markup
Easy7 min

see how one string behaves in two properties.

const p = document.querySelector("footer p");

p.textContent = "<b>Mary</b>, 2026";
console.log(p.children.length, p.innerHTML);

p.innerHTML = "<b>Mary</b>, 2026";
console.log(p.children.length, p.textContent);

Predict the four values, run the code, look at the page after each write.

After the first write innerHTML shows the tags strangely — through &lt; and &gt;. That is how the browser writes angle brackets that must stay letters.
  • the predictions are written down before running;
  • it is explained where the &lt; and &gt; in innerHTML came from;
  • it is written down which of the two ways fits a name that came from a form;
  • the same paragraph is made with the technique “own markup, data as text”: <b> from your own string, “Mary” through textContent.
3. The link’s attributes
Easy7 min

go through all four attribute methods and one reflection.

Take the second link in nav. Compare getAttribute("href") and the href property. Check whether the link has a title, set it, read it, write null into it, read it again and remove it.

After writing null check not only the value but also typeof.
  • both variants of the address are written down, and the difference is explained;
  • after writing null the answer of getAttribute and its type are written down;
  • at the end hasAttribute("title") gives false;
  • in the Elements tab you watched the attribute appear and disappear.

Main tasks

4. Classes
Medium12 min

change the classes of many elements at once without losing other classes.

With one forEach over all li give the class star to those who were in class — through toggle with a condition. Check who has star now. Then with a second forEach toggle the class absent for everyone and check who is “absent” now.

“Was in class” means there is no absent class: !li.classList.contains("absent"). After the second pass, the absent ones should be exactly those who have a star.
  • exactly three students have a star — Aman, Gülnar, Oguljan;
  • after toggling, the same three became absent;
  • Meret got className = "star" — it is written down which classes disappeared;
  • classList.add("star absent") is called — the error text is written down and the call is fixed.
5. Style or class
Medium12 min

compare two ways of styling on one task.

Make the heading purple on a light background with 8-pixel padding: first through style (three properties), then through a class accent that you add to the page’s <style>. Then remove the styling in both variants.

For style you will need color, backgroundColor and padding. Read getAttribute("style") — the background color comes back not in the form you wrote it.
  • both variants give the same look;
  • it is written down in what form the background color came back;
  • it is checked that fontSize = 24 and the typo colour change nothing — and that there is no error either;
  • it is counted how many lines of code are needed to remove the styling in each variant;
  • a conclusion is drawn: when to use a class and when style.
6. Data in the markup
Medium13 min

keep numbers in data- attributes and not trip over strings.

Collect an array of numbers from the data-id of all items and calculate the sum. Then give the items marks from the array through dataset.mark and find with a selector those who have a 5. Calculate the average mark, reading the marks back from dataset.

const marks = [5, 3, 4, 5, 4];   // in the order of the list items
The sum of the numbers should be 15, and the average mark 4.2. If you got "012345", recall the walkthrough from the lecture: where is Number needed?
  • the sum of the numbers is 15, the average mark is 4.2;
  • the selector [data-mark="5"] found two — Aman and Sapar;
  • the new data-mark attributes are visible in the Elements tab;
  • it is explained why after dataset.mark = 5 the value reads as a string;
  • an attribute is added through dataset.lastVisit — it is written down what it is called in the markup.

Starred tasks

8. A safe card
Hard10 min

show other people’s data in your own markup so that it does not become code.

Add an empty <div id="card"></div> to the page and write showStudent(card, student): it writes the card’s markup — a heading and a paragraph — as its own string, and puts the name and the marks into them as text.

showStudent(card, { name: "Aman", marks: [5, 4, 5] });
// <h3>Aman</h3><p class="marks">Marks: 5, 4, 5</p>

showStudent(card, { name: "<img src=x onerror=alert(1)>", marks: [3] });
// the name is seen as letters, no alert window appears
card.innerHTML = '<h3></h3><p class="marks"></p>', then querySelector inside the card and textContent. The marks are glued into a string by join from day 19.
  • both calls give the expected look, alert does not fire;
  • it is checked that there is not a single img inside the card;
  • the name is also saved in dataset.name;
  • for comparison the dangerous string is written through innerHTML — it is written down what happened, and it is explained why.
9. Six catches
Hard10 min

gather everything that is silent or surprising today.

// 1
const h = document.querySelector("#title");
h.style.fontSize = 24;
console.log(h.style.fontSize);

// 2
console.log(document.querySelector("li").dataset.id + 1);

// 3
const secret = document.querySelector("#secret");
secret.setAttribute("hidden", "false");
console.log(secret.hidden);

// 4
const meret = document.querySelector(".absent");
meret.className = "star";
console.log(meret.classList.contains("student"));

// 5
document.querySelector("#list").textContent = "List:";
console.log(document.querySelectorAll("li").length);

// 6
document.querySelector("h1").classList.add("star absent");
Only the last one crashes. The other five work silently — and each does not do what the author most likely expected. The first prints an empty string.
  • the predictions are written down before running;
  • for the sixth the exact error text is written down;
  • for each of the first five it is explained what went wrong;
  • all six are rewritten to do what the author apparently wanted.
