День 26. Создаём и удаляем элементы

Выжимка лекции: создать, вставить, перенести, скопировать, удалить — и собрать кусок дерева.

Главное

Порядок всегда один: создать, наполнить, вставить. Созданный элемент живёт в памяти и на странице не виден, пока его не вставили: isConnected — false. 
const li = document.createElement("li");   // создать
li.textContent = "Назик";                    // наполнить — данные только текстом
li.classList.add("student");
list.append(li);                             // вставить

Куда вставить

list.append(a, "текст")   // внутрь, в конец; узлы и строки, сколько угодно
list.prepend(a)           // внутрь, в начало
title.before(p)           // рядом, перед элементом
title.after(p)            // рядом, после элемента
list.append(...items)     // массив элементов — одним вызовом
append ничего не возвращает: const x = list.append(li) даст undefined. Всё, что не узел, он превращает в текст — даже null и undefined. before и after у элемента без родителя молча ничего не делают.

Перенести, скопировать, удалить, заменить

list.prepend(list.lastElementChild);   // вставка существующего — ПЕРЕНОС
el.cloneNode(true);                     // копия с содержимым; без true — пустая оболочка
el.remove();                            // убрать; объект остаётся в переменной
old.replaceWith(a, b);                  // поставить другое на место
Узел не может стоять в двух местах: вставка забирает его со старого. Нужна копия — cloneNode(true), и сразу смените ей id, иначе на странице окажутся два одинаковых.
for...of по list.children с remove удаляет каждый второй: живая коллекция сжимается на ходу. Удалять всех — querySelectorAll(...).forEach((x) => x.remove()), очистить целиком — list.textContent = "".

Старый набор Node

СтарыйНовый
parent.appendChild(node)parent.append(node)
parent.insertBefore(node, ref)ref.before(node)
parent.removeChild(node)node.remove()
parent.replaceChild(newNode, oldNode)oldNode.replaceWith(newNode)

Старые методы вызываются у родителя, берут один узел, строк не принимают (appendChild("текст") — TypeError) и возвращают узел. insertBefore(node, null) вставляет в конец. У replaceChild сначала новый, потом старый.

Собрать и нарисовать

function toItem(name) {
  const li = document.createElement("li");   // создаём сверху вниз…
  li.textContent = name;
  return li;                                 // …и отдаём, ещё не вставив
}

function renderList(list, names) {
  list.textContent = "";                     // перерисовать = очистить…
  list.append(...names.map(toItem));         // …и вставить заново, разом
}

Детей прикрепляют к родителю снизу вверх, а на страницу готовый кусок попадает один раз. Для данных createElement с textContent безопаснее innerHTML с шаблонной строкой. Перестановка — это вставка в новом порядке: list.append(...[...list.children].reverse()).

Дерево не даёт сделать из себя не дерево: циклов в нём не бывает (день 24). Новые методы от части этих ошибок избавляют — el.remove() сам знает родителя.

  1. Создайте пункт «Назик», проверьте isConnected до и после вставки.
  2. Перенесите первого студента в конец, потом вставьте его копию — сравните число пунктов после каждого шага.
  3. Напишите renderList и вызовите её трижды: с тремя именами, с теми же ещё раз и с пустым массивом.
  4. Переделайте «Табель» так, чтобы строки создавались кодом, и добавьте из консоли шестого студента.
