Day 27. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. The page is yesterday’s, plus a button <button id="hello"> and an empty paragraph <p id="log"> at the end of main. Write the code in app.js: a listener needs a person to click the button. Task 7 is done in the folder day-27/tabel.

Warm-up

1. The first listener
Easy6 min

add a listener and read the event object.

On a click on the button write “Salam!” into #log with the click number, the event name and the value of isTrusted. Then call button.click() in the code and compare what is written after it and after a real click.

// Salam! ×1 (click, false)   — after button.click()
// Salam! ×2 (click, true)    — after a mouse click
The number is a counter variable outside the listener, which the listener increases. A template string from day 16 builds the text in one line.
  • the text changes on every click, the number grows;
  • it is written down how a click from code differs from a real one;
  • the button is pressed with the Tab and Enter keys — it is written down what isTrusted is this time, and why;
  • the function is passed to the listener with the mistake greet() — it is written down what happened.
2. Keys
Easy7 min

see the difference between key and code.

Listen for keydown on document and write both properties into #log. Fill in a table for the keys: a, Shift+a, 1, Enter, Space, Esc, the up arrow — and the same a on another layout, for example French AZERTY.

A space in key is a string of one space; it is not visible on the page. Print the value in quotes or through JSON.stringify from day 23.
  • the table is filled in for all eight presses;
  • pairs where key differs and code is the same are found;
  • it is written down when to use key and when code;
  • the same listener is added to the paragraph #info — it is explained why it is silent.
3. Mouse buttons
Easy7 min

figure out which events different mouse buttons give.

Add four listeners to the button: mousedown, mouseup, click and contextmenu. Each writes its name and event.button to the console. Click with the left, middle and right mouse button.

In the contextmenu listener try event.preventDefault() — what happens to the right-click menu?
  • for each mouse button it is written down which events came and with what number;
  • it is explained why a right click does not cause click;
  • the right-click menu is turned off with preventDefault;
  • clientX and clientY are written down for clicks in different corners of the button.

Main tasks

4. Bubbling with your own eyes
Medium12 min

see the path of an event and control it.

Add click listeners to the first list item, to ul, main, body and document. Each writes its name and event.eventPhase to the console. Click on Aman. Then add one more listener to body with { capture: true }, and put stopPropagation into the ul listener.

One “factory” function from the lecture saves you from five identical arrows: const say = (name) => (event) => console.log(name, event.eventPhase);
  • the order without capturing is written down: li, ul, main, body, document — and the phases 2, 3, 3, 3, 3;
  • after capturing on body it fires first, with phase 1;
  • after stopPropagation in ul it is written down who else got the event;
  • a click on the paragraph #info — it is written down which of the listeners fired, and why.
5. Delegation
Medium13 min

serve all the items — and the future ones too — with one listener.

One listener on #list: a click on an item toggles the class star and writes the name into #log. The #hello button adds to the end of the list an item “New 1”, “New 2” and so on.

For the item — event.target.closest("li"). For the button — a separate listener with createElement and append from day 26.
  • the star toggles on the old items and on the ones added by the button;
  • the code has not a single listener on a separate item;
  • a click on the list past the items causes no error;
  • a <b> is added to Aman’s item — it is checked that a click on the bold text still toggles the star, and it is explained what would happen without closest.
6. Hotkeys
Medium12 min

control the page from the keyboard.

The digits 1–5 toggle the star of the student with that number, Esc removes all the stars. The other keys, including 9, do nothing.

Number(event.key) turns "3" into 3, and "a" into NaN. Any comparison with NaN is false (day 5) — a handy check.
  • after 3 and 5 Gülnar and Oguljan have stars;
  • 9 and a change nothing and cause no errors;
  • Esc removes all the stars;
  • it is written down why key is needed here, not code — and what changes if the digits are typed on the numeric keypad on the right.
7. The “Report card” with buttons
Medium13 min

make the table alive with one listener.

Copy day-26/tabel to day-27/tabel and add:

  • a seventh cell with a “Delete” button in every row;
  • one listener on tbody: the button deletes the row both from the data and from the page, a click on the row toggles the class selected;
  • Esc unselects all the rows;
  • the total and the tab title are recalculated after deleting.
  • after deleting Meret and Sapar the total is “Top students: 1 of 3”;
  • the page has exactly one click listener, and it is on tbody;
  • a sixth student, added from the console to the data and to the page, is also deleted by the button — and the total is correct after that;
  • it is explained why there is a return after deleting;
  • it is written down why the tab title had to be reworded.

Starred tasks

8. Five clicks
Hard10 min

remove a listener from inside and understand which function can be removed.

The button counts clicks and writes “Clicks: N” into #log. After the fifth one it adds “— enough” and removes its listener: the sixth and further clicks change nothing.

Only a named function can be removed: declare function countClick() and inside it call removeEventListener with that same function.
  • after six clicks the page says “Clicks: 5 — enough”;
  • the same is done with an arrow — it is written down why it did not work;
  • a variant is made where the button fires exactly once, with { once: true };
  • it is checked in the console with getEventListeners(button) that the listener is gone.
9. Six catches
Hard10 min

gather everything that behaves unexpectedly today.

const button = document.querySelector("#hello");

button.addEventListener("Click", () => console.log(1));
button.addEventListener("click", console.log("2"));
document.querySelector("#info").addEventListener("keydown", () => console.log(3));
button.addEventListener("click", () => console.log(4));
button.removeEventListener("click", () => console.log(4));
button.onclick = () => console.log("5a");
button.onclick = () => console.log("5b");
document.querySelector("#list").addEventListener("click", (e) => console.log(e.currentTarget.nodeName));

Predict what appears in the console: right on load, after a click on the button, after pressing any key and after a click on Meret.

One line appears even before any click. On the button — two lines. Listeners are called in the order they were added, and onclick joins the queue at the moment it is first given a function.
  • the predictions are written down before running;
  • for each of the eight lines it is explained what it did;
  • it is explained why a click on Meret printed UL, not LI;
  • all the lines are rewritten to do what the author apparently wanted.
