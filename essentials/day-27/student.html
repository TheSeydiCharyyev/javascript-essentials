День 27. События

Выжимка лекции: слушатели, объект события, всплытие, делегирование.

Главное

Событие — сообщение браузера «что-то произошло»: щелчок, клавиша, конец загрузки. Слушатель — функция, которую браузер вызовет, когда событие случится, и передаст ей объект события. 
button.addEventListener("click", (event) => {
  log.textContent = "Салам!";
});
Функцию передают, а не вызывают: greet, а не greet(). Имя события — без on и маленькими буквами: "click", а не "onclick" или "Click". Ошибки в этих случаях нет — щелчок просто ничего не делает.

Объект события

СвойствоЧто это
typeимя события: "click"
targetгде случилось — самый глубокий элемент
currentTargetгде висит сработавший слушатель
clientX, clientYточка щелчка в видимой части окна
buttonкнопка мыши: 0 левая, 1 колесо, 2 правая
keyчто напечатано: "a", "A", "ф", "Enter"
codeкакая клавиша физически: "KeyA"
isTrustedот человека (true) или из кода (false)

Правый щелчок не даёт click — только mousedown, mouseup и contextmenu. Клавиши приходят элементу в фокусе, а без фокуса — body, поэтому клавиши страницы слушают у document.

Всплытие и делегирование

Событие приходит на элемент и поднимается к предкам: li → ul → main → body → document → window. Поэтому хватает одного слушателя на родителе:

list.addEventListener("click", (event) => {
  const li = event.target.closest("li");   // до пункта, даже если щёлкнули по <b> в нём
  if (!li) return;                         // щелчок мимо пунктов
  li.classList.toggle("star");
});
Делегирование обслуживает и элементы, добавленные позже: слушатель висит на родителе. Не всплывают focus и blur — их слушают на самом элементе.

Остановить и отменить

event.stopPropagation();   // дальше к предкам не пойдёт
event.preventDefault();    // браузер не сделает своё: переход по ссылке, меню, отправку формы

Это разные вещи: preventDefault не мешает всплытию, stopPropagation не отменяет действия браузера. Останавливать всплытие приходится редко: оно ломает делегирование выше.

Снять, загрузка, события из кода

button.removeEventListener("click", greet);    // только ТА ЖЕ функция
button.addEventListener("click", greet, { once: true });   // один раз
button.onclick = greet;                        // старый способ: место одно

document.addEventListener("DOMContentLoaded", () => {});   // дерево готово
window.addEventListener("load", () => {});                 // и картинки тоже

button.click();                                // щелчок из кода, isTrusted — false
button.dispatchEvent(new Event("hello", { bubbles: true }));
Анонимную стрелку не снять: написанная заново — это другая функция. Скрипту с defer обёртка DOMContentLoaded не нужна: он и так выполняется при готовом дереве. Слушатель, повешенный после события, не сработает: события не повторяются.

Три тихие ошибки

НаписалиЧто будет
addEventListener("click", greet())greet сработала при загрузке, щелчок — ничего
addEventListener("onclick", …)слушатель не сработает никогда
removeEventListener со стрелкой, написанной зановослушатель остался

У всех трёх одно общее: консоль молчит. Если кнопка «не работает», проверяйте их первыми, а getEventListeners(button) в консоли Chrome покажет, какие слушатели на самом деле висят на элементе.

  1. Повесьте на кнопку счётчик щелчков, который пишет результат на страницу.
  2. Выведите key и code для десяти клавиш, в том числе на русской раскладке, и объясните разницу.
  3. Повесьте слушатели на пункт, список и body и запишите порядок вызовов.
  4. Добавьте в «Табель» кнопку «Удалить» у каждой строки — одним слушателем на tbody.
