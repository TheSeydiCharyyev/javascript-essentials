Day 29. Mini project: a to-do list

A summary of the lecture: how the program is built and how to check that the project is ready.

The five parts of the program

// 1. The data — everything the look of the page depends on
let tasks = [
  { id: 1, text: "Review day 26", done: true },
  // … every task has id, text and done
];
let nextId = 4;
let filter = "all";

// 2. The elements of the page — we find them once
const list = document.querySelector("#tasks");

// 3. Showing: the page is built from the data
function render() {
  list.textContent = "";
  list.append(...tasks.filter(isVisible).map(makeItem));
  // the counter and the buttons — from the data too, over all the tasks
}

// 4. Actions: understand what happened → change the data → render()
// 5. The first showing
render();
The page is a picture of the data. A listener does not fix the list itself: it changes tasks or filter and calls render(). One action changes the list, the counter and the buttons at once — when one function builds everything, the page will not drift apart from the data.

makeItem(task) makes one item out of one object and only returns it. The data goes in through textContent, the class through classList.toggle("done", task.done), and in data-id the item remembers the number of its task.

From an element to the data

function taskOf(element) {
  const id = Number(element.closest("li").dataset.id);   // "2" → 2
  return tasks.find((t) => t.id === id);
}

// in the click listener on the list — delete the clicked task:
const task = taskOf(event.target);
tasks = tasks.filter((t) => t !== task);   // all but it; that is why let
Everything in dataset is strings: without Number the comparison "2" === 2 is false and find returns undefined. The link “item — task” is built only through id: a position in the list changes because of filtering and deleting, an id — never.

Mistakes by their symptoms

SymptomCause
the neighboring task was deletedthe item has a position number instead of id
Cannot set properties of undefineda string against a number in find
the data changed, the page did notrender() was forgotten
Assignment to constant variable.const tasks, while deleting assigns a new array

For any oddity the first question is what is in the data? Ask the console: tasks. If the data is right and the page is not, look for render.

How to extend it

Any improvement fits into the same scheme: a new field or variable in the data (important, query), a line in makeItem or isVisible, a new listener that changes the data and calls render. There is no saving yet: reload the page — the initial tasks are back. We will add it on day 31.

  1. Finish the project from the tasks and go through the whole checklist, row by row.
  2. Make one improvement from tasks 4–8 that you did not manage in the lesson.
  3. Label the five parts of the program in app.js, and above every listener write in one line what it changes in the data.
  4. For day 31: which variables need to be saved so that after reloading the page everything is back as it was? Which one does not have to be saved?
