Day 29. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 build the project from the lecture in the folder day-29/todo — stage by stage, checking each stage in the console. Tasks 4–8 are improvements of the same project: do them in turn, one on top of another, and after each one check that the old features did not break. Task 9 needs a copy of the todo folder from task 3.

5. “Check all”
Medium12 min

add an action over all the tasks at once.

Next to the counter — a “Check all” button. If there is at least one task that is not done, it checks all of them; if all are done, it removes the marks, and then its label is “Uncheck all”. When there are no tasks, the button is not visible.

The click: remember tasks.every((t) => t.done), go with forEach over the data, call render once. The label and the visibility are set by render — the same way as for “Clear done”.
  • the first click gives “Left: 0 of 3” and “Uncheck all”; the second — “Left: 3 of 3”, “Check all”, and “Clear done” is hidden;
  • after deleting all the tasks the button is not visible;
  • it is explained why the label changes in render and not in the click listener;
  • the button is moved inside .filters for a minute — it is written down what happened to filter and to the highlighting of the buttons, and it is explained why.

Medium13 min

add one more condition for showing and combine it with the filters.

Above the list — a field “Search tasks”. On every letter show only the tasks whose text contains what was typed, ignoring case and the spaces at the edges. The search works together with the filters. If not a single task is visible, below the list it says “Nothing found”.

7. Important tasks
Medium13 min

carry a new data field through the whole project.

Every task gets an important field; in the initial data the important one is “Do the tasks of day 28”. The item has a “★” button: a click makes the task important or ordinary. Important tasks are in bold and come first in the list; otherwise the order is the same.

// on load the items go like this: 2, 1, 3
// “★” at task 3 → 2, 3, 1
// “★” at task 2 → 3, 1, 2
tasks.map((t) => t.id);   // [1, 2, 3] — the order in the data is the same
Four places: the data (and the new object in submit), makeItem (the button and the important class through toggle), render (in one append — first the important ones, then the rest) and a listener for clicks on .star. The look: .important span { font-weight: bold; }.
  • the order of the items matches the example at every step;
  • a new task appears ordinary and at the end of the list;
  • after the two clicks from the example the “Active” filter shows the items 3, 2;
  • it is explained why the order on the page changed, while in tasks it did not.

Starred tasks

8. Editing with a double click
Hard10 min

temporarily replace a part of an item with a field and bring the edit back into the data.

A double click on the text of a task replaces it with a field with the same text, the cursor in the field. Enter saves the new text into the data, Esc cancels the edit. An empty text and a text longer than 60 characters are not saved: the field stays.

A double click is the dblclick event, it is listened for the same way as click: on ul, with the check matches("span"). The field takes the place of the text through replaceWith from day 26. The keys are a keydown listener on ul; both after saving and for canceling, render() is enough: it will build the item anew.
  • “Review day 26” is corrected to “Review days 26 and 27” — the new text is in tasks[0].text, the task is still done;
  • Esc returns the old text; an empty text and 61 characters are not saved;
  • a double click on the checkbox does not open an edit — it is written down what happened to the mark;
  • it is explained why the change listener from section 10 does not confuse the edit field with the checkbox;
  • it is explained where an edit in progress goes if a filter is clicked during it.

// in the submit listener

// in render

After two additions ask the console tasks.map((t) => t.id). Marking and deleting are done by taskOf, and find returns the first match.
  • each complaint is reproduced and matched with its line;
  • for the first one the output of tasks.map((t) => t.id) is written down, and it is explained why both marking and deleting break, although there are no mistakes in their listeners;
  • all three lines are fixed, the complaints do not repeat any more;
