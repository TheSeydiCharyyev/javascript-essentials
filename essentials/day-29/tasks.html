День 29. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 собирают проект из лекции в папке day-29/todo — по этапам, с проверкой каждого этапа в консоли. Задания 4–8 — доработки того же проекта: делайте их по очереди, одну поверх другой, и после каждой проверяйте, что старое не сломалось. Для задания 9 нужна копия папки todo из задания 3.

Добавьте isVisible и render из раздела 7. Слушателей пока нет — управляйте программой из консоли: отметьте все дела сделанными, покажите только активные, потом удалите все дела. После каждого изменения данных вызывайте render().

tasks.forEach((t) => {
  t.done = true;
});
render();
counter.textContent;   // "Осталось: 0 из 3"
Удалить все дела — присвоить tasks пустой массив. Поэтому переменная объявлена через let.
  • при всех сделанных записано, видна ли кнопка «Удалить сделанные»;

  • после tasks = [] — «Осталось: 0 из 0» и кнопка спрятана; объяснено, при чём тут every пустого массива;
  • данные изменены без render() — записано, что стало со страницей.

5. «Отметить все»
Средне12 мин

добавить действие сразу над всеми делами.

Рядом со счётчиком — кнопка «Отметить все». Если есть хоть одно несделанное дело, она отмечает все; если сделаны все — снимает отметки, и тогда подпись у неё «Снять отметки». Когда дел нет, кнопки не видно.

Щелчок: запомнить tasks.every((t) => t.done), пройти forEach по данным, один раз вызвать render. Подпись и видимость задаёт render — так же, как у «Удалить сделанные».
  • первый щелчок — «Осталось: 0 из 3» и «Снять отметки»; второй — «Осталось: 3 из 3», «Отметить все», а «Удалить сделанные» спрятана;
  • после удаления всех дел кнопки не видно;
  • объяснено, почему подпись меняется в render, а не в слушателе щелчка;
  • кнопка на минуту перенесена внутрь .filters — записано, что стало с filter и с выделением кнопок, и объяснено почему.
6. Поиск по делам
Средне13 мин

добавить ещё одно условие показа и совместить его с фильтрами.

Над списком — поле «Поиск по делам». На каждую букву показывайте только дела, в тексте которых есть набранное, без учёта регистра и пробелов по краям. Поиск работает вместе с фильтрами. Если не видно ни одного дела, под списком написано «Ничего не нашлось».

// «за»                     → Сделать задания дня 28
// «  ДЕНЬ »                → Повторить день 26

7. Важные дела
Средне13 мин

провести новое поле данных через весь проект.

У каждого дела появляется поле important; в исходных данных важное — «Сделать задания дня 28». В пункте — кнопка «★»: щелчок делает дело важным или обычным. Важные дела выделены жирным и стоят в списке первыми, в остальном порядок прежний.

// при загрузке пункты идут так: 2, 1, 3
// «★» у дела 3 → 2, 3, 1
// «★» у дела 2 → 3, 1, 2
tasks.map((t) => t.id);   // [1, 2, 3] — в данных порядок прежний
Четыре места: данные (и новый объект в submit), makeItem (кнопка и класс important через toggle), render (в один append — сначала важные, потом остальные) и слушатель щелчка по .star. Оформление: .important span { font-weight: bold; }.
  • порядок пунктов совпадает с примером на каждом шаге;
  • новое дело появляется обычным и в конце списка;
  • после двух щелчков из примера фильтр «Активные» показывает пункты 3, 2;
  • объяснено, почему порядок на странице менялся, а в tasks — нет.

Со звёздочкой

8. Правка двойным щелчком
Сложно10 мин

на время подменить часть пункта полем и вернуть правку в данные.

Двойной щелчок по тексту дела заменяет его полем с тем же текстом, курсор в поле. Enter сохраняет новый текст в данные, Esc отменяет правку. Пустой текст и текст длиннее 60 знаков не сохраняются: поле остаётся.

Двойной щелчок — событие dblclick, его слушают так же, как click: на ul, с проверкой matches("span"). Поле встаёт на место текста через replaceWith из дня 26. Клавиши — слушатель keydown на ul; и после сохранения, и для отмены хватит render(): он построит пункт заново.
  • «Повторить день 26» исправлено на «Повторить дни 26 и 27» — новый текст в tasks[0].text, дело по-прежнему сделано;
  • Esc возвращает старый текст; пустой текст и 61 знак не сохраняются;
  • двойной щелчок по флажку правку не открывает — записано, что стало с отметкой;
  • объяснено, почему слушатель change из раздела 10 не путает поле правки с флажком;
  • объяснено, куда девается начатая правка, если во время неё щёлкнуть фильтр.
9. Три жалобы
Сложно10 мин

искать ошибку от симптома, начиная с вопроса «что в данных?».

Одноклассник прислал свой список дел и три жалобы:

  • «Добавил „Купить хлеб“ и „Купить сок“, отметил сок — зачеркнулся хлеб. Удалил сок — пропал хлеб».
  • «В „Сделанных“ пишет „Осталось: 0 из 3“, хотя два дела не сделаны».
  • «Кнопка „Удалить сделанные“ видна, только когда удалять нечего».

От программы лекции его app.js отличается тремя строками в этих фрагментах. Скопируйте папку todo из задания 3 в todo-bugs, внесите фрагменты и воспроизведите каждую жалобу.

// в слушателе submit
tasks.push({ id: nextId, text, done: false });
error.textContent = "";
form.reset();
render();

// в render
const left = tasks.filter(isVisible).filter((t) => !t.done).length;
counter.textContent = `Осталось: ${left} из ${tasks.length}`;
clearDone.hidden = tasks.some((t) => t.done);
После двух добавлений спросите консоль tasks.map((t) => t.id). Отметку и удаление ведёт taskOf, а find возвращает первое подходящее.
  • каждая жалоба воспроизведена и сопоставлена со своей строкой;
  • для первой записан вывод tasks.map((t) => t.id) и объяснено, почему ломаются и отметка, и удаление, хотя в их слушателях ошибок нет;
  • все три строки исправлены, жалобы больше не повторяются;
  • объяснено, почему вторую ошибку не видно при фильтре «Все».
