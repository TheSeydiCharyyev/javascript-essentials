Day 30. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–5 and 9 are done on the stopwatch page from the lecture (the folder day-30/timer): the markup is from section 2, app.js from sections 2 and 6, the helpers wait, later and failLater are already in it. Tasks 6 and 7 are done in the “Report card” from section 15 together with the fix of the form (the folder day-30/tabel), task 8 in a copy of the to-do list of day 29 (the folder day-30/todo).

Warm-up

1. The order of output
Easy6 min

predict when timers fire.

Without running it, write down in what order the letters will appear. Then check in the console.

console.log("A");
setTimeout(() => console.log("B"), 200);
setTimeout(() => console.log("C"), 0);
console.log("D");
setTimeout(() => console.log("E"), 100);
First all the ordinary code runs, then the timers’ functions — by the time of firing, not by the order of the lines.
  • the order is written down before running and checked against the console;
  • it is explained why “C” with a delay of 0 was not printed right after “A”;
  • the line const start = Date.now(); is added at the start, and before the last one — while (Date.now() - start < 300) {}: the new order is written down and it is explained why two letters swapped places.
2. A countdown
Easy7 min

repeat an action and stop in time.

In the message paragraph show 5, 4, 3, 2, 1 — one number per second, and then “Time!”. The interval stops itself.

clearInterval can be called inside the interval’s function: by that moment the number is already in the variable.
  • after 5 seconds the page says “Time!”, after 10 — still “Time!”;
  • after stopping, the counter variable equals 0 and does not change any more;
  • clearInterval is removed for a while — it is explained why this is not visible on the page, and it is proved with the console that the interval is still working.
3. The first chain
Easy7 min

get the result of a promise and handle the error.

From later("  meret  ", 500) get “MERET” in the console with a chain of three then steps: remove the spaces, convert to upper case, print. Add a catch that prints the text of the error, and a finally with “done”. Then replace later with failLater("The server is asleep", 500).

Each step gets the result of the previous one and returns a new one. trim and toUpperCase are from day 16.
  • the promise from later is saved to a variable: its state right away and after half a second is written down, and it is explained why the value in it kept the spaces;
  • with failLater “The server is asleep” and “done” are printed, while the first then did not run — this is proved with a console.log line inside it;
  • “done” is printed in both cases.

Main tasks

4. An accurate stopwatch
Medium12 min

count time by the clock, not by the timer’s ticks.

The stopwatch from section 6 counts the interval’s ticks and so falls behind when the browser is busy. Rewrite it: on “Start” remember Date.now(), the interval only updates the clock, and the time is computed as a difference. “Stop” and a new “Start” continue from the same place, “Reset” sets it to zero.

You need two variables: the moment of the last “Start” and how many milliseconds piled up before the last “Stop”. The clock shows their sum divided by 1000, with toFixed(1). A second “Start” must not start a second interval — section 7.
  • “Start”, 2 seconds, “Stop”, a pause, “Start”, one more second, “Stop” — the clock shows 3.0;
  • during counting the browser is kept busy for a second by the loop from section 8 in the console: 2 seconds after “Start” the old stopwatch showed about 1.1, and the new one about 2.1;
  • pressing “Start” again on the go speeds nothing up;
  • it is explained why the interval is needed at all, if the time is taken from Date.now().
5. Your own function with a promise
Medium13 min

wrap “the data will come later” in a promise — the way a server does it.

Write loadStudent(name): after 500 ms the promise is fulfilled with the student object from the group array, and if there is no such student, it is rejected with the error “No student: name”. Spaces at the edges of the name do not get in the way. Then write averageOf(name): it prints the average mark with two digits or the text of the error, and at the end, in any case, “request finished”.

const group = [
  { name: "Aman", marks: [5, 4, 4] },
  { name: "Meret", marks: [3, 3, 4] },
  { name: "Sapar", marks: [5, 5, 4, 5] },
];

averageOf("Meret");   // in 500 ms: Meret: 3.33, then “request finished”
averageOf("Ilýas");   // in 500 ms: No student: Ilýas, then “request finished”
Inside new Promise — setTimeout, inside the timer — find from day 20 and exactly one of two calls: resolve(student) or reject(new Error(…)). The average — with reduce.
  • both examples give what is stated, and “  Sapar ” gives “Sapar: 4.75”;
  • loadStudent("Meret") is called in the console without then — the state of the promise right away and after 500 ms is written down;
  • reject is replaced with throw for a while — it is written down what the console showed and what state the promise stayed in, and it is explained why;
  • it is explained how loadStudent is similar to a request to a server, which will come on day 31.
6. The “Report card”: a highlight and a message
Medium12 min

tell the timers that have to be canceled from the ones that do not.

A new row added by the form is highlighted with the new class for two seconds, then the highlight is removed. The form’s error message disappears three seconds after the last error, and after a successful addition — at once.

Every new row has its own timer, and there is no need to cancel it. The message has one timer for everyone: its number is in a variable outside the fail function, with clearTimeout before a new one, as in flash from section 5. The look: .new { background: #fef08a; }.
  • Ilýas is added, a second later Aýna: the highlight of Ilýas goes out 2 seconds after he was added, of Aýna — 2 seconds after she was;
  • two errors 2 seconds apart: the second one stays for the full 3 seconds;
  • a successful addition removes the message at once;
  • it is explained why the rows do not need clearTimeout, while the message does.
7. The “Report card”: a “Refresh” button
Medium13 min

repeat loading and not break the data.

Above the form — a “Refresh” button. It loads the data anew, as when the page opens: “Loading…”, and a second later — the initial five students; the ones added by the form disappear, because the “server” does not know about them. While loading is in progress, the button and the form are hidden.

Move the chain from section 15 into a function load() and call it on opening and on a click. Remove the old data only in then, when the new data has already come: reports.splice(0) clears the array, tbody.textContent = "" clears the table.
  • Ilýas is added (“Top students: 3 of 6”), “Refresh” — a second later five rows and “Top students: 2 of 5”;
  • during loading the button and the form are not visible, and the old rows are in place;
  • if loadSaved gives saved.slice(0, 40), after “Refresh” the total shows an error, and the six old rows stayed;
  • it is explained why reports is cleared with splice and not by assigning a new array.

Starred tasks

8. Undo deleting
Hard10 min

give five seconds to change one’s mind.

In the to-do list after “✕”, “Deleted: ‘text’ Undo” appears below the list. For five seconds the task can be returned to its former place, then the message disappears. A new deletion replaces the previous one: only the last one can be undone.

What was deleted is data too: let undo = null or { task, index }, and the message is shown and hidden by render. Remember the position with indexOf before deleting, put it back in place with splice(index, 0, task) from day 19.
  • “✕” at “Do the tasks of day 28”, 2 seconds later “Undo” — the task is second again, with the same id 2;
  • without “Undo”, after 5 seconds there is no message, and the task cannot be returned;
  • two deletions 3 seconds apart: the message is about the second one, and it stays for 5 seconds from the second one;
  • deleting and returning under the “Active” filter work too.
9. Six catches
Hard10 min

gather together everything that behaves unexpectedly today.

Each line does not do what the author apparently wanted. For each one write down a prediction: what will appear in the console, and when.

console.log(1, typeof setTimeout(() => {}, 0));                     // 1
setTimeout(console.log("2"), 100);                                  // 2
const p = later(3, 100);
console.log(p);                                                     // 3
p.then((x) => { x * 10; }).then((y) => console.log(y));             // 4
Promise.reject(new Error("five")).finally(() => console.log("5"));  // 5
new Promise(() => {                                                 // 6
  setTimeout(() => { throw new Error("six"); }, 0);
}).catch(() => console.log("6: caught"));
No line stops the others: an error in one does not get in the way of the next ones. In two lines the error will stay uncaught.
  • the predictions are written down before running;
  • for lines 5 and 6 the exact text of the red messages in the console is written down;
  • for each line it is explained where the result came from;
  • all six are rewritten to do what the author wanted.
