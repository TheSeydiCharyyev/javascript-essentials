Day 31. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. We open everything through Live Server. Tasks 1–5 and 9 are done on the group page from the lecture (the folder day-31/group: index.html, app.js, group.json from section 2). Task 6 is done in the to-do list with saving from section 14 (the folder day-31/todo), tasks 7 and 8 in the “Report card” from section 15 (the folder day-31/tabel, with students.json next to it).

Warm-up

1. The first request
Easy6 min

see a request and a response with your own eyes.

In the console of the group page get the response to fetch("group.json") and study it: the status, ok, the content-type header, the body as a string and as data. Find the same request on the Network tab.

A header is read like this: response.headers.get("content-type"). Reading the body a second time needs a new request — the body is read once.
  • the status, ok and content-type of the response are written down;
  • the exact text of the error on a second json() on the same response is written down;
  • the status and the body of the response are found on the Network tab;
  • the page is opened with a double click — it is written down what the console showed for the same request.
2. Three troubles
Easy7 min

tell a server error, a network failure and broken data apart.

Cause three troubles in turn and for each one write down where it is visible: whether fetch was rejected, what ok and status are, what json() gave, which red line is in the console. The troubles: a typo in the file name; a stopped Live Server; an extra comma after the last student in group.json.

After group.json is saved, Live Server reloads the page by itself — repeat the request in the console anew. Do not forget to put the file back in order.
  • for each trouble a row of the table from section 6 of the lecture is filled in;
  • for the extra comma the text of the SyntaxError is written down, and it is explained which character caused it;
  • it is explained why fetch was not rejected on the typo.
3. Storage in the console
Easy7 min

learn to write, read and look at storage.

Make the visit counter from section 10 on the group page. Save a “student” object through JSON.stringify and read it back. Print all the keys of the storage to the console with a loop over localStorage.length and key(i). Look at all of this on the Application tab → Local Storage.

  • the counter grows with every reload of the page;
  • the object after the round trip “write — read” is the same, the array of marks is in place;
  • sessionStorage is checked in a new tab — it is written down what stayed in which storage;
  • it is explained why the keys in the loop’s output are not necessarily in the order they were written.

Main tasks

4. The group list with averages
Medium12 min

get data from a server and show it on the page.

On the “Load” button show a list: the name and the average mark with two digits, and for whoever has no marks — “no marks”. While loading is in progress — “Loading…” and the button is not visible; on an error — a clear message.

// Aman — 4.33
// Meret — 3.33
// Gülnar — no marks
// Sapar — 4.75
// Oguljan — 4.50
Take the listener from section 8 of the lecture and change only the text of an item. The average is reduce from day 20 divided by the number of marks; check for an empty array before dividing.
  • five items exactly as in the example;
  • with a typo in the address — “Could not load: Server replied 404”, and the button is visible again;
  • with Live Server stopped — “Could not load: Failed to fetch”;
  • it is explained what Gülnar would get without the check for an empty array.
5. A search that waits
Medium13 min

join the delayed timer of day 30, a request and an address with data.

Add a search field. 300 ms after the last letter build the address group.json?name=… with the typed text, show it on the page and send the request. From the response keep those whose name contains what was typed, ignoring case, and write “Found: N”. Live Server does not read the parameter and gives the whole file — a real server would filter by itself, while we filter on the page.

A timer and clearTimeout — as in the autosave of day 30; the timer’s function can be made async. Text goes into an address only through encodeURIComponent.
  • “ar” — Gülnar and Sapar, “Found: 2”, the address group.json?name=ar;
  • “Sapar”, typed without pauses, — exactly one request on the Network tab;
  • “Gülnar & Aman” — %26 in the address, “Found: 0”;
  • it is explained what the server would see if the text were put into the address without encodeURIComponent.
6. The to-do list: the filter and “Start over”
Medium12 min

decide what to keep and where, and remove only your own.

In the to-do list with saving from section 14 remember the filter too: after a reload the selected one stays. Add a “Start over” button: it brings back the three example tasks and selects “All”.

Move the three examples into a constant EXAMPLES and take a copy: EXAMPLES.map((t) => ({ ...t })) — otherwise the marks will change the examples themselves. Your own keys are deleted with removeItem, not with clear().
  • “Active”, the page reloaded — “Active” is highlighted, there are two tasks in the list;
  • after “Start over” — the three example tasks, “All”, nextId equals 4;
  • a key of another project (for example, group:visits from task 3) is in place after “Start over”;
  • it is explained why the filter is kept in localStorage or in sessionStorage — the choice is justified.
7. The “Report card”: a “Reset” button
Medium13 min

get out of broken storage without the console.

Above the form — a “Reset” button. It forgets what was saved and loads the data from the server anew, without reloading the page.

Delete your key, clear reports with splice(0) and the table, show “Loading…” again and call start() from section 15. updateSummary will save it.
  • Ilýas is added, the page reloaded — six rows; “Reset” — five rows and “Top students: 2 of 5”;
  • after “Reset” and a reload of the page there are still five rows;
  • "[object Object]" is written into the storage — the “Report card” shows an error, and “Reset” fixes it;
  • it is explained why after “Reset” the storage has the key tabel:reports again.

Starred tasks

8. A draft of the form
Hard10 min

choose a storage for the job.

The name and the marks typed in the form of the “Report card” survive a reload of the page, but in a new tab the form is empty. After a successful addition the draft is forgotten.

One input event on the whole form catches input in both fields — it bubbles (day 27). The draft is an object of two strings through JSON.stringify.
  • typed “Ilýas” and “5 4”, reloaded — the fields are filled in;
  • the same page in a new tab — the fields are empty;
  • after “Add” and a reload the fields are empty, and there are six rows;
  • it is explained why sessionStorage is used here, and localStorage for the reports.
9. Six catches
Hard10 min

gather together everything that behaves unexpectedly today.

Run one line at a time in the console of the group page. For each one first write down a prediction.

const r = await fetch("grup.json"); console.log(r.ok, r.status);                       // 1
localStorage.setItem("marks", [5, 4]); console.log(localStorage.getItem("marks").length); // 2
async function f() { return 5; } console.log(f() + 1);                                  // 3
console.log(encodeURI("?q=a&b"));                                                       // 4
console.log(JSON.parse(localStorage.getItem("no")));                                    // 5
const data = (await fetch("group.json")).json; console.log(typeof data);                // 6
Not a single line fails with an error — and that is a catch too: a wrong value silently goes on.
  • the predictions are written down before running;
  • for each line it is explained where the answer came from;
  • all six are rewritten to do what the author apparently wanted;
  • it is explained why the lines with await work in the console, but not in app.js.
