Day 32. Mini project: a catalog with data from a server

A summary of the lecture: how an application that waits for a server is built, and how to check that the project is ready.

Where what lives

DataWhereWhen it appears

let books = [];                                                // will come from the server
let favorites = JSON.parse(localStorage.getItem(KEY)) ?? [];   // read first!

async function load() {
  try {
    const response = await fetch("catalog.json");
    if (!response.ok) throw new Error(`server replied ${response.status}`);
    books = await response.json();
    makeGenreButtons();   // once — not in render
    render();             // the first showing — only when there is data
  } catch (err) {
    error.textContent = `Could not load the catalog: ${err.message}`;
  } finally {
    loading.hidden = true;
  }
}
A page that waits for a server is always in one of three states: loading, data or error — and the person must see each of them. “Loading…” is removed in finally, otherwise on an error it will hang next to the message. catch also catches mistakes in our own code: the text on the page is the first thing to read for any oddity.

A filter of several conditions

function isVisible(book) {
  const text = `${book.title} ${book.author}`.toLowerCase();
  if (!text.includes(query)) return false;                              // search
  if (genre !== "all" && book.genre !== genre) return false;           // genre
  if (onlyFavorites && !favorites.includes(book.id)) return false;      // favorites
  return true;                                                          // passed everything
}
Every check only refuses, and true comes in one line at the end. An early return true (“the genre ‘all’ — show it”) turns off all the checks below. The search brings both sides to lower case. The favorites keep the numbers of books, not copies: everything else about a book is always taken fresh from the server.

The genre buttons are built from the data: a genre is added if !names.includes(genre). A new genre on the server gets a button by itself. This has to be called once, after loading: from render the buttons would multiply after every action.
