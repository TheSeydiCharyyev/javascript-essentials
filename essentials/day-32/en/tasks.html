Day 32. Tasks

Lessons 2 and 3, 90 minutes. Warm-up — 20 minutes, main tasks — 50 minutes, starred tasks — 20 minutes. Tasks 1–3 build the catalog from the lecture in the folder day-32/catalog stage by stage, checking each stage in the console. Tasks 4–8 are improvements of the same catalog: do them in turn, and after each one check that the old features did not break. Task 9 needs a copy of the folder after task 3. We open everything through Live Server.

Warm-up

1. The server and the data
Easy6 min

start the project with the data and check it before the first line of code.

Create catalog.json and index.html from sections 3 and 5 of the lecture. While app.js is empty, ask the server from the console. Then put into app.js the data from section 4 and the finding of elements from section 5.

await in the Chrome console works without async — day 31.
  • 8 books were got from the console, 2 of them novels;
  • a request for katalog.json gave the status 404;
  • after the second part [books.length, favorites, genres.children.length, loading.hidden] equals [0, [], 0, false];
  • it is explained why every book has an id, although the titles are different.
2. Loading and cards
Easy7 min

build loading and the showing of one book.

Add load from section 7 and run it as it is, before makeGenreButtons and render. Then add makeCard and makeGenreButtons from sections 8 and 9.

While the functions do not exist, comment out their calls in load — and uncomment them when the function appears.
  • the error text on the page while makeGenreButtons is not written is written down, and it is explained why catch caught it;
  • makeCard(books[4]).outerHTML matches the lecture, and with favorites = [5] the class is "card favorite";
  • there are six genre buttons, none is highlighted yet;
  • makeGenreButtons() is called in the console a second time — it is written down how many buttons there are, and it is explained.
3. render and actions
Easy7 min

finish the catalog and check it against the assignment.

Add isVisible, render and the four listeners from sections 10–11. Go by hand through the scenario from section 15 and the table of edge cases.

If something is wrong, the first question is what is in the data: [query, genre, onlyFavorites, favorites]. The second is what is on the page in #error.
  • all the rows of the scenario give what is in the table;
  • after a reload of the page the favorites are in place, while the search and the genre are reset;
  • with catalog.json renamed — an error message and no “Loading…”;
  • it is explained why the first render is called in load, and not at the end of the file.

Main tasks

4. Protecting storage
Medium12 min

not let broken storage break the page.

First, on the finished catalog, write into storage in turn "[object Object]" and "5" and reload the page — write down what happened. Then replace the reading of the favorites with a function readFavorites(): if storage does not hold an array or it cannot be parsed, it returns an empty array.

JSON.parse goes inside try...catch from day 11. Whether it is an array — Array.isArray from day 19.
  • before the protection: with "5" the page says “Could not load the catalog: favorites.includes is not a function”, with "[object Object]" “Loading…” hangs;
  • after the protection both cases give eight cards, and storage becomes "[]";
  • "[99]" stays in storage after the protection and gets in nobody’s way;
  • it is explained why with "5" the error appeared in #error, and with "[object Object]" it did not.
5. Sorting
Medium12 min

add one more choice and carry it through render.

Below the genres — three buttons: “as in the catalog”, “newest first”, “by title”. The choice is kept in the variable sort and works together with the search, the genre and the favorites.

In render first pick the visible ones, then sort a copy with toSorted (day 20). Strings are compared with < (day 7): (a, b) => (a.title < b.title ? -1 : 1). For our titles this is enough; sorting by all the rules of a language (capital letters, letters like é) is in course 2.
  • “by title” — the first is “Crime and Punishment”, the last is “War and Peace”;
  • “newest first” — the first is “Harry Potter and the Philosopher's Stone”, the last is “The Captain's Daughter”;
  • “newest first” and the genre “fantasy” — “Harry Potter…”, then “The Hobbit”;
  • after sorting the order in books is the same — it is explained what would break with sort instead of toSorted.
6. “Show more”
Medium13 min

show a long list in parts.

The catalog shows four cards at a time. A “Show more” button below the list adds the next four and hides when everything is shown. A new search, genre or checkbox starts with four again.

One more data field — let limit = 4. In render — slice(0, limit) from day 19. The button is hidden by render: it is visible only if there are more visible books than limit.
  • on opening — four cards, “Shown: 4 of 8”, the button is visible;
  • after “Show more” — eight cards, no button;
  • the search “to” — four cards and the button; after a click — five, no button;
  • it is explained why limit is reset in the listeners and not in render.
7. Search and genre for the life of the tab
Medium13 min

choose a storage for the job.

The search and the selected genre survive a reload of the page, but in a new tab the catalog opens clean. The search field shows the saved text.

Read where query and genre are declared, with ??; write at the end of render. Fill the search field before the first showing: search.value = query.
  • “to” and “fantasy”, reloaded — two cards, “to” in the field, “fantasy” is highlighted;
  • the same page in a new tab — the field is empty, “all”, “Shown: 8 of 8”;
  • the favorites still live in localStorage and are visible in both tabs;
  • it is explained why the search is in sessionStorage, and the favorites in localStorage.

9. Three complaints
Hard10 min

look for a mistake starting from the symptom.

A classmate sent their catalog and three complaints:

  • “‘hobbit’ is found, but ‘Hobbit’ is not.”
  • “After every action there are more genre buttons.”
  • “A star cannot be removed.”

Their app.js differs from the program of the lecture in the fragments below; besides, the call of makeGenreButtons was removed from load. Put them into a copy of the catalog and reproduce each complaint.

// in the search listener
query = search.value.trim();

// in render, after the cards
makeGenreButtons();

// in the list listener
if (favorites.includes(id)) {
  favorites.filter((f) => f !== id);
} else {
  favorites.push(id);
}
For each complaint ask the console: query, genres.children.length, favorites. The data will tell which line is to blame.
  • each complaint is reproduced and matched with its line;
  • it is written down how many genre buttons there are after opening and after the first letter of the search;
  • it is explained why filter without an assignment changes nothing;
  • all three places are fixed, the complaints do not repeat any more.
