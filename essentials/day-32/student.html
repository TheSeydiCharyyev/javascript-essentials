Выжимка лекции: как устроено приложение, которое ждёт сервер, и как проверить, что проект готов.

async function load() {
  try {
    const response = await fetch("catalog.json");
    if (!response.ok) throw new Error(`сервер ответил ${response.status}`);
    books = await response.json();
    makeGenreButtons();   // один раз — не в render
    render();             // первый показ — только когда данные есть
  } catch (err) {
    error.textContent = `Не удалось загрузить каталог: ${err.message}`;
  } finally {
    loading.hidden = true;
  }
}
Страница, которая ждёт сервер, всегда в одном из трёх состояний: загрузка, данные или ошибка — и каждое человек должен видеть. «Загрузка…» убирают в finally, иначе при ошибке она повиснет рядом с сообщением. catch ловит и ошибки в нашем коде: текст на странице — первое, что читают при любой странности.

Фильтр из нескольких условий

function isVisible(book) {
  const text = `${book.title} ${book.author}`.toLowerCase();
  if (!text.includes(query)) return false;                              // поиск
  if (genre !== "все" && book.genre !== genre) return false;           // жанр
  if (onlyFavorites && !favorites.includes(book.id)) return false;      // избранное
  return true;                                                          // прошла всё
}
Каждая проверка только отказывает, а true — одной строкой в конце. Ранний return true («жанр „все“ — показываем») отключает все проверки ниже. Поиск приводит к нижнему регистру обе стороны. Избранное хранит номера книг, а не копии: всё остальное о книге всегда берётся свежим с сервера.

Кнопки жанров строятся из данных: жанр добавляется, если !names.includes(genre). Новый жанр на сервере сам получит кнопку. Вызывать это нужно один раз, после загрузки: из render кнопки множились бы после каждого действия.
