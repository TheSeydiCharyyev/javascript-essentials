День 32. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Задания 1–3 собирают каталог из лекции в папке day-32/catalog по этапам, с проверкой каждого этапа в консоли. Задания 4–8 — доработки того же каталога: делайте их по очереди и после каждой проверяйте, что старое не сломалось. Для задания 9 нужна копия папки после задания 3. Всё открываем через Live Server.

Разминка

1. Сервер и данные
Легко6 мин

начать проект с данных и проверить их до первой строки кода.

Создайте catalog.json и index.html из разделов 3 и 5 лекции. Пока app.js пуст, спросите сервер из консоли. Потом положите в app.js данные из раздела 4 и поиск элементов из раздела 5.

await в консоли Chrome работает без async — день 31.
  • из консоли получены 8 книг, из них 2 романа;
  • запрос к katalog.json дал статус 404;
  • после второй части — [books.length, favorites, genres.children.length, loading.hidden] равно [0, [], 0, false];
  • объяснено, почему у каждой книги есть id, хотя названия разные.
2. Загрузка и карточки
Легко7 мин

собрать загрузку и показ одной книги.

Добавьте load из раздела 7 и запустите как есть, до makeGenreButtons и render. Затем добавьте makeCard и makeGenreButtons из разделов 8 и 9.

Пока функций нет, закомментируйте их вызовы в load — и раскомментируйте, когда функция появится.
  • записан текст ошибки на странице, пока makeGenreButtons не написана, и объяснено, почему её поймал catch;
  • makeCard(books[4]).outerHTML совпадает с лекцией, а при favorites = [5] — класс "card favorite";
  • кнопок жанров шесть, выделенной пока нет;
  • makeGenreButtons() вызвана в консоли второй раз — записано, сколько стало кнопок, и объяснено.
3. render и действия
Легко7 мин

завершить каталог и проверить его по заданию.

Добавьте isVisible, render и четыре слушателя из разделов 10–11. Пройдите руками сценарий из раздела 15 и таблицу крайних случаев.

Если что-то не так, первый вопрос — что в данных: [query, genre, onlyFavorites, favorites]. Второй — что на странице в #error.
  • все строки сценария дают то, что в таблице;
  • после обновления страницы избранное на месте, а поиск и жанр сброшены;
  • при переименованном catalog.json — сообщение об ошибке и нет «Загрузка…»;
  • объяснено, почему первый render вызывается в load, а не в конце файла.

Основные задания

4. Защита хранилища
Средне12 мин

не дать испорченному хранилищу сломать страницу.

Сначала на готовом каталоге запишите в хранилище по очереди "[object Object]" и "5" и обновите страницу — запишите, что случилось. Потом замените чтение избранного функцией readFavorites(): если в хранилище не массив или его не разобрать, она возвращает пустой массив.

JSON.parse — внутри try...catch из дня 11. Массив ли это — Array.isArray из дня 19.
  • до защиты: с "5" на странице «Не удалось загрузить каталог: favorites.includes is not a function», с "[object Object]" — «Загрузка…» висит;
  • после защиты оба случая дают восемь карточек, а хранилище становится "[]";
  • "[99]" после защиты остаётся в хранилище и ничему не мешает;
  • объяснено, почему с "5" ошибка появилась в #error, а с "[object Object]" — нет.
5. Сортировка
Средне12 мин

добавить ещё одно поле выбора и провести его через render.

Под жанрами — три кнопки: «как в каталоге», «новые сначала», «по названию». Выбор хранится в переменной sort и работает вместе с поиском, жанром и избранным.

В render сначала отберите видимые, потом отсортируйте копию через toSorted (день 20). Строки сравниваются < (день 7): (a, b) => (a.title < b.title ? -1 : 1). Для наших названий этого хватает; сортировка с учётом всех правил языка (буква «Ё») — в курсе 2.
  • «по названию» — первая «Война и мир», последняя «Хоббит»;
  • «новые сначала» — первый «Гарри Поттер и философский камень», последняя «Капитанская дочка»;
  • «новые сначала» и жанр «фэнтези» — «Гарри Поттер…», затем «Хоббит»;
  • после сортировки порядок в books прежний — объяснено, что сломалось бы с sort вместо toSorted.
6. «Показать ещё»
Средне13 мин

показывать длинный список частями.

Каталог показывает по четыре карточки. Кнопка «Показать ещё» под списком добавляет следующие четыре и прячется, когда показано всё. Новый поиск, жанр или флажок снова начинают с четырёх.

Ещё одно поле данных — let limit = 4. В render — slice(0, limit) из дня 19. Кнопку прячет render: она видна, только если видимых больше, чем limit.
  • при открытии — четыре карточки, «Показано: 4 из 8», кнопка видна;
  • после «Показать ещё» — восемь карточек, кнопки нет;
  • поиск «ин» — четыре карточки и кнопка; после щелчка — пять, кнопки нет;
  • объяснено, почему limit сбрасывается в слушателях, а не в render.
7. Поиск и жанр на время вкладки
Средне13 мин

выбрать хранилище под задачу.

Поиск и выбранный жанр переживают обновление страницы, но в новой вкладке каталог открывается чистым. Поле поиска показывает сохранённый текст.

Читать — там же, где объявлены query и genre, с ??; записывать — в конце render. Поле поиска заполнить до первого показа: search.value = query.
  • «ин» и «фэнтези», обновили — две карточки, в поле «ин», выделена «фэнтези»;
  • та же страница в новой вкладке — поле пустое, «все», «Показано: 8 из 8»;
  • избранное по-прежнему живёт в localStorage и видно в обеих вкладках;
  • объяснено, почему поиск — в sessionStorage, а избранное — в localStorage.

9. Три жалобы
Сложно10 мин

искать ошибку от симптома.

Одноклассник прислал каталог и три жалобы:

  • «„хоббит“ находится, а „Хоббит“ — нет».
  • «После каждого действия кнопок жанров становится больше».
  • «Звезду нельзя снять».

От программы лекции его app.js отличается фрагментами ниже; кроме того, из load убран вызов makeGenreButtons. Внесите их в копию каталога и воспроизведите каждую жалобу.

// в слушателе поиска
query = search.value.trim();

// в render, после карточек
makeGenreButtons();

// в слушателе списка
if (favorites.includes(id)) {
  favorites.filter((f) => f !== id);
} else {
  favorites.push(id);
}
Для каждой жалобы спросите консоль: query, genres.children.length, favorites. Данные подскажут, какая строка виновата.
  • каждая жалоба воспроизведена и сопоставлена со своей строкой;
  • записано, сколько кнопок жанров после открытия и после первой буквы поиска;
  • объяснено, почему filter без присваивания ничего не меняет;
  • все три места исправлены, жалобы больше не повторяются.
