День 33. Итоговый проект: замысел и план

Выжимка лекции: семь шагов от идеи к плану и что должно быть готово к концу дня.

Сначала решения, потом код. Ошибку в замысле исправить стоит одну строку текста, ошибку в готовой программе — часы. Код появляется только на шестом шаге.

Данные проверяют до кода

console.table(data);                                          // глазами
console.assert(data.every((w) => w.id && w.word), "не хватает поля");      // молчит, если всё верно
console.assert(data.every((w, i) => data.findIndex((x) => x.id === w.id) === i), "номера повторяются");

Такие проверки переносят в функцию-сторож checkData и зовут после каждой загрузки: файл данных правят руками, и ошибка может появиться завтра. Повтор номера, пустое поле, тема с заглавной буквы — каждая даст в приложении свой странный симптом.

Каркас и проверки до кода

function deck() {
  return [];   // заглушка — того же типа, что настоящий ответ
}
Заглушка без return отдаёт undefined, и код ниже упадёт с Cannot read properties of undefined. Проверки для функции пишут до неё и подбирают так, чтобы заглушка их проваливала: every на пустом массиве — true, поэтому рядом всегда проверка длины. Проверки складывают в функцию, которая возвращает данные как было, — её можно запускать после каждой правки.

Проверка «ни одного null» сразу после поиска элементов ловит опечатку в селекторе там, где её сделали. Без неё скрипт упадёт на первом слушателе, и «Загрузка…» повиснет без объяснений.

Если замысел не помещается в 180 минут двух дней — режьте объём, а не качество. Приложение из пяти работающих возможностей сильнее, чем из пятнадцати недоделанных.

  1. Доведите свой чек-лист дня 33 до конца — все девять строк.
  2. Перечитайте таблицу возможностей и уберите в «потом» всё, без чего приложение работает.
  3. Добавьте в данные ещё несколько объектов и убедитесь, что сторож checkData молчит.
  4. К дню 34: выпишите первую задачу плана и то, как вы узнаете, что она готова.
