День 33. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Сегодня каждый планирует свой итоговый проект по шагам лекции. Задание 3 — на примере «Карточек» (папка day-33/cards), остальные — в папке вашего проекта (day-33/project), через Live Server. Записи — таблицы и предложения — ведите в файле plan.md рядом с кодом: на дне 36 он понадобится на защите.

Разминка

1. Идея одним предложением
Легко6 мин

выбрать идею, которая помещается в два дня, и сформулировать её.

Возьмите идею из таблицы раздела 2 или придумайте свою. Проверьте её по четырём условиям и запишите замысел одним предложением: кому, что делает, зачем.

Если предложение не влезает в две строки — замысел расплывчат или слишком велик. Если в нём нет ни выбора, ни памяти — слишком мал: добавьте фильтр или избранное.
  • против каждого из четырёх условий записано, чем идея ему отвечает;
  • в предложении видны три части: кому, что, зачем;
  • сосед пересказал ваш замысел своими словами — и не ошибся;
  • решено, откуда данные: с сервера, как в каталоге, или от самого человека, как в списке дел.
2. Таблица возможностей
Легко7 мин

записать обещания так, чтобы их можно было проверить.

Составьте таблицу «№ — возможность — как проверить», как в разделе 4 лекции, и две строки под ней: «потом, если останется время» и «не делает совсем».

Хорошая проверка — действие и видимый результат: «набрали „ма“ — одна карточка». Не забудьте состояния, которые легко упустить: загрузка, ошибка, пусто.
  • от 6 до 10 строк, у каждой проверка, которую выполнит человек, не видевший код;
  • есть строка про ошибку загрузки или пустой результат;
  • в «потом» не меньше двух пунктов, в «не делает» — не меньше одного;
  • каждое слово замысла из задания 1 нашло свою строку.
3. Проверки данных на примере
Легко7 мин

научиться ловить ошибки в данных до кода.

В папке day-33/cards создайте words.json и index.html из лекции и повторите проверки раздела 6. Затем сделайте копию words-bad.json с тремя ошибками: у «window» пустой перевод, у «apple» номер 5, у «water» тема «Еда».

Проверки — те же два console.assert и список тем через includes; меняется только имя массива.
  • на words.json проверки молчат, тем три, слов по темам 3, 3 и 2;
  • на words-bad.json — две красные строки, а тем четыре, с «Еда»;
  • слово без перевода найдено через find;
  • для каждой из трёх ошибок записано, какой симптом она дала бы в готовом приложении.

Основные задания

4. Свои данные
Средне12 мин

подготовить данные проекта и проверить их.

Если данные вашего проекта приходят с сервера — создайте JSON-файл: 6–10 объектов, у каждого id. Если их создаёт человек — запишите в plan.md, как выглядит один объект, и сделайте 3–4 объекта для примера. Проверьте данные из консоли.

const data = await (await fetch("items.json")).json();
console.table(data);
console.assert(data.every((x) => x.id && x.name), "не хватает поля");
console.assert(data.every((x, i) => data.findIndex((y) => y.id === x.id) === i), "номера повторяются");
Поля берите из таблицы возможностей: каждое чем-то пользуется. Категорий — не меньше двух, иначе фильтр нечем проверить.
  • для каждого поля записано, какая возможность им пользуется;
  • проверки полей и номеров молчат;
  • выведен список категорий без повторов и сколько объектов в каждой;
  • нарочно испорчен один объект — проверка его поймала, объект исправлен.
5. Где что живёт
Средне12 мин

превратить решения в переменные программы.

Составьте таблицу «данные — где — почему», как в разделе 8, и напишите начало app.js: все переменные программы с комментарием к каждой и ключ хранилища с приставкой проекта.

Чтение хранилища — сразу при объявлении, с ?? [] или другим значением «пусто». Если для строки таблицы возможностей не нашлось переменной — план не додуман.
  • у каждой строки таблицы «где что живёт» есть причина выбора;
  • каждой возможности из задания 2 соответствует хотя бы одна переменная;
  • в консоли выведены все переменные при первом открытии страницы — значения «пусто»;
  • объяснено, почему именно эти данные в хранилище, а остальные — нет.
6. Макет и рама
Средне13 мин

увидеть страницу до кода и собрать её раму.

Нарисуйте макет узким, как экран телефона, и подпишите каждую часть: из каких данных она строится и что её меняет. По макету напишите index.html без данных и поиск элементов в app.js.

Места, куда придут данные, в разметке пустые: <ul></ul>, <p></p>. «Загрузка…» видна сразу, если данные с сервера.
  • у каждой части макета есть подпись; частей без данных нет;
  • проверка «ни одного null» из раздела 9 даёт false;
  • нарочно сделана опечатка в одном селекторе — проверка это показала, опечатка исправлена;
  • фото или рисунок макета лежит в папке проекта.
7. Каркас и первый шаг
Средне13 мин

получить работающую страницу с первыми данными.

Объявите все функции заглушками и все слушатели — с комментарием-планом внутри. Для одной главной функции (как deck у «Карточек») сначала напишите функцию-проверку, потом саму функцию. В конце — load и render, которые показывают первые данные на странице.

Заглушка возвращает значение того же типа: [], 0, "". Проверки подбирайте так, чтобы заглушка их проваливала, — не только every, но и длину.
  • страница с каркасом открывается без красных строк в консоли;
  • функция-проверка на заглушке даёт хотя бы две красные строки, а на настоящей функции молчит;
  • после обновления страница показывает первые данные;
  • при переименованном файле данных — понятное сообщение об ошибке.

Со звёздочкой

8. План на дни 34–35
Сложно10 мин

разложить работу по дням и уложить её во время.

Запишите план массивом, как в разделе 13: день, задача, минуты, отметка «потом». Посчитайте сумму по каждому дню кодом.

const plan = [
  { day: 34, task: "поиск по названию", minutes: 20 },
  { day: 35, task: "сортировка", minutes: 20, later: true },
];
[34, 35].map((d) => plan.filter((t) => t.day === d).reduce((sum, t) => sum + t.minutes, 0));
  • каждая заглушка каркаса стала задачей плана;
  • сумма по каждому дню не больше 90 минут;
  • у каждой задачи есть проверка — строка таблицы возможностей или своя;
  • объяснено, почему первая задача дня 34 — именно эта.
9. Чужой план
Сложно10 мин

читать чужой замысел так, как его прочтут на защите.

Обменяйтесь с соседом файлами plan.md и проверьте его план по чек-листу конспекта. Запишите три замечания: что непонятно, что нельзя проверить, что не влезет во время. Потом исправьте свой план по замечаниям соседа.

Замечание полезно, когда в нём есть «что» и «почему»: «задачу „сделать дизайн“ не закрыть — неясно, когда она готова». Оценок «хорошо / плохо» не нужно.
  • соседу отдано три замечания, у каждого есть «почему»;
  • по своим замечаниям план исправлен, и видно, что именно поменялось;
  • записано, какое замечание было самым неожиданным;
  • объяснено, почему проверять чужой план проще, чем свой.
