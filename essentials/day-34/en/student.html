Day 34. Final project: implementation

A summary of the lecture: working by the plan, the current item in a circle, the empty state, plan and actual.

One task at a time

Take a task of the plan → replace the stub with code → check it by hand and in the console → mark it in the plan with the real minutes → the next one. Then the error is always in the last piece. Before a big edit — a copy of the project folder. Stuck — read the red line to the end, ask the data, run the check functions; if it did not help in 10 minutes — go back to the copy and go in smaller steps.

The current item in a circle

function current() {
  const cards = deck();
  return cards.length === 0 ? null : cards[position % cards.length];   // null — empty
}

againButton.addEventListener("click", () => {
  position++;          // it just grows — % keeps it within the deck
  flipped = false;     // a new card — as a word
  render();
});
The current card is not kept but computed from the deck and the position: a copy would be out of date after the first “I know”. The remainder goes around in a circle — after the last card the first one again, and the deck can become shorter without errors. Without % — undefined and Cannot read properties of undefined (reading 'word').

Data that depends on other data is reset together with it: the card changed — flipped = false; the topic changed — also position = 0. Otherwise the next card will open with the translation at once.

The empty state and the reset

knowButton.hidden = current() === null;   // in render: do not offer the impossible
if (current() === null) return;           // in a listener: guard anyway
if (!confirm("Forget all the learned words?")) return;
learned = [];                             // reset the data, not the storage
undefined — “there is no such place”, most often a mistake. null — “we said it ourselves: there is nothing”, it is expected and checked. Storage is a copy of the data: removing the key is useless, render will at once write the old learned back.

Mistakes by their symptoms

SymptomCause
reading 'word' of undefined after the last cardno %: the number went outside the deck
the next card shows the translation at onceflipped is not reset when the card changes
reading 'id' of nullthe button is visible and not guarded on an empty deck
“Start over” reset nothingthe storage key was removed, not the data

A new idea in the middle of the work is not done but written down into “later” with minutes. An overrun of time is not a reason to hurry, but a reason to recount the next day and throw out the task with the mark later.
