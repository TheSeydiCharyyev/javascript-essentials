День 34. Задания

Уроки 2 и 3, 90 минут. Разминка — 20 минут, основные — 50 минут, со звёздочкой — 20 минут. Разминка — на примере «Карточек»: скопируйте папку day-33/cards в day-34/cards и доведите её по лекции. Основные задания — в вашем проекте (day-33/project), по вашему плану. После каждой задачи — проверка и отметка минут в plan.md. Всё открываем через Live Server.

Разминка

1. Текущая карточка и переворот
Легко6 мин

сделать первую задачу плана по шагам лекции.

Добавьте функцию current из раздела 3, новый render и слушатель переворота из раздела 4.

Слушатель только меняет flipped; что показать — слово или перевод, — решает render.
  • щелчок по карточке — «книга», ещё щелчок — «book»;
  • при learned из всех восьми номеров current() — null;
  • слушатель на время переписан как flipped = true — записано, что сломалось;
  • в плане отмечена задача и настоящие минуты.
2. «Знаю» и «Повторить»
Легко7 мин

пройти колоду по кругу и не потерять ни одного слова.

Добавьте оба слушателя из разделов 5–6 и функцию-проверку testCurrent.

Остаток от деления живёт в current, а не в слушателе: «Повторить» просто прибавляет единицу.
  • testCurrent() и testDeck() молчат;
  • восемь раз «Повторить» — снова «book», в position — 8;
  • семь раз «Повторить», потом «Знаю» на «window» — снова «book»;
  • после десятка щелчков вперемешку проверка повторов в learned даёт 0.
3. Темы, сохранение, пустая колода
Легко7 мин

довести пример до конца и пройти таблицу возможностей.

Добавьте кнопки тем, запись в хранилище, пустую колоду и «Начать сначала» из разделов 9–11. Пройдите сценарий раздела 15 целиком.

  • все строки сценария раздела 15 совпали;
  • тема «дом», два раза «Знаю» — «Все слова темы выучены!», кнопок нет;
  • «Начать сначала» с Отменой ничего не меняет, с OK — «Выучено: 0 из 8»;
  • программа сверена с разделом 14 — различий нет.

Основные задания

4. Первая задача своего плана
Средне12 мин

начать реализацию с той задачи, на которую опираются остальные.

Возьмите в своём проекте первую задачу дня 34. Если несколько слушателей говорят об одном и том же — выделенном элементе, текущем вопросе, выбранной категории, — сначала вынесите это в функцию, как current.

Функция, которая только отвечает и ничего не меняет, легко проверяется в консоли. «Ничего нет» пусть она возвращает как null, а не падает.
  • задача проверена так, как записано в плане, — руками и в консоли;
  • новая функция проверена в консоли хотя бы на двух значениях, одно из них — «пусто»;
  • до правки сделана копия папки проекта;
  • в плане отмечены задача и настоящие минуты.
5. Следующие задачи и сторож
Средне13 мин

двигаться по плану и не ломать сделанное.

Выполните следующие задачи плана по одной. Для главной функции своего проекта заведите функцию-проверку в духе testCurrent — она меняет данные на время и возвращает их.

Хорошая проверка проваливается на заглушке и молчит на настоящем коде. Запускайте её после каждой задачи — даже той, что её «не касается».
  • у каждой закрытой задачи в плане есть отметка и минуты;
  • функция-проверка молчит, а после её вызова данные прежние;
  • хотя бы один раз проверка поймала поломку, которую вы не заметили глазами, — или записано, почему таких не было;
  • в слушателях, которые меняют «текущее», сброшены зависимые переменные.
6. Пустое состояние
Средне12 мин

сделать так, чтобы «ничего нет» выглядело как задумано.

Найдите в своём проекте все места, где что-то может оказаться пустым: пустой список, ничего не найдено, всё сделано. Для каждого — понятный текст, спрятанные бесполезные кнопки и защита в слушателях.

Правило раздела 12: кнопку прячут, а слушатель всё равно защищают первой строкой if (… === null) return;.
  • выписаны все пустые состояния проекта, для каждого — как до него дойти;
  • в каждом — понятный текст вместо пустоты;
  • вызов слушателя из консоли (кнопка.click()) в пустом состоянии не даёт красных строк;
  • строки о пустых состояниях добавлены в таблицу возможностей.
7. Сохранение и проверка по таблице
Средне13 мин

убедиться, что обещанное работает целиком.

Если в проекте есть что помнить — запись в конце render, чтение при объявлении. Затем пройдите свою таблицу возможностей строка за строкой, как на защите, и отметьте каждую: работает, работает с оговоркой, не сделано.

Сбрасывают данные, а не хранилище: render сам перепишет ключ — разбор раздела 13.
  • после обновления страницы сохранённое на месте;
  • сброс — если он есть — стирает данные, и после обновления они не возвращаются;
  • у каждой строки таблицы есть отметка, у «с оговоркой» — сама оговорка;
  • всё «не сделано» перенесено в план дня 35 или в «потом».

Со звёздочкой

8. Три жалобы на «Карточки»
Сложно10 мин

искать ошибку по симптому.

Одноклассник собрал «Карточки» и прислал три жалобы:

  • «После восьмого „Повторить“ карточка застревает, а в консоли красное».
  • «Нажал „Знаю“ на перевёрнутой карточке — следующая сразу показала перевод».
  • «„Начать сначала“ ничего не сбрасывает, даже после обновления».

От программы раздела 14 его код отличается тремя местами:

// в current
return cards.length === 0 ? null : cards[position];

// в слушателе «Знаю» — нет одной строки
learned.push(current().id);
render();

// в слушателе «Начать сначала»
localStorage.removeItem(KEY);
Для каждой жалобы спросите данные: position, flipped, learned и хранилище.
  • каждая жалоба воспроизведена в копии «Карточек» и сопоставлена со своим местом;
  • для первой записан точный текст ошибки из консоли;
  • для третьей записано, что лежит в learned и в хранилище после «Начать сначала»;
  • все три места исправлены, жалобы не повторяются.
9. План и факт
Сложно10 мин

сравнить прикидку с делом и спокойно пересчитать завтра.

Допишите к задачам своего дня 34 настоящие минуты массивом actual, как в разделе 16, и посчитайте перерасход кодом. Пересчитайте день 35: если не помещается — решите, что переезжает в «потом». Новые идеи, пришедшие сегодня, — в «потом», с минутами.

  • для каждой задачи — план и факт, сумма посчитана кодом;
  • для задачи с самым большим перерасходом записано, куда ушло время;
  • день 35 без задач «потом» помещается в 90 минут;
  • объяснено, почему выбросить решили именно эту задачу.
