Day 35. Final project: polishing and testing

A summary of the lecture: a phone, edge cases, data at the entrance, someone else’s code.

A phone

From a phone in the same Wi-Fi network you open the address of the computer from ipconfig (the IPv4 line) instead of 127.0.0.1: http://192.168.1.23:5500/index.html. It does not open — use the phone mode of DevTools, Ctrl + Shift + M.

<meta name="viewport" content="width=device-width, initial-scale=1.0">
<style>
  button { font-size: 18px; padding: 10px 16px; margin: 0 8px 8px 0; }
  .card { … overflow-wrap: anywhere; }
</style>
Without the viewport line a phone builds the page 980 wide and shrinks it: innerWidth is 980 instead of 360. You check the worst: a narrow screen, a finger (a button 21 pixels high means a miss), the longest word.

Shuffling

for (let i = result.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1));   // from 0 to i, not to the end of the array
  const temp = result[i];
  result[i] = result[j];
  result[j] = temp;
}

sort(() => Math.random() - 0.5) shuffles unevenly: in Chrome two orders of three numbers out of six come out twice as often. After shuffling, a check must guard the rule (“the first card is the first in the deck”), not the order.

A remark: where · what I did · what I saw · what I expected; a guess goes at the end. First errors, then readability. Every remark on your own code gets an answer: do it, explain or postpone. Before answering — repeat it yourself.
