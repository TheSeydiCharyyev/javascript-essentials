1. Краткая история JavaScript

1. A brief history of JavaScript

JavaScript — один из самых популярных языков программирования в мире. Но он появился не сразу и не просто так. Понимание истории поможет вам увидеть, почему язык устроен именно так, а не иначе.

JavaScript is one of the most popular programming languages in the world. But it didn't appear out of nowhere. Understanding its history helps you see why the language is designed the way it is.

1995 — Рождение языка
1995 — The birth of the language

Компания Netscape выпускала самый популярный на тот момент браузер — Netscape Navigator. Им был нужен «лёгкий» язык, чтобы веб-страницы могли хоть как-то «оживать»: проверять формы, показывать всплывающие окна. Руководство поручило создать такой язык программисту Брендану Айку (Brendan Eich) — и дало ему всего 10 дней. За эти 10 дней родился прототип языка под названием Mocha, который вскоре переименовали в LiveScript, а затем, на волне популярности Java, — в JavaScript.

Netscape made the most popular browser at the time — Netscape Navigator. They needed a "light" language so that web pages could come alive: validate forms, show popups. Management assigned programmer Brendan Eich to create such a language — and gave him just 10 days. In those 10 days a prototype was born called Mocha, later renamed to LiveScript, and then — riding on Java's fame — to JavaScript.

1996 — JavaScript против JScript
1996 — JavaScript vs JScript

Microsoft выпустила свою копию языка под названием JScript для браузера Internet Explorer. Началась «война браузеров»: в каждом браузере свой JS, код, написанный для одного, ломался в другом.

Microsoft released its own clone called JScript for Internet Explorer. The "browser wars" began: each browser had its own JS, and code written for one broke in another.

1997 — Стандарт ECMAScript
1997 — The ECMAScript standard

Чтобы прекратить хаос, язык передали международной организации Ecma International, которая выпустила первый стандарт — ECMAScript 1 (ES1). С этого момента JavaScript — это конкретная реализация спецификации ECMAScript. Запомните эту разницу: мы о ней ещё поговорим в разделе 3.

To end the chaos, the language was handed to the international body Ecma International, which released the first standard — ECMAScript 1 (ES1). From this point on, JavaScript is a specific implementation of the ECMAScript specification. Remember this distinction — we'll return to it in section 3.

2005 — AJAX и возрождение
2005 — AJAX and rebirth

Появилась технология AJAX — возможность загружать данные с сервера без перезагрузки страницы. Именно благодаря ей стали возможны такие сервисы, как Google Maps и Gmail. Это вернуло интерес к JavaScript, и он начал стремительно развиваться.

AJAX appeared — the ability to load data from a server without reloading the page. Thanks to it, services like Google Maps and Gmail became possible. This revived interest in JavaScript and the language started evolving rapidly.

2009 — Node.js: JS вне браузера
2009 — Node.js: JS outside the browser

Райан Даль (Ryan Dahl) создал Node.js — среду исполнения JavaScript, работающую прямо в операционной системе, без браузера. С этого момента на JS стало можно писать серверы, CLI-утилиты, скрипты автоматизации. Это был переломный момент: JS перестал быть «только языком для кнопок».

Ryan Dahl created Node.js — a JavaScript runtime that works directly on the operating system, without a browser. From this moment on, you could write servers, CLI tools, and automation scripts in JS. It was a turning point: JS stopped being "just a language for buttons".

2015 — ES6 (ES2015): большой скачок
2015 — ES6 (ES2015): the big leap

Вышла версия ECMAScript 6 — самое крупное обновление в истории языка. Появились let/const, стрелочные функции, классы, модули, деструктуризация, промисы. После ES6 новые версии стандарта выходят каждый год (ES2016, ES2017, … ES2025).

ECMAScript 6 was released — the largest update in the language's history. It introduced let/const, arrow functions, classes, modules, destructuring, promises. After ES6, new versions of the standard are released every year (ES2016, ES2017, … ES2025).

Сегодня
Today

JavaScript — язык №1 на GitHub по количеству репозиториев, обязательный навык для любого веб-разработчика. На нём написаны фронтенды всех крупных сайтов, серверы Netflix, PayPal, LinkedIn, мобильные приложения Facebook и Instagram (через React Native), даже некоторые десктопные программы — VS Code, Slack, Discord (через Electron).

JavaScript is the #1 language on GitHub by repository count and a must-have skill for any web developer. Frontends of all major sites, servers at Netflix, PayPal, LinkedIn, mobile apps of Facebook and Instagram (via React Native), and even desktop apps — VS Code, Slack, Discord (via Electron) — are written in JS.

Название JavaScript — чисто маркетинговое решение. Netscape договорилась с компанией Sun (создателем Java) назвать язык похожим именем, чтобы «прокатиться» на волне популярности Java. На самом деле JavaScript и Java — это совершенно разные языки, у них почти ничего общего. Как говорят разработчики: «Java относится к JavaScript так же, как автомобиль (car) к ковру (carpet)».

The name JavaScript is purely a marketing move. Netscape made a deal with Sun (creator of Java) to give the language a similar name, riding on Java's popularity. In reality, JavaScript and Java are completely different languages with almost nothing in common. As developers say: "Java is to JavaScript what a car is to a carpet."

2. Кто такой Брендан Айк

2. Who is Brendan Eich

Brendan Eich
Создатель JavaScript
Creator of JavaScript

Американский программист, родился в 1961 году. В 1995-м, работая в Netscape, за 10 дней создал прототип языка JavaScript. Позднее стал CTO компании Mozilla, участвовал в создании браузера Firefox. В 2016 году основал компанию Brave Software, которая делает браузер Brave, ориентированный на приватность. Сегодня продолжает активно участвовать в развитии веб-технологий.

An American programmer born in 1961. In 1995, while working at Netscape, he created the JavaScript prototype in 10 days. Later he became CTO of Mozilla and co-founded Firefox. In 2016 he founded Brave Software, making the privacy-focused Brave browser. He remains active in shaping web technologies today.

Представьте: вам дают 10 дней, чтобы спроектировать язык, который потом будут использовать миллиарды людей 30 лет подряд. Именно поэтому в JS есть странности и «причуды» — Брендан делал то, что успевал. Многие из них мы увидим позже (например, typeof null === 'object'). Но именно эти «причуды» — часть истории языка.

Imagine: you have 10 days to design a language that billions of people will use for 30 years. That's why JS has quirks — Eich did what he could in the time given. We'll see many of them later (e.g., typeof null === 'object'). But those quirks are part of the language's story.

3. Что такое JavaScript

3. What is JavaScript

JavaScript — это высокоуровневый, мультипарадигменный, динамически-типизированный, интерпретируемый язык программирования, являющийся реализацией спецификации ECMAScript. Изначально создан для добавления интерактивности веб-страницам, но сегодня используется везде — от серверов до космических аппаратов.

JavaScript is a high-level, multi-paradigm, dynamically-typed, interpreted programming language, which is an implementation of the ECMAScript specification. Originally created to add interactivity to web pages, today it's used everywhere — from servers to spacecraft.

Это определение звучит сложно, но его легко разобрать на части. Разберём каждый термин.

This definition sounds complex, but it's easy to break down. Let's go through each term.

3.1. Высокоуровневый язык (high-level)

3.1. High-level language

«Высокоуровневый» означает, что язык далёк от «железа» компьютера. Вам не нужно думать о регистрах процессора, управлении памятью, указателях. Все эти детали скрыты от вас — вы просто пишете let x = 5, а движок сам решает, где и как хранить число в памяти. Противоположность — «низкоуровневые» языки вроде C или Ассемблер, где вы работаете с памятью вручную.

"High-level" means the language is far from the computer's hardware. You don't need to think about CPU registers, memory management, or pointers. All those details are hidden — you just write let x = 5, and the engine decides where and how to store the number in memory. The opposite is "low-level" languages like C or Assembly, where you manage memory by hand.

3.2. Мультипарадигменный язык

3.2. Multi-paradigm language

Парадигма программирования — это стиль или подход к написанию программ. JavaScript называют мультипарадигменным, потому что он поддерживает сразу несколько стилей, и программист сам выбирает, как писать код. Три основных стиля:

A programming paradigm is a style or approach to writing programs. JavaScript is called multi-paradigm because it supports several styles at once, and the programmer chooses how to write code. Three main styles:

На одном и том же языке одну и ту же задачу можно решить по-разному. Например, посчитать сумму массива чисел:

The same task can be solved in different ways in the same language. For example, summing an array of numbers:

// Императивный стиль
let sum = 0;
for (let i = 0; i < nums.length; i++) {
    sum += nums[i];
}

// Функциональный стиль
const sum = nums.reduce((a, b) => a + b, 0);

На практике профессиональные разработчики смешивают парадигмы. Например, в React компоненты часто пишутся в функциональном стиле, но состояние внутри обновляется императивно. Умение выбирать подходящий стиль под задачу — признак зрелого программиста.

In practice, professional developers mix paradigms. For example, React components are often written functionally, but state inside is updated imperatively. Picking the right style for the task is the mark of a mature programmer.

3.3. Динамически-типизированный (dynamically-typed)

3.3. Dynamically-typed

Тип — это то, какие данные хранит переменная: число, строка, объект и т. д. В статически-типизированных языках (Java, C++, TypeScript) тип переменной указывается заранее и не может меняться. В динамически-типизированных (JavaScript, Python, Ruby) — тип определяется автоматически во время выполнения и может меняться «на лету»:

A type is the kind of data a variable stores: a number, a string, an object, etc. In statically-typed languages (Java, C++, TypeScript), the type is declared in advance and cannot change. In dynamically-typed languages (JavaScript, Python, Ruby), the type is determined automatically at runtime and can change on the fly:

let x = 42;              // тип: number
x = "hello";             // стал string — JS не ругается
x = [1, 2, 3];           // теперь array — тоже OK
x = { name: "Seydi" };   // теперь object — OK

Динамическая типизация = свобода и риск. С одной стороны, писать код быстрее. С другой — легко случайно смешать типы и получить баг. Например: "5" + 3 даёт "53" (строка), а "5" - 3 даёт 2 (число). Именно поэтому придумали TypeScript — «надстройку» над JS со статическими типами. Но это тема отдельного занятия.

Dynamic typing = freedom and risk. On one hand, you write code faster. On the other, it's easy to accidentally mix types and get a bug. For example: "5" + 3 gives "53" (string), but "5" - 3 gives 2 (number). That's exactly why TypeScript was invented — a "superset" over JS with static types. But that's a topic for another lesson.

3.4. Интерпретируемый (interpreted)

3.4. Interpreted

Существует два больших способа исполнять код:

There are two broad ways to execute code:

Компилируемые языки (C, Rust, Go)
Compiled languages (C, Rust, Go)

Сначала компилятор переводит весь код в машинные инструкции и создаёт исполняемый файл (.exe). Потом этот файл запускается. Медленная сборка, но быстрый запуск.

First a compiler translates the whole code into machine instructions and creates an executable file (.exe). Then this file runs. Slow build, fast execution.

Интерпретируемые (JS, Python, Ruby)
Interpreted (JS, Python, Ruby)

Программа (интерпретатор) читает код построчно и сразу его выполняет. Ничего заранее компилировать не надо. Быстрый старт, удобно для веба.

A program (the interpreter) reads code line by line and executes it on the fly. No pre-compilation needed. Quick to start, convenient for the web.

На практике современные движки JavaScript (например, V8 в Chrome) используют JIT-компиляцию (Just-In-Time) — они на лету превращают куски JS в машинный код для скорости. То есть формально JS интерпретируемый, но фактически работает почти так же быстро, как компилируемые языки.

In practice modern JavaScript engines (like V8 in Chrome) use JIT compilation (Just-In-Time) — they convert chunks of JS into machine code on the fly for speed. So formally JS is interpreted, but in practice it runs nearly as fast as compiled languages.

3.5. JavaScript и ECMAScript — в чём разница?

3.5. JavaScript and ECMAScript — what's the difference?

Это, пожалуй, самое важное, что нужно понять из этого раздела.

This is perhaps the most important takeaway from this section.

  • ECMAScript (ES) — это спецификация, то есть формальный документ, который описывает, как должен вести себя язык: какие есть ключевые слова, как работает if, как устроены числа и т. д. Это «закон».
  • JavaScript — это реализация этой спецификации, то есть реальный язык, которым мы пользуемся. Это «исполнение закона».
  • ECMAScript (ES) is a specification, a formal document describing how the language should behave: what keywords exist, how if works, how numbers are represented, etc. It's the "law".
  • JavaScript is an implementation of that specification — the actual language we use. It's the "enforcement of the law".

Аналогия: ECMAScript — как правила футбола (написанные в книжке ФИФА). JavaScript — это реальный футбольный матч, который играют команды по этим правилам. Правила — одни, а матчей с этими правилами может быть много. Разные движки (V8 в Chrome, SpiderMonkey в Firefox, JavaScriptCore в Safari) — это разные «команды», которые играют по одним и тем же правилам ECMAScript.

Analogy: ECMAScript is like the rules of football (written in the FIFA book). JavaScript is an actual football match played by teams according to those rules. The rules are the same, but many matches can be played. Different engines (V8 in Chrome, SpiderMonkey in Firefox, JavaScriptCore in Safari) are different "teams" playing by the same ECMAScript rules.

Когда вы слышите «ES6», «ES2020», «ES2024» — это версии спецификации. Каждая новая версия добавляет новые возможности в язык. Мы в этом курсе будем использовать современный JavaScript — код, соответствующий ES2015 (ES6) и выше.

When you hear "ES6", "ES2020", "ES2024" — those are versions of the specification. Each new version adds new features. In this course we'll use modern JavaScript — code compliant with ES2015 (ES6) and above.

3.6. Однопоточный (single-threaded)

3.6. Single-threaded

JavaScript выполняет код по одной операции за раз. Нет параллельного исполнения из коробки, как в Java. Зато есть цикл событий (event loop) и асинхронность, которые позволяют не блокировать программу при долгих операциях (например, запросах к серверу). Об этом — в разделе 5 и подробно в занятии 24 («Промисы»).

JavaScript executes code one operation at a time. There's no built-in parallel execution like in Java. Instead, there's the event loop and asynchronous programming, which let the program avoid blocking during long operations (like server requests). More in section 5 and in detail in Lesson 24 ("Promises").

5. Как JavaScript работает в браузере

5. How JavaScript works in the browser

В каждом современном браузере встроен движок JavaScript — специальная программа, которая читает ваш JS-код и выполняет его. У каждого браузера — свой движок:

Every modern browser has a built-in JavaScript engine — a special program that reads your JS code and executes it. Each browser has its own engine:

  • V8 — Chrome, Edge, Opera, а также Node.js (самый известный, разработан Google)
  • SpiderMonkey — Firefox (первый JS-движок в истории, создан Бренданом Айком)
  • JavaScriptCore (Nitro) — Safari, все браузеры на iOS
  • V8 — Chrome, Edge, Opera, and Node.js (the most famous, developed by Google)
  • SpiderMonkey — Firefox (the first JS engine ever, created by Brendan Eich)
  • JavaScriptCore (Nitro) — Safari and all iOS browsers

Что делает движок, когда вы открываете страницу

What the engine does when you open a page

Что JS умеет делать в браузере

What JS can do in the browser

  • Изменять содержимое HTML-страницы (через DOM)
  • Менять стили CSS
  • Реагировать на клики, ввод текста, скролл, наведение
  • Загружать данные с сервера без перезагрузки (AJAX / fetch)
  • Хранить данные прямо в браузере (localStorage, cookies)
  • Показывать уведомления, работать с камерой и микрофоном (с разрешения пользователя)
  • Modify the HTML page contents (via the DOM)
  • Change CSS styles
  • React to clicks, typing, scrolling, hovering
  • Load data from the server without reload (AJAX / fetch)
  • Store data right in the browser (localStorage, cookies)
  • Show notifications, access camera and microphone (with user's permission)

  • Читать/записывать произвольные файлы на вашем диске
  • Запускать программы на компьютере

  • Run programs on your computer
  • Freely talk to other websites (CORS restriction)

6. Три способа подключения JavaScript к HTML

6. Three ways to link JavaScript to HTML

Чтобы браузер выполнил ваш JS-код, его нужно «подключить» к HTML-странице. Есть три способа.

For the browser to execute your JS code, it needs to be "linked" to an HTML page. There are three ways.

Способ 1: Inline (внутри атрибута тега)

Method 1: Inline (inside a tag attribute)

<button onclick="alert('Привет!')">Нажми меня</button>

Код пишется прямо в атрибут onclick, onmouseover и т. п. Так делать не надо — это смешивает HTML и JS, делает код трудно поддерживаемым. Упоминаем только, чтобы вы знали, что так бывает.

Code is written directly into an onclick, onmouseover, etc. attribute. Don't do this — it mixes HTML and JS and makes code hard to maintain. We mention it only so you know it exists.

Способ 2: Internal (тег <script> внутри HTML)

Method 2: Internal (<script> tag inside HTML)

<!DOCTYPE html>
<html>
<head>
    <title>Моя страница</title>
</head>
<body>
    <h1>Привет, мир!</h1>
    <script>
        console.log('Скрипт работает!');
    </script>
</body>
</html>

Код пишется прямо в <script>...</script>. Подходит для маленьких страничек или когда скрипт нужен только на этой странице.

Code is written directly inside <script>...</script>. Good for small pages or when the script is only used on this page.

Способ 3: External (отдельный .js-файл) — рекомендуемый

Method 3: External (separate .js file) — recommended

<!-- index.html -->
<body>
    <h1>Привет, мир!</h1>
    <script src="app.js"></script>
</body>

// app.js
console.log('Скрипт из отдельного файла!');

JavaScript выносится в отдельный файл с расширением .js, а в HTML подключается через <script src="...">. Это правильный способ для любого серьёзного проекта: HTML занимается структурой, CSS — стилями, JS — логикой.

JavaScript goes into a separate file with the .js extension and is linked via <script src="...">. This is the right way for any serious project: HTML for structure, CSS for styles, JS for logic.

Где размещать <script> и зачем нужны defer и async

Where to place <script> and why defer and async exist

Браузер читает HTML сверху вниз. Если тег <script> встретится в <head>, он остановит парсинг страницы, пока скрипт не скачается и не выполнится. Страница будет «зависать». Чтобы этого избежать, есть три варианта:

The browser reads HTML top to bottom. If <script> is encountered in <head>, the browser pauses parsing until the script is downloaded and executed. The page will "freeze". To avoid that, you have three options:

ВариантЧто делаетКогда использовать
OptionWhat it doesWhen to use
<script src="app.js"> в конце <body>HTML успевает прогрузиться до выполнения скриптаПростые страницы
<script defer src="app.js"> в <head>Скрипт скачивается параллельно, выполняется после парсинга HTML, в порядке появленияРекомендуемый вариант
<script async src="app.js"> в <head>Скачивается параллельно, выполняется сразу после скачивания (в любом порядке)Независимые скрипты (аналитика)
<script src="app.js"> at the end of <body>HTML finishes loading before the script runsSimple pages
<script defer src="app.js"> in <head>Downloads in parallel, runs after HTML is parsed, in orderRecommended
<script async src="app.js"> in <head>Downloads in parallel, runs as soon as ready (any order)Independent scripts (analytics)
