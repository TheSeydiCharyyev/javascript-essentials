1. Инструкции и выражения

1. Statements and expressions

Программа на JavaScript — это последовательность инструкций (statements), которые движок выполняет по очереди, сверху вниз. Каждая инструкция — это «шаг» программы: создать переменную, вызвать функцию, сделать проверку.

A JavaScript program is a sequence of statements, which the engine executes in order, top to bottom. Each statement is a "step" of the program: create a variable, call a function, make a check.

let name = "Seydi";      // инструкция 1 — создать переменную
console.log(name);       // инструкция 2 — вывести её
let age = 25;            // инструкция 3 — ещё переменная
console.log(age + 5);    // инструкция 4 — вывести age + 5

Инструкция vs выражение

Statement vs expression

  • Выражение (expression) — это что-то, что производит значение. Например: 2 + 2, "hello", Math.random().
  • Инструкция (statement) — это действие, которое что-то делает. Обычно заканчивается точкой с запятой. Например: let x = 5;, console.log("hi");.
  • Expression — something that produces a value. E.g., 2 + 2, "hello", Math.random().
  • Statement — an action that does something. Usually ends with a semicolon. E.g., let x = 5;, console.log("hi");.

Аналогия: выражение — это слово или словосочетание («три», «два плюс два», «синий цвет»). Инструкция — это целое предложение с точкой («Иди домой.»). Из выражений строятся инструкции. Из инструкций — вся программа.

Analogy: an expression is a word or phrase ("three", "two plus two", "the color blue"). A statement is a full sentence with a period ("Go home."). Statements are built from expressions. Programs are built from statements.

Точка с запятой и ASI

Semicolons and ASI

Каждая инструкция должна заканчиваться точкой с запятой ;. Но у JS есть ASI (Automatic Semicolon Insertion) — если вы забыли, движок попытается поставить сам. Это не всегда работает правильно.

Each statement should end with a semicolon ;. JS has ASI (Automatic Semicolon Insertion) — if you forget, the engine tries to insert one. But it doesn't always work right.

С точкой с запятой (надёжно)
With semicolons (safe)
let x = 5;
let y = 10;
console.log(x + y);
Без (рискованно)
Without (risky)
let x = 5
let y = 10
console.log(x + y)

Включённый Prettier (из прошлого занятия) расставит точки с запятой сам при каждом сохранении. Поэтому просто пишите код и сохраняйте — всё будет чисто.

With Prettier enabled (from the last lesson), semicolons are added automatically on every save. Just write code and save — it stays clean.

2. Комментарии

2. Comments

Комментарий — это текст, который движок JS игнорирует. Он не влияет на работу программы, но помогает людям понимать, что делает код. В JS есть три вида комментариев:

A comment is text that the JS engine ignores. It doesn't affect the program, but helps people understand the code. JS has three kinds of comments:

Однострочный

Single-line

// Это однострочный комментарий
let price = 100; // можно писать в конце строки тоже

Многострочный

Multi-line

/*
    Это комментарий из нескольких строк.
    Полезен для длинных объяснений,
    или чтобы временно «выключить» кусок кода.
*/
let x = 10;

JSDoc (документация функций)

JSDoc (function documentation)

/**
 * Складывает два числа и возвращает результат.
 * @param {number} a — первое число
 * @param {number} b — второе число
 * @returns {number} — сумма
 */
function sum(a, b) {
    return a + b;
}

JSDoc-комментарии VS Code «понимает» и показывает подсказку при наведении на функцию. Очень полезная привычка для командной работы.

VS Code "understands" JSDoc comments and shows a hint when hovering over a function. A very useful habit for teamwork.

Когда писать комментарии

When to write comments

  • ✅ Когда код делает что-то неочевидное («почему именно так?»)
  • ✅ Когда есть особый случай или обход бага
  • ✅ Для TODO-заметок: // TODO: добавить валидацию email
  • ❌ НЕ пишите очевидного: let x = 5; // присваиваем 5 переменной x — это мусор
  • ❌ НЕ комментируйте устаревший код — удаляйте его, Git сохранит историю
  • ✅ When the code does something non-obvious ("why like this?")
  • ✅ Special cases or bug workarounds
  • ✅ TODO notes: // TODO: add email validation
  • ❌ DON'T state the obvious: let x = 5; // assign 5 to x — noise
  • ❌ DON'T comment out old code — delete it, Git keeps history

Комментарии — это не замена хорошим названиям переменных. Плохо: let d = 5; // количество дней. Хорошо: let days = 5; (вообще без комментария).

Comments are not a substitute for good variable names. Bad: let d = 5; // number of days. Good: let days = 5; (no comment at all).

Горячая клавиша комментирования

Comment shortcut

Ctrl+/ — VS Code закомментирует/раскомментирует текущую строку или выделение. Очень полезно для быстрого «выключения» кода при отладке.

Ctrl+/ — VS Code toggles the comment for the current line or selection. Very handy for temporarily "disabling" code during debugging.

3. Правила синтаксиса

3. Syntax rules

Регистр символов важен (case-sensitive)

Case sensitivity

JavaScript различает большие и маленькие буквы. name, Name и NAME — это три разные переменные.

JavaScript distinguishes upper and lower case. name, Name, and NAME are three different variables.

let age = 25;
console.log(Age);  // ❌ ReferenceError: Age is not defined

Пробелы и отступы

Whitespace and indentation

Для движка JS пробелы и отступы не важны — он одинаково понимает все три варианта ниже:

For the JS engine, whitespace and indentation don't matter — all three below are equivalent:

let x=5;let y=10;console.log(x+y);

let x = 5;
let y = 10;
console.log(x + y);

let x  =  5 ;
let y  =  10 ;
console.log ( x + y ) ;

Но для человека, который будет читать код (в том числе для вас через месяц), аккуратное форматирование с отступами — это жизненно важно. Стандарт: 2 пробела отступа, пробелы вокруг =, после запятых.

But for a human reading the code (including you a month from now), neat formatting with indentation is vital. Standard: 2-space indent, spaces around =, after commas.

Строки в кавычках — три варианта

Strings in quotes — three variants

let a = "двойные кавычки";
let b = 'одинарные кавычки';
let c = `обратные кавычки (шаблонные строки)`;

Первые два варианта работают одинаково. Третий — шаблонная строка — позволяет вставлять выражения через ${ }. Мы её подробно разберём в занятии 10, а пока знаем, что такая есть.

The first two are equivalent. The third — a template literal — lets you embed expressions via ${ }. We'll cover it in detail in Lesson 10; for now just know it exists.

Консистентность важнее выбора. Выберите один стиль кавычек и используйте везде. Prettier сам приведёт всё к одному виду — по умолчанию к двойным.

Consistency beats the choice itself. Pick one quote style and use it everywhere. Prettier will unify them — defaults to double.

4. Идентификаторы и ключевые слова

4. Identifiers and keywords

Идентификатор — это имя, которое вы даёте переменной, функции, классу. Например, age, calculateTotal, User.

An identifier is a name you give to a variable, function, or class. E.g., age, calculateTotal, User.

Правила именования

Naming rules

ПравилоПример
RuleExample
Можно буквы (a-z, A-Z), цифры, _, $age, _name, $total, user2
Нельзя начинать с цифры❌ 2user, ✅ user2
Нельзя использовать пробелы и дефисы❌ my name, ❌ my-name, ✅ myName
Нельзя использовать ключевые слова❌ let let = 5;
Можно любые буквы Unicodeимя, возраст (но лучше английские)
Allowed: letters (a-z, A-Z), digits, _, $age, _name, $total, user2
Not allowed to start with a digit❌ 2user, ✅ user2
Not allowed: spaces, hyphens❌ my name, ❌ my-name, ✅ myName
Not allowed: reserved keywords❌ let let = 5;
Unicode letters allowedимя, возраст (but English is preferred)

Соглашения по стилю (не правила языка, а общепринятые)

Style conventions (not language rules, but widely used)

  • camelCase — переменные и функции: userName, calculateTotal
  • PascalCase — классы и «конструкторы»: User, HttpClient
  • UPPER_SNAKE_CASE — константы-настройки: MAX_USERS, API_URL
  • Имена должны быть говорящими: userAge, а не ua или x
  • camelCase — variables and functions: userName, calculateTotal
  • PascalCase — classes and "constructors": User, HttpClient
  • UPPER_SNAKE_CASE — config constants: MAX_USERS, API_URL
  • Names should be descriptive: userAge, not ua or x

Ключевые (зарезервированные) слова

Reserved keywords

Эти слова имеют особое значение в языке — их нельзя использовать как имена переменных:

These words have special meaning in the language — you cannot use them as variable names:

break case catch class const continue debugger default delete do else export extends false finally for function if import in instanceof let new null return super switch this throw true try typeof var void while with yield await async

Не пугайтесь — заучивать список наизусть не нужно. VS Code сразу подчеркнёт ошибку красным, если вы случайно попытаетесь использовать ключевое слово. Со временем список запомнится сам.

Don't panic — you don't need to memorize this list. VS Code will instantly underline an error in red if you accidentally use a keyword. Over time the list becomes second nature.

5. Console во всей красе

5. Console in depth

В занятии 1 мы использовали только console.log(). На самом деле у объекта console есть более 20 методов. Разберём самые полезные.

In Lesson 1 we only used console.log(). Actually, console has over 20 methods. Let's cover the most useful.

Основные методы

Main methods

console.log("обычное сообщение");      // белое
console.info("информационное");        // синяя иконка
console.warn("⚠️ предупреждение");      // жёлтый фон
console.error("❌ ошибка!");            // красный фон
console.debug("для отладки");          // мелкое

Все пять выводят текст в консоль, но разного цвета. Это удобно, когда в консоли много вывода — ошибки сразу бросаются в глаза.

All five print to the console, but in different colors. Useful when the console is busy — errors stand out.

console.table — красивая таблица

console.table — a nice table

const users = [
    { name: "Anna", age: 25, city: "London" },
    { name: "Bob", age: 30, city: "Paris" },
    { name: "Charlie", age: 22, city: "Berlin" }
];

console.table(users);

Вывод — аккуратная таблица в консоли. Незаменимо, когда смотришь массивы объектов (результаты API, пользователей).

Output — a neat table in the console. Invaluable when inspecting arrays of objects (API results, users).

console.group — группировка сообщений

console.group — grouping messages

console.group("Пользователь Anna");
    console.log("Возраст: 25");
    console.log("Город: London");
    console.log("Email: anna@mail.com");
console.groupEnd();

console.group("Пользователь Bob");
    console.log("Возраст: 30");
    console.log("Город: Paris");
console.groupEnd();

В консоли появятся две сворачиваемые группы. Удобно для отчётов с большим количеством логов.

The console shows two collapsible groups. Handy for reports with lots of logs.

console.time — измерение времени

console.time — measuring time

console.time("Мой таймер");

// ... какой-то код, например цикл:
let sum = 0;
for (let i = 0; i < 1000000; i++) sum += i;

console.timeEnd("Мой таймер");  // Мой таймер: 4.2 ms

Позволяет узнать, сколько миллисекунд занял кусок кода. Имя таймера ("Мой таймер") должно совпадать в time и timeEnd.

Shows how many milliseconds a block of code took. The timer name ("My timer") must match in time and timeEnd.

Форматирование с подстановками

Formatting with placeholders

let name = "Seydi";
let age = 25;

// Обычный способ — через запятую
console.log("Имя:", name, "Возраст:", age);

// С подстановками
console.log("Имя: %s, Возраст: %d", name, age);
// %s — строка, %d — число, %o — объект

// Стилизация через %c (только в браузере)
console.log("%c🎉 Победа!", "color: green; font-size: 20px; font-weight: bold");

Откройте консоль (F12) и выполните каждый из примеров выше. Посмотрите, как разные методы выглядят в вашем браузере.

Open the console (F12) and run each example above. See how different methods look in your browser.

6. Как читать ошибки в консоли

6. Reading console errors

Ошибки в консоли — это не враг, а ваш главный помощник. Они точно говорят, где и почему всё сломалось. Научиться читать ошибки — важнейший навык программиста.

Console errors are not your enemy but your main helper. They tell you exactly where and why things broke. Learning to read them is a core dev skill.

Анатомия ошибки

Anatomy of an error

В консоли ошибка выглядит примерно так:

In the console, an error looks roughly like this:

ReferenceError: userName is not defined at greet (app.js:5:15) at app.js:9:1
  • ReferenceError — тип ошибки
  • userName is not defined — описание («переменная userName не определена»)
  • app.js:5:15 — стек вызовов: файл app.js, строка 5, символ 15
  • ReferenceError — error type
  • userName is not defined — description
  • app.js:5:15 — call stack: file app.js, line 5, column 15

Кликните по синей ссылке app.js:5:15 в консоли — браузер откроет файл и поставит курсор прямо на проблемное место. Магия.

Click the blue app.js:5:15 link in the console — the browser opens the file and positions the cursor right at the problem. Magic.

Три главных типа ошибок

Three main error types

ТипЧто значитПример
TypeMeaningExample
SyntaxError Сломан синтаксис — движок не может прочитать код. Скрипт не запустится вообще. let x = ; или if (x { ... }
ReferenceError Вы обратились к переменной, которой не существует. Часто — опечатка в имени. console.log(userNmae);
TypeError Вы делаете с данными что-то, для чего они не годятся (например, вызываете число как функцию). let x = 5; x();
SyntaxError Syntax is broken — the engine can't read the code. The script won't run at all. let x = ; or if (x { ... }
ReferenceError You referenced a variable that doesn't exist. Often a typo in the name. console.log(userNmae);
TypeError You do something to data that doesn't fit it (e.g., call a number as a function). let x = 5; x();

Примеры и как чинить

Examples and fixes

SyntaxError: «Забыл закрыть скобку»

SyntaxError: "Forgot to close a brace"

// ❌ Сломано
if (age > 18 {
    console.log("Взрослый");
}
// SyntaxError: Unexpected token '{'

// ✅ Починили — закрыли круглую скобку
if (age > 18) {
    console.log("Взрослый");
}

ReferenceError: «Опечатка»

ReferenceError: "Typo"

let userName = "Seydi";
console.log(userNmae);   // ❌ опечатка
// ReferenceError: userNmae is not defined

// ✅ Починили
console.log(userName);

TypeError: «Неправильный тип»

TypeError: "Wrong type"

let num = 42;
num.toUpperCase();       // ❌ у числа нет метода toUpperCase
// TypeError: num.toUpperCase is not a function

// ✅ Починили — превратили в строку
String(num).toUpperCase();

Опытные разработчики первым делом смотрят в консоль браузера, когда что-то не работает. Красная строка в DevTools — это не катастрофа, это подсказка, которая обычно на 80% решает задачу.

Experienced developers first look at the browser console when something breaks. A red line in DevTools isn't a disaster — it's a hint that usually solves 80% of the problem.

7. Диалоговые окна: alert, prompt, confirm

7. Dialog boxes: alert, prompt, confirm

Пока мы не изучили DOM (это занятие 16), у нас есть только три встроенных функции для общения с пользователем. Они работают только в браузере (не в Node.js).

Until we learn the DOM (Lesson 16), we only have three built-in functions for talking to the user. They work only in the browser (not Node.js).

alert — показать сообщение

alert — show a message

alert("Привет! Это моё первое сообщение.");

Выведет модальное окно с текстом и кнопкой OK. Пока пользователь не нажмёт OK — скрипт приостановлен.

Shows a modal with text and an OK button. Until the user clicks OK, the script is paused.

prompt — запросить ввод

prompt — ask for input

let name = prompt("Как тебя зовут?");
console.log("Привет, " + name + "!");

// С дефолтным значением
let age = prompt("Сколько тебе лет?", "18");

Возвращает:

Returns:

  • Строку, если пользователь ввёл текст и нажал OK
  • null, если нажал «Отмена» или Esc
  • A string if the user entered text and clicked OK
  • null if they clicked Cancel or Esc

prompt всегда возвращает строку! Даже если пользователь ввёл число. Чтобы получить число, оборачивайте: Number(prompt("Возраст:")).

prompt always returns a string! Even if the user typed a number. Wrap it to get a number: Number(prompt("Age:")).

confirm — задать вопрос «да/нет»

confirm — ask a yes/no question

let answer = confirm("Ты готов учить JavaScript?");

if (answer) {
    console.log("Отлично, продолжаем!");
} else {
    console.log("Жаль. Возвращайся, когда будешь готов.");
}

Возвращает true (OK) или false (Отмена).

Returns true (OK) or false (Cancel).

Диалоги — простые, но неудобные: блокируют страницу, выглядят некрасиво, нельзя стилизовать. В реальных проектах их почти не используют — делают свои формы на HTML/CSS. Но для учёбы (пока мы не изучили DOM) — идеально.

Dialogs are simple but clunky: they block the page, look ugly, can't be styled. Real projects rarely use them — custom HTML/CSS forms are used instead. But for learning (until we cover the DOM) — they're perfect.

8. Mini-project "Interactive Greeter"

Let's combine everything we learned into a small program that introduces itself to the user, asks a few questions, and reacts to the answers.

Create folder greeter/ with index.html and app.js.

index.html:

index.html:

app.js:

// ====== Приветствие ======
alert("Привет! Сейчас мы познакомимся 👋");

// Спрашиваем имя
const name = prompt("Как тебя зовут?");

// Если пользователь нажал «Отмена» — выходим
if (name === null || name.trim() === "") {
    alert("Жаль, без имени не познакомиться. Пока!");
} else {
    // Спрашиваем возраст и сразу превращаем в число
    const age = Number(prompt("Сколько тебе лет, " + name + "?"));

    // Считаем, сколько лет до 100
    const yearsTo100 = 100 - age;

    // Выводим в консоль красиво через group
    console.group("👤 Профиль пользователя");
    console.log("Имя:", name);
    console.log("Возраст:", age);
    console.log("Лет до 100:", yearsTo100);
    console.groupEnd();

    // Спрашиваем, нравится ли JS
    const likesJS = confirm("Тебе нравится JavaScript?");

    if (likesJS) {
        alert("Отлично, " + name + "! Продолжай учиться 🎉");
        console.log("%c" + name + " любит JS!", "color: green; font-size: 16px");
    } else {
        alert("Ничего, " + name + ". Через пару занятий полюбишь 😉");
        console.warn(name + " пока не любит JS. Дадим шанс!");
    }
}
