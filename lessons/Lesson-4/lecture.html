1. Что такое переменная

1. What is a variable

Переменная — это именованное хранилище данных. Можно представить её как подписанную коробку в памяти компьютера: у коробки есть имя (по которому мы её находим) и содержимое (значение, которое мы туда положили).

A variable is a named storage for data. Think of it as a labeled box in the computer's memory: the box has a name (so we can find it) and contents (the value we put inside).

Представьте полку в кладовке. Вы берёте коробку, подписываете её «age» и кладёте туда число 20. Когда вам понадобится узнать возраст — вы не помните само число, вы просто говорите «откройте коробку age», и вам её содержимое выдают. Если возраст изменится, вы заменяете содержимое — имя на коробке остаётся прежним.

Imagine a shelf in a pantry. You take a box, label it "age", and put the number 20 inside. When you need to know the age, you don't remember the number itself — you just say "open the age box" and someone hands you its contents. If the age changes, you swap the contents — the label on the box stays the same.

let age = 20;          // создали коробку "age" и положили 20
console.log(age);      // 20 — достали содержимое

age = 21;              // заменили содержимое
console.log(age);      // 21

В этом простом примере мы:

In this simple example we:

  • Объявили переменную ключевым словом let
  • Дали ей имя age
  • Присвоили значение 20 через знак =
  • Завершили инструкцию точкой с запятой ;
  • Declared a variable with the keyword let
  • Gave it the name age
  • Assigned the value 20 via the = sign
  • Ended the statement with a semicolon ;

Знак = в программировании — это не «равно», а «присвоить». age = 21 читается как «положи в коробку age значение 21», а не «age равно 21». Для сравнения используются другие операторы: == и === (об этом — на занятии 5).

The = sign in programming is not "equals", it's "assign". age = 21 reads as "put the value 21 into the box age", not "age equals 21". Comparison uses different operators: == and === (we'll cover them in Lesson 5).

2. var, let, const — три способа объявления

2. var, let, const — three ways to declare

В JavaScript есть три ключевых слова для создания переменной. Каждое появилось в свою эпоху и ведёт себя по-разному.

JavaScript has three keywords for creating variables. Each appeared in its own era and behaves differently.

2.1. let — переменная, значение которой может меняться

2.1. let — a variable whose value can change

let score = 0;
score = 10;            // OK, меняем значение
score = score + 5;     // OK, score стал 15
console.log(score);    // 15

let используется, когда мы заранее знаем, что значение будет меняться — счётчик кликов, текущий шаг анкеты, выбранный пункт меню.

Use let when you know the value will change — a click counter, the current step in a wizard, a selected menu item.

2.2. const — константа, значение которой нельзя переприсвоить

2.2. const — a constant whose value cannot be reassigned

const PI = 3.14159;
const userName = "Seydi";

PI = 3.14;            // ❌ TypeError: Assignment to constant variable

const используется, когда значение не должно меняться: математические константы, URL API, конфигурация. По умолчанию выбирайте const, и переключайтесь на let только если действительно нужно переприсваивать.

Use const when the value shouldn't change: mathematical constants, an API URL, configuration. Default to const, and switch to let only when you really need to reassign.

Правило хорошего тона: начинайте писать переменную с const. Если позже окажется, что её значение нужно менять — переключите на let. Это уменьшает количество багов: чем меньше переменных «свободно меняются», тем легче читать код.

Style rule: start with const. If later you find you need to reassign, switch to let. This reduces bugs — the fewer variables that "freely change", the easier the code is to read.

2.3. var — наследие из 1995

2.3. var — a legacy from 1995

var name = "Анна";
var name = "Боб";        // ⚠️ можно переобъявить — это запутывает
console.log(name);       // Боб

var существовал ещё до ES6 и обладает странностями: его можно переобъявить, он «всплывает» (hoisting) и имеет видимость на уровне функции, а не блока. Из-за этого в нём легко допустить ошибку. В современном коде его не используют.

var existed before ES6 and has quirks: it can be re-declared, it "hoists", and its scope is the function, not the block. These make bugs easier. In modern code we don't use it.

2.4. Область видимости (scope) — let/const vs var

2.4. Scope — let/const vs var

// let живёт только внутри блока { }
if (true) {
    let x = 1;
    var y = 2;
}
console.log(y);   // 2 — var "вытекает" из блока
console.log(x);   // ❌ ReferenceError: x is not defined

Это одна из главных причин избегать var: переменная, объявленная внутри if, цикла или любого блока, видна и снаружи. Это создаёт неочевидные баги, особенно в больших проектах.

This is one of the main reasons to avoid var: a variable declared inside if, a loop, or any block leaks out. It creates non-obvious bugs, especially in large projects.

Так писали раньше
How it was written before
var counter = 0;
var userName = "Seydi";
var MAX_USERS = 100;
Так пишут сейчас
How it's written now
let counter = 0;
const userName = "Seydi";
const MAX_USERS = 100;

3. Правила именования переменных

3. Naming rules

Имя переменной — это контракт с будущим вами. Через месяц вы откроете код и должны сразу понять, что в этой переменной хранится. Правила делятся на обязательные (диктует язык) и стилистические (диктует команда).

A variable name is a contract with your future self. A month later you'll open the code and should immediately understand what's in this variable. Rules split into required (the language enforces them) and stylistic (the team agrees on them).

3.1. Обязательные правила (иначе SyntaxError)

3.1. Required rules (otherwise SyntaxError)

  • Может содержать буквы, цифры, _, $
  • Не может начинаться с цифры: 2name — ошибка, name2 — OK
  • Регистр имеет значение: age, Age, AGE — три разные переменные
  • Нельзя использовать зарезервированные слова: let, const, if, function, return и т. д.
  • Нельзя пробелы и дефис: user-name — ошибка, user name — ошибка
  • May contain letters, digits, _, $
  • Cannot start with a digit: 2name — error, name2 — OK
  • Case matters: age, Age, AGE are three different variables
  • Cannot use reserved words: let, const, if, function, return, etc.
  • No spaces or hyphens: user-name — error, user name — error

Every value in JavaScript has a type — a category that defines which operations are allowed on it. There are 8 types in total, split into two big groups.

4.1. Примитивы vs ссылочные типы

4.1. Primitives vs reference types

Примитивы хранятся напрямую в переменной как простое значение. Когда вы копируете примитив, копируется само значение:

Primitives are stored directly in the variable as a simple value. Copying a primitive copies the value itself:

let a = 5;
let b = a;     // скопировали значение
b = 10;
console.log(a); // 5 — a не изменилось

А объекты хранятся по ссылке. Сама переменная держит «адрес» объекта в памяти. Копируя объект через =, вы копируете адрес — обе переменные смотрят на один объект:

Objects, on the other hand, are stored by reference. The variable holds an "address" to the object in memory. Copying with = copies the address — both variables now point to the same object:

let user1 = { name: "Анна" };
let user2 = user1;          // скопировали ссылку, не объект
user2.name = "Боб";
console.log(user1.name);    // "Боб" — оба указывают на один объект

Эту разницу полезно запомнить уже сейчас, хотя глубже мы её разберём на занятии 14 («Объекты — основы»). Пока главное: примитив = копия, объект = ссылка.

It's worth remembering this distinction now, even though we'll cover it deeper in Lesson 14 ("Objects — basics"). For now, the key idea: primitive = copy, object = reference.

5. Number — числа

5. Number

В JavaScript нет отдельного типа для целых и дробных чисел — есть один тип number, который покрывает оба случая. Это 64-битные числа с плавающей точкой по стандарту IEEE 754 (как double в C++).

JavaScript has no separate type for integers and floats — there's a single number type covering both. These are 64-bit floating-point numbers per the IEEE 754 standard (like double in C++).

const age = 20;             // целое
const price = 19.99;        // дробное
const negative = -7;        // отрицательное
const big = 1e6;            // 1 000 000 в научной нотации
const hex = 0xff;           // 255 в шестнадцатеричной

5.1. Особые значения: Infinity, -Infinity, NaN

5.1. Special values: Infinity, -Infinity, NaN

console.log(1 / 0);          // Infinity (бесконечность)
console.log(-1 / 0);         // -Infinity
console.log("text" * 2);     // NaN — «Not a Number»
console.log(0 / 0);          // NaN

NaN (Not a Number) — это специальное значение типа number, которое возвращается, когда математическая операция не имеет осмысленного числового результата. Парадокс: typeof NaN равно "number".

NaN (Not a Number) is a special number value returned when a math operation has no meaningful numeric result. Paradoxically, typeof NaN is "number".

NaN не равен ничему — даже самому себе: NaN === NaN возвращает false. Для проверки на NaN используют функцию Number.isNaN(value).

NaN equals nothing — not even itself: NaN === NaN returns false. To check for NaN use Number.isNaN(value).

5.2. Точность дробных чисел

5.2. Precision of floating-point numbers

console.log(0.1 + 0.2);     // 0.30000000000000004 😱

Это не баг JavaScript — то же самое происходит в Python, Java, C++. Это особенность двоичного представления дробных чисел. На практике для точных вычислений (деньги, валюты) числа хранят в копейках (целых), а не в рублях (дробных).

This is not a JavaScript bug — the same happens in Python, Java, C++. It's a quirk of the binary representation of fractions. In practice, for precise calculations (money, currencies) you store amounts in cents (integers), not dollars (floats).

6. String — строки и шаблонные литералы

6. String — strings and template literals

Строка — это последовательность символов в кавычках. В JavaScript есть три типа кавычек:

A string is a sequence of characters in quotes. JavaScript has three types of quotes:

const a = 'одинарные кавычки';
const b = "двойные кавычки";
const c = `обратные кавычки (backticks)`;

6.1. Одинарные и двойные — почти одно и то же

6.1. Single and double quotes — almost identical

Между '...' и "..." в JS нет функциональной разницы. Используйте те, что договорились в команде. Удобно: одинарные снаружи позволяют свободно писать двойные внутри (и наоборот) без экранирования:

There's no functional difference between '...' and "..." in JS. Use whichever your team agrees on. Tip: single quotes outside let you write double quotes inside without escaping (and vice versa):

const phrase1 = 'She said "hello"';   // OK
const phrase2 = "It's working";       // OK
const phrase3 = "She said \"hello\""; // тоже OK, но громоздко

6.2. Шаблонные литералы (обратные кавычки) — самые мощные

6.2. Template literals (backticks) — the most powerful

Это нововведение ES6 (2015), и оно решает две большие проблемы обычных строк.

This is an ES6 (2015) addition, and it solves two big problems of regular strings.

Проблема 1: подстановка переменных. Раньше приходилось склеивать строки плюсами:

Problem 1: variable interpolation. Before, you had to glue strings with +:

Через конкатенацию
With concatenation
const name = "Анна";
const age = 25;
const text = "Меня зовут " + name +
    ", мне " + age + " лет";
Через шаблонный литерал
With a template literal
const name = "Анна";
const age = 25;
const text = `Меня зовут ${name}, мне ${age} лет`;

Внутри ${...} можно писать любое выражение:

Inside ${...} you can put any expression:

const a = 5, b = 3;
console.log(`Сумма: ${a + b}`);           // Сумма: 8
console.log(`Большее: ${a > b ? a : b}`); // Большее: 5

Проблема 2: многострочный текст. Обычные строки не могут идти на несколько строк, а backticks — могут:

Problem 2: multiline text. Regular strings can't span multiple lines, but backticks can:

const html = `
    <div class="card">
        <h2>Заголовок</h2>
        <p>Описание</p>
    </div>
`;

На современных проектах backticks — стандарт по умолчанию. Они работают и как обычные строки, и как шаблоны. Один тип кавычек на весь проект — меньше путаницы.

In modern projects, backticks are the default. They work both as plain strings and as templates. One quote style across the project — less confusion.

6.3. Полезные методы строк (пара примеров)

6.3. Useful string methods (a few examples)

const text = "Hello, World!";

text.length;                  // 13 (свойство, без скобок!)
text.toUpperCase();           // "HELLO, WORLD!"
text.toLowerCase();           // "hello, world!"
text.includes("World");       // true
text.replace("World", "JS");  // "Hello, JS!"
text[0];                      // "H" — обращение по индексу

Подробно методы строк разберём на занятии 10. Сейчас важно одно: строки в JS — неизменяемые (immutable). Любой метод возвращает новую строку, оригинал не меняется.

We'll cover string methods in detail in Lesson 10. For now, one key idea: strings in JS are immutable. Any method returns a new string; the original isn't changed.

7. Boolean — логические значения

7. Boolean

У типа boolean всего два значения: true (истина) и false (ложь). Они используются для условий, флагов, ответов на вопросы «да/нет».

The boolean type has only two values: true and false. They're used for conditions, flags, and yes/no answers.

const isLoggedIn = true;
const isAdmin = false;
const hasPermission = age >= 18;       // выражение возвращает boolean

Любая операция сравнения возвращает булево значение:

Any comparison operation returns a boolean:

console.log(5 > 3);          // true
console.log(5 === 5);        // true
console.log("a" === "b");    // false

7.1. Truthy и falsy значения

7.1. Truthy and falsy values

В условиях (например, в if) можно использовать любое значение — JS автоматически приведёт его к булеву. Значения, которые превращаются в false, называются falsy:

In conditions (e.g. inside if), you can use any value — JS auto-converts it to a boolean. Values that become false are called falsy:

  • false
  • 0 и -0
  • "" (пустая строка)
  • null
  • undefined
  • NaN
  • false
  • 0 and -0
  • "" (empty string)
  • null
  • undefined
  • NaN

Всё остальное — truthy. Включая "0" (строка с нулём), "false" (строка) и пустой массив [].

Everything else is truthy. Including "0" (a string with zero), "false" (a string), and an empty array [].

Откройте консоль и попробуйте:

Open the console and try:

Boolean(0)         // false
Boolean("")        // false
Boolean("0")       // true ← неочевидно!
Boolean([])        // true ← пустой массив truthy
Boolean({})        // true ← пустой объект тоже truthy

8. null и undefined — пустота двух видов

8. null and undefined — two kinds of "empty"

let x;
console.log(x);              // undefined — мы не присвоили значение

let user = null;             // мы СПЕЦИАЛЬНО говорим: «нет пользователя»

Представьте полку. undefined — «коробка есть, но мы не знаем, что в ней» (или туда ещё ничего не положили). null — «коробка есть, и мы специально положили в неё табличку „пусто“». В обоих случаях содержимого нет, но смысл разный.

Imagine a shelf. undefined — "the box is there, but we don't know what's in it" (or nothing was put in it yet). null — "the box is there, and we deliberately put an 'empty' tag inside". Both lack content, but the meaning differs.

Историческая «причуда»: typeof null возвращает "object", а не "null". Это известный баг, который тянется с 1995 года. Брендан Айк об этом знает, но исправить нельзя — миллионы сайтов написаны с расчётом на эту особенность.

A historical quirk: typeof null returns "object", not "null". This is a known bug dating back to 1995. Brendan Eich knows about it, but it can't be fixed — millions of sites rely on the existing behavior.

9. Symbol и BigInt — особые типы

9. Symbol and BigInt — special types

Эти два типа на начальном этапе встретятся редко, но знать о них надо — на них могут спросить на собеседовании.

You'll rarely meet these two types early on, but it's good to know they exist — they may come up in interviews.

9.1. Symbol — уникальный идентификатор

9.1. Symbol — a unique identifier

const id1 = Symbol("id");
const id2 = Symbol("id");
console.log(id1 === id2);    // false — каждый Symbol уникален

Symbol используется как «секретный» ключ для свойств объектов, когда нужно гарантировать, что никто другой случайно не создаст такое же имя. Подробно — на занятии 30.

Symbols are used as "secret" keys for object properties when you want to guarantee no one else accidentally creates the same name. Details in Lesson 30.

9.2. BigInt — целые числа сколь угодно большие

9.2. BigInt — arbitrarily large integers

const huge = 9007199254740993n;   // n в конце — это BigInt
const a = 2n ** 100n;             // 2 в степени 100, без потери точности
console.log(a);                   // 1267650600228229401496703205376n

Обычный number точно работает с целыми до 253 − 1 (≈ 9 квадриллионов). Если нужно больше — используется bigint. Применение: криптография, точные расчёты, идентификаторы из БД.

Regular number safely handles integers up to 253 − 1 (≈ 9 quadrillion). Beyond that, use bigint. Use cases: cryptography, exact calculations, DB identifiers.

10. Оператор typeof

10. The typeof operator

typeof — это оператор, который возвращает строку с именем типа переданного значения.

typeof is an operator that returns a string with the type name of the value.

typeof 42;              // "number"
typeof "hello";         // "string"
typeof true;            // "boolean"
typeof undefined;       // "undefined"
typeof null;            // "object"   ← историческая причуда!
typeof Symbol();        // "symbol"
typeof 10n;             // "bigint"
typeof { a: 1 };        // "object"
typeof [1, 2, 3];       // "object"   ← массив тоже object
typeof function(){};    // "function" ← хотя функция тоже object

Два неочевидных результата:

Two non-obvious results:

  • typeof null === "object" — баг 1995 года, не исправляют ради совместимости
  • typeof function(){} === "function" — функция технически объект, но JS даёт ей отдельный «ярлык» в typeof
  • typeof null === "object" — a 1995 bug, kept for backward compatibility
  • typeof function(){} === "function" — a function is technically an object, but JS gives it its own typeof label

11. Преобразование типов (Type Coercion)

11. Type conversion (Type Coercion)

JavaScript — динамически-типизированный язык, и в нём типы могут автоматически преобразовываться один в другой. Это удобно, но если не понимать правил — становится источником багов. Преобразование бывает явным (мы сами просим) и неявным (JS делает за нас).

JavaScript is dynamically typed, and types can convert automatically from one to another. Convenient, but a source of bugs if you don't know the rules. Conversion is explicit (we ask) or implicit (JS does it for us).

11.1. Явное преобразование

11.1. Explicit conversion

// В строку
String(123);           // "123"
String(true);          // "true"
String(null);          // "null"
(42).toString();       // "42"

// В число
Number("42");          // 42
Number("3.14");        // 3.14
Number("abc");         // NaN — невозможно преобразовать
Number("");            // 0
Number(true);          // 1
Number(false);         // 0
parseInt("42px");      // 42 — игнорирует хвост
parseFloat("3.14abc"); // 3.14

// В булево
Boolean(1);            // true
Boolean(0);            // false
Boolean("text");       // true
Boolean("");           // false

11.2. Неявное преобразование — самое коварное

11.2. Implicit conversion — the trickiest

"5" + 3        // "53"   ← плюс со строкой = склейка строк
"5" - 3        // 2      ← минус всегда число
"5" * "2"      // 10     ← умножение всегда число
1 + "2" + 3    // "123"  ← слева направо: "12" + 3
"10" / "2"     // 5
"abc" - 1      // NaN
true + 1       // 2      ← true → 1
null + 1       // 1      ← null → 0
undefined + 1  // NaN    ← undefined → NaN

Главное правило: оператор + со строкой превращается в склейку. Все остальные арифметические операторы (-, *, /, %) — всегда работают с числами. Это и есть ответ на загадку из занятия 1: "5" + 3 = "53", но "5" - 3 = 2.

Key rule: the + operator with a string becomes concatenation. All other arithmetic operators (-, *, /, %) always work with numbers. That's the answer to the riddle from Lesson 1: "5" + 3 = "53", but "5" - 3 = 2.

11.3. Когда нужно явное преобразование

11.3. When you need explicit conversion

Классический пример — ввод с формы. Поле <input> всегда даёт строку, даже если пользователь ввёл число:

A classic example — form input. An <input> field always gives a string, even if the user typed a number:

const ageInput = "20";         // строка из input
const age = Number(ageInput);  // делаем явное преобразование
const nextYear = age + 1;      // 21, не "201"

12. Практический пример: «Карточка пользователя»

12. Practical example: "User card"

Соберём всё, что мы узнали, в маленький скрипт. Выведем в консоль информацию о пользователе, используя все типы данных и шаблонные литералы.

Let's put everything together in a small script. We'll print a user card to the console, using all data types and template literals.

const firstName = "Сейди";
const lastName = "Чарыев";
const age = 24;
const isStudent = true;
const score = 87.5;
const skills = ["HTML", "CSS", "JavaScript"];
let coffeesDrunk = 3;

console.log(`
=== Карточка пользователя ===
Имя:        ${firstName} ${lastName}
Возраст:    ${age}
Студент:    ${isStudent ? "да" : "нет"}
Балл:       ${score}
Навыки:     ${skills.join(", ")}
Кофе:       ${coffeesDrunk} чашки
`);

coffeesDrunk = coffeesDrunk + 1;
console.log(`Выпил ещё чашку. Всего: ${coffeesDrunk}`);
